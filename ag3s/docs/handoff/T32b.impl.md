## 무엇을 했나 (평이한 요약 먼저)

T31b 의 attention split 이 남긴 부작용 둘을 `TargetConfirm` 안에서 고쳤다.

- **S2 — 파지 시도가 끝나면 anchor 를 한 번 가른다.**
  - 원인: 동결(closing … held) 중에는 분할이 꺼지고, 기하가 관측을 그대로 따라간다. 그래서 동결이 풀릴 때 서 있는 기하(새 anchor)가 다시 사과 + 이웃 덩어리일 수 있다.
  - 그 뒤에는 분할된 사과가 이 덩어리 anchor 의 **부분(subset)** 으로만 보인다. 그래서 `subset_kept_anchor` 로 덩어리가 계속 유지됐다.
  - 수정: 해제 뒤 첫 grounding 호출에서, 서 있는 기하를 **그 기하가 관측될 때의 attention** 으로 같은 T31b 분할에 한 번 통과시킨다.
  - 갈라지고 target 성분이 admissible 이면 그 성분이 anchor 가 된다. 이때 source 는 `release_split`, `attention_split = 1` 이다. 이 표시 덕분에 T31b 의 `unsplit_kept_anchor` 가 이 anchor 도 보호한다.
- **S3 — 손이 가린 프레임은 switch 수에 넣지 않는다.** 다음 셋이 모두 맞으면 그 프레임은 도전자의 연속 프레임으로 세지 않고, 동결 프레임처럼 연속을 끊는다(T20 "가려짐은 새 물체가 아니다").
  1. held 물체가 이번 프레임에 온전히 보이지 않는다. 곧 `occluded`(사유 무관)이거나 `subset_kept_anchor` 다.
  2. 손 collision 구(손바닥·손가락)의 표면이 서 있는 기하에서 **`hand_occlusion_reach` = 30 mm** 안에 있다.
  3. 손이 **도전자 점보다 held 쪽에 더 가깝다**(같아도 된다).
  - 손이 멀어지거나 도전자 쪽으로 가면 수가 다시 돈다. 그래서 진짜 전환은 그대로 일어난다.
- **손 위치는 grounding 이 받지 않는다.** `ground_target` 도 `TargetConfirm` 도 robot state 를 받지 않는다.
  - 그래서 입구 `TargetConfirm.note_hand(HandSpheres)` 와 만드는 함수 `admissibility.hand_spheres(robot_model, robot_state)` 를 넣었다.
  - **pipeline 배선 한 줄은 T32a 소유라 넣지 않았다(§6).** 배선 전까지 AG3S 안에서 S3 는 동작하지 않는다(손 정보가 없으면 억제 없음). S2 는 pipeline 이 이미 `freeze()` 를 부르므로 바로 동작한다.

## 1. S3 의 "손이 reach 안" — 정의와 근거

**정의.** `gap = min over 손 구 i, 점 p ‖p − cᵢ‖ − rᵢ`
- 손 구는 gripper 의 손바닥(손가락의 parent link)과 손가락 두 link 의 collision 구다. RB-Y1 에서는 `ee_left/right`, `ee_finger_l1/l2/r1/r2` 이다. 이름을 박지 않고 `gripper_joint_pairs()` 로 구조에서 찾는다.
- 점 p 는 **서 있는 기하**, 곧 가려진 동안 대신 쓰는 anchor 다.
- 값은 **결정 전** 기하에 대해 잰다.

**자료.** T31b 규칙(현 tree 기본에서 S2·S3 끔) 재생의 파지 전·비동결 청크를 썼다. 손은 npz 의 `sphere_centres/radii` 다. 이 기록의 제약 모델은 gripper link 뿐이고, 궤적 0 행(≈ q_now)이다.

## 2. S2 — 무엇이 언제 갈리나

- **발동:** `freeze(True → False)` 가 다음 grounding 호출을 무장한다. 그 호출 전에 다시 `freeze(True)` 이면 해제한다. 해제 뒤 첫 `ground_target` 이 맨 앞에서 `split_anchor_on_release(cfg)` 를 부른다. 그 호출이 cluster 없이 끝나더라도(NO_SEED 등) 분할은 한다.
- **입력:** 서 있는 기하의 점, 그리고 그 기하가 관측된 프레임의 점별 attention(`observe(target, attention=…)` 로 저장).
- 규칙과 파라미터는 T31b 와 같다. 15 mm 재연결, `min_points` 20, 평균 attention 비 ≥ 2, 발동 조건 `좁은 축 ≤ max_opening < 긴 축`.
- 다음 경우에는 기록만 남기고 anchor 는 그대로 둔다.
  - 분할이 꺼짐(`off`)
  - 개도 모름
  - 기하 없음
  - attention 없음
  - 발동 안 됨(`not_triggered`)
  - 한 성분
  - attention 이 두 성분을 구별 못함
  - 성분이 inadmissible
- **재생의 해제 사건(예).** 각 값은 해제 시 청크 → 결과 → 성분 크기·평균 attention 순이다.
  - T28 E3b ep1808 r2 t=280 → split (154 → 85 점, 비 24.8)
  - T28 E3a ep1808 r1 t=240 → split (175 → 110, 비 3.4)
  - T30 E3a ep1808 r1 t=208 → `one_component` (50·64·131 mm; 사과·orange 접촉)
  - T30 E3a ep1800 r3 t=248 → `one_component` (banana 단독 19·39·76 mm, 병합 아님)

## 6. pipeline.py 에 필요한 것 (T32a 소유 — lead 가 전달)

S3 가 AG3S 안에서 동작하려면 `AG3S._run` 에서 grounding 직전, `self._target_confirm.freeze(...)` 바로 다음(현재 `runtime/pipeline.py:893` 부근)에 **한 줄**이 필요하다.

```python
from benchmark.ag3s.stages.admissibility import hand_spheres   # 파일 머리 import 에
...
self._target_confirm.freeze(self._grasp_active or self._attached is not None)
self._target_confirm.note_hand(hand_spheres(self.robot_model, robot_state))   # T32b S3
```

- `robot_state` 는 `_run` 이 이미 받는 값이다. `process_multi` 에서는 가장 새 observation 의 state 다.
- `self.robot_model` 은 self-filter 와 같은 모델이다. 손가락 관절은 T29 의 현재 값을 쓴다.
- 둘 중 하나가 None 이거나 모델에 gripper 가 없으면 `hand_spheres` 가 None 을 돌려주고, S3 는 억제하지 않는다(T31b 동작).
- 기록은 이미 `metrics["manipulated"] = manipulated.record()` 를 거쳐 `summary_json.manipulated.hand` 에 실린다. pipeline 을 더 고칠 필요는 없다.
- **S2 는 배선이 필요 없다.** pipeline 이 매 프레임 `freeze()` 를 부르고, `ground_target` 이 해제 분할을 부른다.
