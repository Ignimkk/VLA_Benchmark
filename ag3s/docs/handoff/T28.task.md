# T28 — 폐루프 사다리 실험: VLA → +TO → +목적함수/limit → +거리장, 실패하면 원인을 가른다

> writer: lead (A0) · 2026-09-28 · 읽는 쪽: verifier (구현 없음)
> 근거: 사용자 지시 2026-09-28 (아래 Q1–Q7), [T14.audit](T14.audit.md) §0b (T16 vs T17), [T26](T26.task.md) · [T27](T27.task.md)
> **이 실험은 GPU 서버에서 폐루프로 돈다** — 정책 서버(포트 **820x**, 8123 금지) + headless MuJoCo client (같은 서버). 로컬 PC 불필요.

## 사용자가 반드시 답을 요구한 것

| Q | 질문 | 어느 실험이 답하나 |
|---|---|---|
| Q1 | 제약·목적함수 없이(추적만, 충돌 없음) TO 했을 때 사과를 집는가 — ESDF 판정·HOLD 없이 | E1 |
| Q2 | 일부 목적함수·제약을 넣어도 집는가 | E2 |
| Q3 | 거리장을 더하되 조건을 최대한 완화했을 때 집는가 | E3a (게이트 off) · E3b (게이트 on) |
| Q4 | 실패하면 원인: HOLD 규칙인가 · 지연시간인가 · action chunk–TO 결합인가 | 사다리의 어느 칸에서 깨지나 + 아래 진단 |
| Q5 | gripper capsule 구가 너무 커서인가 — **최대한 작게** 구성해서 진행 | P1-3 · E3 |
| Q6 | 사과를 여전히 충돌 객체로 인식해서 못 집는가 | E3 프레임별 최악 행의 대상 물체 |
| Q7 | 사과를 잡지도 않았는데 target 이 crate 로 바뀌어 사과가 충돌 객체가 되었나 | E3 프레임별 manipulated 라벨 · T14/T16 기록 |

**lead 가 코드로 이미 확인한 것 (재확인해 숫자로)**: `pi05_infer.py` 제어 루프는 **동기식**이다 — 추론하는 동안 `mj_step` 이 돌지 않는다
(`pi05_infer.py:1695-1697`, "sim time is frozen"). 그러므로 시뮬레이션에서 지연시간이 물리에 주는 영향은 **timeout → HOLD** 경로뿐이다.
프레임별 `infer_ms` 와 timeout·stale 수를 모든 실행에서 보고하라.

## 공통 실행 규약

```bash
# 서버 (포트 8201..8209 중 하나 — 8123 은 절대 쓰지 않는다)
cd /mnt/dev/work && OPENPI_DATA_HOME=/mnt/dev/work/pi05_TO_hybrid/cache/openpi XLA_FLAGS="--xla_gpu_enable_command_buffer=" \
  XLA_PYTHON_CLIENT_PREALLOCATE=false PYTHONUNBUFFERED=1 .venv-openpi-live/bin/python -m benchmark.trajopt.serve_safe \
  --config pi05_rby1_randomized_pick_place_16d_lora \
  --checkpoint /mnt/dev/work/pi05_TO_hybrid/checkpoints/pi05_rby1_randomized_pick_place_16d_lora/rby1_randomized_pick_place_16d_30k_xla_retry_20260923/29999 \
  --model-xml /mnt/dev/work/pi05_TO_hybrid/rby1_description/models/rby1a/mujoco/model_transport.xml --port 820x <조건별 flag> \
  --record-constraints <out>/server_constraints   # (--no-safe 제외)
# client (같은 서버, headless)
cd /mnt/dev/work/pi05_TO_hybrid && MUJOCO_GL=osmesa /mnt/dev/work/.venv-openpi-live/bin/python -u rby1_bringup/pi05_infer.py \
  --model rby1_randomized_pick_place_16d --remote localhost:820x --episode-index <ep> --max-steps 600 --headless \
  --record-frames <out>/<cond>_ep<ep>_r<k> [--safe-remote --safe-timeout 120 --safe-phase approach --safe-manipulators left <조건별>]
```

- 출력: `outputs/verify/T28/<조건>/...` · figure: `benchmark/ag3s/docs/figures/t28/` · 수치: `T28.verify.json` (phase 마다 `T28.verify.partial.json` 에 이어 저장).
- **한 번에 한 서버·한 client.** 서버는 조건마다 다시 띄우고 끝나면 반드시 죽인다 (`pkill -f "serve_safe.*--port 820x"`). 로그는 `<out>/serve_safe.log`.
- 서버 MuJoCo 3.11.0 (로컬 PC 3.10.0) — 그래서 **E0 을 여기서 먼저** 잰다. 비교는 이 서버의 E0 과만 한다.
- 에피소드: `1807` (T14–T17 과 같은 씬) + test split(1800–1999) 에서 **target = apple · 왼팔** 인 에피소드 2 개 (`load_randomized_episode` 메타로 고른다; 고른 근거를 기록).
  정책이 결정론적인지 1807 을 2 회 돌려 먼저 본다 — 결정론적이면 반복 대신 에피소드로 N 을 채운다, 아니면 에피소드당 N=2.
- **성공 판정** (`frames.jsonl` 의 planning frame `object_poses`): grasp = 사과 z 가 초기 + 50 mm 이상 (시각 기록) · place = 마지막에 사과가 crate 안
  (crate body pose + 모델의 crate 크기로 정의; 정의를 verify.json 에). 둘 다 참이면 success.
- 기준선 (skill `regression-baseline`) 은 **모든 폐루프 실행이 끝난 뒤 단독으로** — 부하가 숫자를 바꾼다.
