# T1 — 연속 프레임 AG3S, 실측 policy attention 으로 지각이 쓸 만한가

> writer: lead (A0) · 2026-09-25 · 주 담당 **A2(검증)**

## 왜 지금 열리나

T1 은 grounding 이 서야 잴 수 있는 항목이 대부분이다. X2(teleop keyframe 의 `head_1` 이
기록에서 0 이 되어 `cam_high` 가 벽을 봤다)를 고치고 재촬영한 뒤 **`has_target` 이 15/15** 가
되면서 전부 열렸다.

**합성 attention 을 몰래 끼워넣지 않는다** — 계획서가 못박은 계약이다. 실측 npz 만 쓴다.

## 자산 (전부 머리 고친 뒤에 뜬 것)

계획서의 *"새 seed 3 개 이상"* 을 이 셋으로 맞춘다. **셋 다 held-out (1800–1999) 이다.**

## 합격 조건 — 여덟 항목 전부 수치로 낸다

| # | 무엇 | 합격 |
|---|---|---|
| 1 | **target 중심 오차** | **보이는 표면 중심** 기준으로 낸다. body 원점 기준은 쓰지 않는다 — 카메라가 보는 것은 표면이지 원점이 아니다 |
| 2 | **지지면 높이 오차** | 수치로. 참값은 MuJoCo 의 테이블 상면 |
| 3 | **카메라 간 표면 정렬 오차** | 세 카메라의 점군이 같은 표면을 얼마나 어긋나게 놓나 |
| 4 | **로봇 마스크** | 마스크 후 **로봇 표면이 만든 위반 0**. 잔여 위반은 segmentation 참값으로 최근접 body 에 귀속시킨다 |
| 5 | **낮은 실제 장애물** | attention 이 낮아도 충돌 기하에서 **사라지지 않는다** |
| 6 | **입력 부족** | `degraded` · `no_target` · 명시적 실패 중 하나. **조용히 정상이 되지 않는다** |
| 7 | **completeness** | expected = captured observation frames. attention/lifting/grounding 기록이 **전 프레임** |
| 8 | **diagnostic frame card** | **모든** observation frame 에 하나씩 |

에피소드 **셋 각각**에 대해 낸다. 한 에피소드만 통과하면 T1 은 안 닫힌다.

## 규칙

- **해석·판정을 쓰지 않는다.** 수치와 경로만 `T1.verify.json` 에 담는다. 판정은 A0 와 사용자가 한다.
- figure 는 `benchmark/ag3s/docs/figures/t1/` 아래. **기존 이름을 덮어쓰지 않는다.**
- raw 는 `outputs/verify/T1/`. 터미널에만 있는 숫자는 없는 숫자다.
- 시작 전 `regression-baseline` skill 로 환경이 성한지 본다.
- **8번(frame card)이 가장 비싸다.** 프레임 45 장(15 × 3 에피소드)이니, 만드는 비용을 먼저 재고
  A0 에게 보고한 뒤 만들어라. 한 장에 몇 초가 걸리는지 모르고 시작하지 않는다.

## 이 게이트가 답하는 질문

**실측 policy attention 으로, held-out 세 에피소드에서 지각이 쓸 만한가.**
쓸 만하다면 그 근거는 위 여덟 수치다.
