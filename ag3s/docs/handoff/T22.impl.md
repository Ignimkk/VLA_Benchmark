## 무엇을 했나 (평이한 요약 먼저)

이제 서버는 **계획 청크의 gripper 값으로 attach 하지 않는다.** 직전 청크의 실행 피드백(T18)에서 닫힘 명령이
**실제로 적용**됐는지 보고, 측정 개도가 **줄어들다 명령보다 위에서 멈췄는지**(손가락이 물체에 막혔다), 그리고
조작 대상(T20 `ag3s.manipulated`)이 손가락 link 의 **reach 안**인지 본다. 전부 맞을 때만 `attach()` 한다. 닫힘이
HOLD 로 취소된 청크, 빈손 닫힘, 멀리 있는 대상, 피드백이 없는 옛 클라이언트는 attach 하지 않고 그 이유를 기록에 남긴다.

이 판단은 **제약을 짓기 전에** 한다 (순서 (a)). 그래서 attach/detach 가 그 프레임의 거리장·제약에 바로 들어간다.
`AG3S.attach()` 자체도 reach 를 넘는 물체를 `AttachRejected` 로 거절한다 (SafePolicy 가 넘기는 값으로 — 마지막 관문).
옛 동작은 `LatchConfig(legacy_gripper_attach=True)` 로만 켜진다.

## 상태와 전이 (`GraspLatch(evidence=True)` — SafePolicy 기본)

| 상태 (`GraspPhase`) | 지침 §6.2 | attach | 들어가는 조건 |
|---|---|---|---|
| `searching` | — | 안 함 | 시작 · `reset()` |
| `latched` | 대상 확정 | 안 함 | 같은 물체 3 프레임 + 격차 1.3 (예전 규칙 그대로, **이번 프레임 grounding 뒤** `_run_latch`) |
| **`closing` (새)** | 닫힘 시도 | 안 함 | `latched` 에서 피드백의 **실행된** 스텝 중 `applied_gripper < 0.85` 가 1 개 이상 |
| `held` | 파지 확인 | **함** | `closing` 에서 아래 7 조건이 전부 참 |
| `placed` | 놓임 확인 | detach | `held` 에서 측정 개도 ≥ 0.85 가 2 프레임 연속, 또는 (`placed_fn` ∧ 측정 개도 ≥ 0.85) |

되돌아가는 전이: `closing` → `latched` (마지막 실행 명령 **과** 측정 개도가 둘 다 ≥ 0.85 = 시도 포기) ·
`held` → `closing` (`AG3S.attach` 가 거절 — `revert_attach`) · 피드백 없음 = **어떤 전이도 없음** (note 만).

파지 확인 조건 (`GraspLatch._grasp_checks`, 기록의 `evidence.checks` 키 이름 그대로):

| 키 | 조건 | 무엇을 막나 |
|---|---|---|
| `settled` | 닫힘 시도 뒤 **실행된** 닫힘 명령 스텝 누적 ≥ `settle_steps` (3) | 청크 끝에서 막 닫히기 시작한 중간 개도 |
| `closed` | 측정 개도 < 0.85 | 안 닫힌 손 |
| `dropped` | 시도 직전 측정 개도 − 지금 개도 ≥ `min_drop` (0.05) | "줄어들다" — 이미 닫힌 채 잠긴 경우 등 |
| `not_empty` | 측정 개도 ≥ `empty_below` (0.10) | 끝까지 닫힘 = 빈손 |
| `blocked` | 측정 개도 − **마지막 실행 명령** ≥ `blocked_gap` (0.05) | 빈손 (위치 제어라 명령까지 닫힌다) |
| `manipulated` | T20 manipulated 가 있고 `visible`/`occluded` | 대상 없음 · `lost` |
| `reach` | parent link 원점 ↔ manipulated centroid ≤ `reach` (0.12 m) | T14 의 636 mm phantom |

HOLD 스텝(`executed[i] == False`)의 `applied_gripper` 는 `rby1_state()`(= 현재 개도)라 **명령으로 세지 않는다**
(`grasp_signal_from_feedback`). 쥔 채 HOLD 면 그 값이 0.72 라 닫힘 명령처럼 보이고, T16 빈손 HOLD 에서도 측정 0.82 가 나왔다.

## 순서 — (a) 를 골랐다

**파지 상태 갱신(`_advance_grasp`)을 `process_multi_debug` 앞으로 옮겼다.** 대상 확정(잠금)과 목적지 학습은 이번 프레임
grounding 이 필요하므로 뒤(`_run_latch`)에 그대로 둔다.

이유:
1. (b) 의 "재생성" 은 이 STEP 이 만질 수 있는 파일 안에서는 `process_multi_debug` 를 **한 번 더 부르는 것**뿐이다.
   그러면 T20 `TargetConfirm` 의 streak · age · `frame_index`, 후보 tracker, ESDF 증분이 한 프레임을 두 번 센다 —
   재생성이 아니라 다른 프레임을 만든다. 제약만 다시 짓는 입구(`_constraints` · `_build_esdf`)는 attach/detach 밖이고
   `_build_esdf` 는 T21 의 것이다.
2. attach 는 거리장에도 들어간다 (`pipeline.py` `_build_esdf`: `nothing_held` 이면 target-free 계층과 target 라벨을 싣지
   않고, 쥔 물체 점을 파낸다). 뒤에서 attach 하면 그 프레임은 "쥔 사과가 아직 장애물" 인 거리장으로 TO 가 돈다 — 파지 순간이다.
3. 입력 셋(피드백 · manipulated · 지금 자세)이 전부 grounding 전에 있다.

대가: attach 하는 기하는 **직전 프레임까지의** manipulated 기하다 (이번 프레임 grounding 전이므로). 파지 순간 물체는 테이블
위 또는 손가락 사이라 한 청크(8 스텝) 동안 거의 안 움직인다는 가정이고, 그 가정의 크기를 기록 `grasp.alignment` 에 남긴다
(`geometry_frame` · `geometry_age_frames` · `pipeline_frame` · 직전 요청 이후 parent 원점 이동 `hand_shift_mm`).

**버전 기록:** `grasp.state_version` = attach/detach 때마다 +1 인 파지 상태 버전, `grasp.constraint_version` = 이번 제약을 지을 때의
버전. evidence 모드에서는 언제나 같다. `legacy_gripper_attach=True` 의 attach 는 제약 **뒤**라 그 청크는 `constraint_version <
state_version` 으로 드러난다. `constraints_match_state` 는 두 버전이 같고 `constraint_set.attached is ag3s.attached` 인가.

## 부착 좌표계 — 지금 구현이 하는 것 (바꾸지 않음)

- `attach_from_target` 은 물체 점(10 mm voxel · 고립점 제거)과 bounding primitive 를 **parent link 프레임**으로 옮겨 저장하고
  `T_parent_object = I` 다. parent 는 `DEFAULT_GRASP_LINKS` 의 `ee_finger_l1`(왼) / `ee_finger_r1`(오른) — **움직이는 손가락 link**.
- 그래서 attach 뒤 개도가 바뀌면 물체는 손이 아니라 **그 손가락과 함께** 움직인다. 모델링 오차는 개도 변화 × 45 mm (손가락 하나).
  T17 유지 구간의 측정 개도는 0.712–0.721 이라 ~0.4 mm 다. 이 오차를 줄이는 것은 좌표계가 아니라 **시점**이다 — 이제 attach 는
  `settled` (닫힘 명령 3 스텝 이상 뒤) 에서만 일어나므로 손가락이 멈춘 뒤다. 옛 경로는 닫힘이 **계획된** 순간(손가락이 아직 열림)에
  붙였으므로 그 뒤 닫힘 이동(최대 ~13 mm)이 물체에 그대로 실렸다.
- 자세는 **이번 요청 촬영 시점 중 최신** `robot_state` (예전과 같다). 기하 시점과의 차이는 위 `alignment` 로 남긴다.
- 바꾼 것은 reach 검사와 증거 기록뿐이다 (task §3).

## verifier 가 알아야 할 것

- **기본 동작 변경 (의도):** SafePolicy 는 이제 실행 피드백 없이 attach 하지 않는다. 옛 클라이언트·옛 기록 재생(`safe_replay.py`) 은
  **attach 0** 이 된다 — T16·T14 재생(#2·#3)에서 옛 결과와 비교할 때 이것이 첫 차이다. 옛 규칙으로 돌리려면
  `SafePolicy(latch=LatchConfig(legacy_gripper_attach=True))` (safe_replay 에는 플래그가 없다 — `trajopt/experiments/**` 는 T24 소유라 안 건드렸다).
- **새 config 키:** 위 표. `AG3S.attach(reach=)` 의 기본은 **`None`(검사 안 함)** 이고 SafePolicy 가 `LatchConfig.reach` 를 넘긴다.
  기본을 0.12 로 켜지 않은 이유: `trajopt/experiments/grasp_damage.py` 가 `link_left_arm_6` 에 붙이는데 그 원점↔사과가 T17 FK 로 ~270 mm 다.
- **오프라인 재생 API (#1–#5):** `latch = GraspLatch(LatchConfig(...), evidence=True)`; 잠금은 `latch.update(label=..., score=..., runner_up=...)`;
  프레임마다 `latch.observe_grasp(grasp_signal_from_feedback(fb, hand_index, 0.85), reach_m=..., manipulated_id=..., manipulated_state=..., placed=...)`.
  `fb` 는 `wire.unpack_exec_feedback` 형식이면 된다 — 옛 기록은 control 프레임의 `qpos[27]/−0.045` (측정) 와 실행된 reference 행의 gripper 열(적용)로
  만들 수 있다 (`tests/trajopt/test_grasp_evidence.py:_fb` 가 그 모양). **이것은 T18 이 경계한 "머리로 재현" 이므로** closed-loop 새 실행과 구별해 적어 달라.
- **reach 는 parent link 원점 기준이다** (body 중심 아님, 손가락 표면 아님). 좌표는 constraint 모델(URDF) FK.
- **재생산이 필요한 산출물:** 없음.
- **옛 기록과 호환:** 깨지지 않음. `summary_json` 에 `grasp` 키가 더해질 뿐. `GraspPhase` 에 `closing` 값이 생겼다 — phase 문자열을 세는 스크립트가 있다면 그 값을 모른다.
- **응답 `notes`:** 상태가 바뀐 청크에만 `grasp: …` 한 줄. 키 집합은 그대로.
- **나는 재지 않았다:** T17/T16/T14 기록 재생 (#1–#3), 빈손·HOLD·놓임 합성 (#4·#5) 의 수치, 회귀 기준선, closed-loop 실행, figure.
  reach 기본값을 고르려고 T17 기록에서 FK 거리 한 번 본 것(위 근거)은 측정 판정이 아니다 — verifier 가 다시 재야 한다.
- **판정 요청 (lead):**
  1. `AG3S.attach(reach=)` 기본을 `None` 으로 둔 것 (위 이유). 켜려면 parent link 별 한도가 필요하다.
  2. slip(쥔 뒤 개도가 명령까지 떨어짐) 은 detach 하지 않는다 — task 가 "놓임 규칙 유지" 라서. 기록의 `evidence` 로 볼 수 있다.
  3. 닫힌 채로 잠금이 늦게 걸리면(`latched` 진입 시 이미 개도 0.72) `dropped` 가 거짓이라 attach 하지 않는다 (fail-closed). 흔하지 않다고 봤다.
  4. 카메라가 0 대인 요청은 `_advance_grasp` 전에 `_scene_fn` 이 던지므로 그 청크의 피드백(닫힘 스텝)은 파지 판단에 안 들어간다.
