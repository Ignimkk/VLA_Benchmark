# T43 Q — 구현: 실행 가능한 계획 (servo 모델) · waypoint 사이 연속 충돌 검사

> writer: ag3s-implementer (lane Q) · 2026-10-05 · 읽는 쪽: verifier, scribe, lead
> benchmark 기준 `d309550` (pre-T43) · pi05_TO_hybrid **변경 없음** · **커밋하지 않았다** (lead 가 커밋)

## 무엇을 했나 (평이한 요약 먼저)

TO 는 명령 waypoint 만 검사했다. 로봇은 위치 servo 라서 명령보다 약 한 제어 주기 늦게, 명령 **사이**를
지나간다. 그래서 두 가지를 더했다. 둘 다 플래그로만 켜지고, 기본은 꺼짐이며 꺼져 있으면 비트 동일하다.

1. **`--servo-model` (실행 가능한 계획).** TO 가 "명령 `Q`" 와 함께 "로봇이 실제로 지날 자세 `X(Q)`" 를 안다.
   `X` 는 시뮬레이터의 servo 그 자체다. 제어 대상 MJCF 의 `kp` · `kv` (dampratio 에서 컴파일된 값) ·
   joint damping · armature + 관성 대각을 읽어서 **유도** 했다. 기록에 맞추지(fit) 않았다. 기록은 **검증** 에만 썼다.
   시작 상태는 촬영 순간 측정 자세에, `exec_feedback.applied_arm` 로 추정한 **속도** 와 상수 토크를 더한 것이다.
   각 제어 행 끝의 예측 자세에 충돌 행을 더한다.
   범위를 자르지 않으므로 (`--rest-start` 와 다르다) 큰 명령은 실제로 큰 움직임이 된다.
   정지에서 21.6° 명령은 첫 행에 3.9–5.1° 를 간다 (MuJoCo). rest-start 는 첫 스텝 **명령** 자체를 2.29° 안으로 잘랐다.
2. **`--sweep-check` (연속 충돌 검사).** 제어 행마다 중간 자세를 검사한다. servo 모델이 꺼져 있으면 관절 공간 보간을,
   켜져 있으면 servo 예측 경로의 sub-step 을 쓴다. 행 하나를 `ceil(L / 12 mm)` 조각으로 자른다.
   `L` 은 행 위에서 질의 구가 움직이는 경로 길이 (8 점 격자 FK) 다. 그래서 검사 사이 이동이 ≤ 12 mm
   (24 mm 막대의 절반) 이고, 실제 값은 매 청크 FK 로 재서 기록한다.

중간 자세 행은 waypoint 행과 같은 여유를 요구하되 세 가지가 다르다.

- **floor.** `h(X) ≥ min(0, h(q_now))` 다. 이미 여유 안에서 출발한 로봇은 더 깊이 들어가지만 않으면 된다.
  이것이 없으면 t=216 (막대 9.7 mm, 여유 10 mm) 에서 어떤 경로도 통과하지 못한다.
- **조작 대상은 뺀다.** 최근접 표면이 잡으려는 사과인 로봇 구 행은 경로 검사에서 뺀다.
  사과에 닿는 것이 과제이고, waypoint 행이 E1 여유를 그대로 지킨다.
  쥔 물체의 질의점은 남긴다. 운반 중 사과가 허들에 걸리는 경우가 바로 그것이다.
- **정지 계획을 두 번째 출발점으로.** reference 가 위반하면 `Q = q_now` (= HOLD 와 같은 계획) 의 merit 도 잰다.
  그것이 더 낮으면 SQP 를 거기서 시작한다. 이것이 없으면 t=216 에서 3–10 반복 모두 VIOLATED 였다
  (아래 "선택의 근거" 3).

결과 (고정 입력 replay → 비트 동일 상태에서 MuJoCo 실행, true mesh GJK):
기록된 접촉 두 청크 모두 waypoint 행은 "clear" 였다. 새 행은 그 계획 안에서 8.4–21.7 mm 의 침투를 본다.
다시 푼 계획 (`--servo-model --sweep-check`) 은 접촉이 없다.

`τ` (중력 · 결합) 는 관절마다 청크 동안 상수로 두고 observer 가 추정한다 (`servo.ServoObserver`).
직전 촬영 상태를 그 사이 적용된 명령 8 행으로 전파한 뒤, 위치 잔차 하나로 `τ` 를 풀고 속도를 갱신한다.
servo 는 초기 속도를 ~0.2 s 안에 잊는다 (한 청크 0.53 s). 그래서 직전 속도 오차는 거의 넘어오지 않는다.
피드백이 없으면 (첫 요청 · seq 불일치 · 모양 틀림) 정지로 두고 `servo_state.source` 에 그 이유를 적는다.

**도달 범위** (`tests/sim/test_t43q_servo_sim.py`, C1807 t=216, HOLD 뒤 정지) 는 첫 행 끝 이동이다.
10.8° 명령에 1.9–2.7°, 21.6° 명령에 3.9–5.1° (왼팔 1–3) 이고, 모델은 모든 sub-step 에서 ≤ 0.25° 안이다.
T41 b 가 기록에서 잰 첫 주기 1.4–2.6° 와 같은 크기다.
반응은 명령 크기에 비례하므로 큰 명령의 탈출은 막히지 않는다 (rest-start 의 2.29° clip 과 다르다).

**가속 한계를 걸지 않은 이유.** URDF `a_max·dt² = 2.29°` 를 실제 운동 `X` 에 걸면 큰 명령의 첫 행 (MuJoCo 3.9–5.1°) 을 막는다.
T41 b 의 21.6° 탈출 계획은 MuJoCo 에서 무접촉이었다 (T41 b `sim_track`, 아래 3-2).
시뮬레이터에는 토크 한계 (`forcerange`) 가 없어서 URDF 가속 한계가 실제로 묶지 않는다.
명령 쪽 속도 · 가속 행과 anchor 는 예전 그대로 둔다.

## 2. 연속 검사 — 무엇을, 얼마나 촘촘히

| 모드 | 행 `k` 의 검사 자세 | QP 행이 닿는 변수 |
|---|---|---|
| `interp` (`--sweep-check`) | `Q[:,k-1] → Q[:,k]` (첫 행은 `q_now → Q[:,0]`) 관절 보간의 내부 점, 손가락 개도도 보간 | `Q[:,k-1]`, `Q[:,k]` |
| `servo` (`--servo-model`) | servo 예측 자세의 행 끝 (+ `--sweep-check` 면 sub-step) | `Q[:,0..k]` (servo 는 인과적이라 그 앞 명령 전부) |

- 자세가 `Q` 의 **affine** 함수다 (`X = offset + Σ W_i ⊙ Q_i`, 선형 모델이라 정확).
  그래서 행 하나가 연쇄 법칙으로 QP 행 하나가 된다. affine 사상 = rollout 은 1e-12 로 맞는다 (시험).
- **QP 예산** 은 제어 행마다 `--sweep-rows-per-step` (기본 24) 이다. 그 행의 모든 중간 자세를 통틀어
  가장 빠듯한 것부터 고른다. 희소 패턴은 설정만으로 정해지고 씬과 무관하다 (시험).
  각 행에 자기 slack 이 있다 (waypoint 행과 같은 L1).
- **최종 검사** 는 모든 중간 자세의 모든 행을 잰다 (`violation`). 위반하면 VIOLATED 가 되고, 기존 gate 가 HOLD 로 거절한다.
- **조각 수**: `m_k = ceil(L_k / sweep_max_m)`, 상한 `--sweep-max-samples` (16) 이다. 묶이면 `cap_bound_steps` 에 남는다.
  servo 경로의 조각은 sub-step (2 ms) 으로 반올림한다.

**3) 정지 계획 출발점이 필요한 이유** (`p/diag_iters.py` · `p/diag_slack.py` · `p/diag_cont.py`).
C1807 t=216 여유 10 mm, 경로 행 on, reference 에서 출발했을 때다.
3 반복은 VIOLATED (servo −20.4 / sweep −18.2 / both −18.0 mm), 6 반복도 VIOLATED 였다.
servo 만 10 반복에서 feasible 이었다. 여유 0 (3 · 5 반복) 도 세 모드 모두 VIOLATED 였다.
reference 가 막대를 관통한다. 그래서 waypoint 행은 명령을 막대 너머로 밀고, 늦게 따라오는 경로 행은 로봇을 되돌린다.
t=216 에서는 첫 반복을 경로 행 없이 돌려도 (continuation), slack 을 행 · 제어 행 · 하나로 묶어도 VIOLATED 였다.
정지 출발을 넣으면 위 세 청크 × 세 모드가 모두 3 반복 안에 feasible 이다.
정지 계획은 reference 가 위반할 때 merit 이 더 낮을 때만 쓰인다 (`initial_source` 에 기록).

구성 (3 차, servo + sweep, 중앙):
- 경로 행 조립 (`timing_ms.path`, 3 반복 합) 22.8 ms
- QP 8.8 → 21.5 ms (행 192 개 · 하삼각 블록)
- check (merit 의 경로 검사 포함) 9.9 → 25.3 ms
- linearize 95.9 → 102.6 ms (잡음 범위)

합이 ≈ 50 ms 이고 청크별 차의 사분위 (+50 – +83 ms) 와 맞는다. 검사 자세는 중앙 8 · 최대 16 개였다.

- 시뮬레이션 루프는 동기식이고, SQP 는 `min_iterations = 3` 까지 시계를 보지 않는다 (T31). 그래서 이 시간이 제어 주기를 깨지 않는다.
  실기처럼 비동기로 돈다면 ~50–80 ms 는 15 Hz 주기 (66.7 ms) 에 맞먹는다. 그때는 `--sweep-max-mm` 를 키우거나
  `--sweep-rows-per-step` 를 줄이는 것이 손잡이다 (측정하지 않음).
- 서버 시작 때 FK map 을 미리 짓는다 (켰을 때만): bucket 8 · 16 · … · 128 × (기울기 유/무).
