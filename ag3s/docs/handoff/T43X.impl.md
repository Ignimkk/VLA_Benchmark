# T43X — 구현 (policy-blind obstacle · obstacle-scene statistic fix)

> writer: ag3s-implementer (A1) · 읽는 쪽: verifier, scribe, lead · 2026-10-06
> 근거: `T42-2.verify.json` `invisible_diag` (장애물이 보이면 첫 청크 0.04–0.14 rad 차, E0 4/14 vs 7/7), `T43.task.md` 사용자 승인 X.

## 무엇을 했나 (평이한 요약 먼저)

`pi05_infer.py --obstacle-policy-hidden` 을 켜면 장애물의 visual geom 이 **정책 RGB 세 장 (head · 양 wrist) 에서만** 빠진다.
AG3S 로 가는 depth, `--record` 3인칭 영상, viewer 에는 그대로 보이고 collision 도 그대로다. 기본은 off 이고, off 이면 이전 코드와 bit 단위로 같다.
따로, 장애물 XML 의 parked slot 때문에 `stat.extent` / `stat.center` 가 달라지던 문제를 고쳤다. 이제 slot 을 하나도 놓지 않은 장애물 장면은 일반 장면과 pixel 단위로 같다 (정책 RGB 3대, depth 3대).

방식은 이렇다. 정책 RGB 는 원래 전용 renderer (`renderer_pol`) 로 그리고, depth 는 `TransportScene.capture` 가 자기 renderer 로 따로 그린다. 그래서 별도 render pass 를 만들 필요가 없었다.
`build_obs` 를 부르는 동안에만 장애물 visual geom 의 `geom_group` 을 5 로 옮겼다가, 블록이 끝나면 (예외가 나도) 원래 값으로 되돌린다.
MuJoCo 기본 `mjvOption.geomgroup` 은 `1 1 1 0 0 0` 이므로 이 geom 은 `mjvScene` 에 아예 들어가지 않는다. 따라서 shadow 와 reflection 도 남지 않는다.

3인칭 record frame (front, 640x480) 은 visible 과 plain 사이 9209 값이 다르다. hidden render 를 거친 뒤에도 visible 과 bit 단위로 같다.

**Shadow / reflection 정리.** 정책 render 는 원래 reflection 을 끈다 (`POLICY_RENDER_REFLECTIONS = False`). shadow 는 켜져 있어서 visible 일 때 silhouette 밖 pixel 이 바뀐다 (위 표 48 / 177).
hidden geom 은 `mjvScene` 에 없으므로 shadow 를 드리울 수 없고, hidden vs plain 은 3대 모두 0 이다. 그래서 별도의 shadow-casting 처리는 필요 없었다.

## verifier 가 알아야 할 것

- **새 플래그:** `--obstacle-policy-hidden` (기본 off). off 이면 client 코드가 bit 단위로 같다 (test 9).
- **XML 변경은 플래그와 상관없이 적용된다.** 장애물 profile 로 도는 모든 run 의 정책 RGB 와 depth 가 이 수정으로 미세하게 바뀐다 (transport 기준 head ~116 값, depth ≤ 4.4e-5 m).
  즉 T43X 이전 장애물 run 과 이후 run 은 pixel 수준에서 같은 조건이 아니다. 대신 이후 run 은 no-obstacle twin 과 정확히 같은 조건이 된다.
  block 장면 (`--model rby1` + 장애물) 은 차이가 크다 (head 149864 값).
- AG3S 서버의 attention 은 request 의 `images` (정책 RGB) 에서 온다. 그래서 모드가 on 이면 **attention 도 장애물을 보지 못한다.** depth, raw cloud, ESDF 는 장애물을 본다.
  장애물은 attention 이 0 인 영역, 즉 obstacle 쪽으로 분류될 것으로 예상하지만 확인하지 않았다 (`not measured`).
- `geom_group` 변경은 main thread 안에서 `build_obs` 동안만 일어난다. passive viewer 는 `sync()` 때 상태를 복사하고, 그 `sync()` 도 같은 thread 에서 블록 밖에 불린다.
  headless 에서는 문제가 없다. viewer 가 render thread 에서 그 사이에 model 을 읽으면 이론상 한 frame 깜빡일 수 있지만, viewer 화면에만 해당한다.
- local PC client (`~/dev_ws/vla/pi0_TO_ws`) 에 이 변경 (pi05_infer.py, XML 2개, pick_place_obstacles.py) 이 동기화되어야 실기 run 에서 쓸 수 있다.
- 재생산이 필요한 산출물: 없음 (새 run 에만 적용된다).
- 옛 기록과 호환: manifest, npz, request 의 키 집합은 off 일 때 그대로다.
