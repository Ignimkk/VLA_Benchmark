# AG3S 적용 시 사과 파지 실패: 원인 분석과 재구현 지침

작성일: 2026-09-28

목적: VLA 단독 실행은 사과 pick-and-place를 수행하지만 AG3S+TO 적용 시 파지에 실패하는 문제를 수정하기 위한 통합 문서다. 원인 분석, self-filter와 접촉 허용의 관계, 조작 대상과 attention의 분리, 수정 항목 3·4·5, HOLD의 동작과 필요성을 한 문서에 정리했다.

이 문서는 **현재 구현과 기록에서 확인한 사실**, **그 사실을 연결한 원인 해석**, **앞으로 구현할 제안**을 구분한다. 제안된 수정은 아직 구현하거나 새 rollout으로 검증하지 않았다. 숫자 기준을 제시하지 않은 허용오차·시간 한도는 로봇과 기록으로 결정해야 하며, 임의의 상수를 확정 사양으로 받아들이면 안 된다.

## 1. 핵심 결론

가장 강한 증거가 있는 실패 경로는 다음과 같다.

```text
손이 사과에 접근
→ self-filter가 사과 관측까지 제거
→ grounding이 다른 물체를 target으로 반환
→ 접촉 허용 대상과 fine/target-free 영역이 그 물체를 따라 이동
→ 사과가 잡는 손가락에게 다시 회피 대상이 됨
→ 충돌 판정 또는 지각 미인증
→ 실행 게이트가 HOLD 선택
→ 그리퍼 닫힘 명령이 실제 실행되지 않음
```

이와 별도로, 실행하기 전의 닫힘 명령을 보고 파지 상태를 갱신하는 경로가 있다. 닫힘이 HOLD로 취소돼도 내부에서는 물체를 잡았다고 판단할 수 있다. 잘못된 attached 기하가 이후 충돌 판정을 악화시킬 수 있다.

**큰 TO 궤적 변경은 실패의 필수 조건이 아니다.** T16은 TO 출력이 VLA와 사실상 같아도 실패했다. 그러나 이것이 **충돌 ON의 TO가 무해하다**는 뜻은 아니다. T17 shadow의 TO 출력은 파지 구간에서 상당한 관절 변경을 보였다. 지각/접촉 모델, 최적화, 실행 게이트를 나눠 검증해야 한다.

## 2. 확인한 증거와 측정 범위

### 2.1 원본 로그 재계산

각 청크 첫 8스텝, 양팔 14개 관절에 대해 refined-reference 절댓값의 최댓값을 구했다. 그리퍼 두 열은 관절 편차에서 제외했다. 사과 높이는 planning 프레임의 표본 기준이다.

| 실행 | planning 청크 | unsafe 청크 | 실제 HOLD control 스텝 | 실행 구간 관절 편차 최대 | 사과 최대 상승 |
|---|---:|---:|---:|---:|---:|
| T14 closed loop | 30 | 2 | 16 | 5.62309° | 0.00136 mm |
| T16 충돌 제약 OFF | 34 | 25 | 200 | 0.00019850° | 0.44771 mm |
| T17 shadow, VLA 원본 실행 | 75 | 1 | 0 | 8.59453° — 미실행 TO 출력 | 240.97416 mm |

T16은 t=72부터 마지막 t=264까지 모든 planning 청크가 unsafe였다. t=176의 왼 그리퍼 원본 첫 명령은 0.0219, t=208은 0.0258로 닫힘이지만 해당 청크는 실행되지 않았다. T17은 t=112 청크의 index 3, 즉 t=115에서 0.9918 → 0.000318의 닫힘 명령을 실행했다. 이 action 규약에서 1은 열림, 0은 닫힘이다.

세 실행 모두 reference/refined의 그리퍼 열 차이는 정확히 0이었다. 따라서 확인된 문제는 **TO가 그리퍼 값을 변형한 것**이 아니라 **실행 게이트가 그 명령을 버린 것**이다. 팔 궤적만 바뀌어도 그리퍼 닫힘과 손 위치의 관계가 깨질 수 있으므로, 그리퍼 열 보존만으로 파지 보존을 보장하지는 않는다.

T17의 접근 구간 t=0..120에서 청크별 최대 관절 편차의 중앙값은 1.46883°, 최대값은 8.59403°였다. T17a의 손끝 편차 중앙값 19.55 mm, 최대 210.33 mm는 기존 검증 문서의 FK 분석이며 이번 분석에서 독립 재계산하지 않았다. 해당 TO 출력은 shadow에서 실행되지 않았다.

### 2.2 코드 최소 재현으로 확인한 동작

- 반지름 20 mm인 로봇 구의 중심에서 50 mm 떨어진 점은 실제 구 표면에서 30 mm 밖에 있지만, 기본 inflation 50 mm에 의해 제거됐다.
- `TargetConfirm(frames=3)`에 apple을 준 다음 crate만 주자, 첫 소실 프레임에 `unobserved`로 crate가 반환됐다. 내부 held centroid는 아직 apple이었다.
- `GraspLatch`에 score=0.015, runner_up=0인 같은 이름을 3프레임 주면 잠겼고, 이후 닫힘 명령만 주면 접촉·실행 증거 없이 attach 이벤트가 발생했다.

이 재현은 해당 함수의 동작을 확인한 것이며, 실제 씬의 모든 인과관계를 새 rollout으로 입증한 것은 아니다.

### 2.3 기존 기록에서 확인되는 상류 현상

T14.audit에는 접근 중 사과가 영상에 계속 보이는데 self-filter를 통과하는 사과 픽셀이 사라지는 측정이 있다. 이후 grounding centroid가 사과에서 crate 또는 다른 과일 쪽으로 이동한다.

T17a는 t=72..120의 target centroid가 crate 쪽으로 이동했고, 사과가 최악 표면으로 식별된 5개 행은 모두 coarse 계층에서 질의됐다고 보고한다. 해당 거리장은 현재 구름만이 아니라 누적 관측을 포함한다. 이번에는 서버 ESDF 원본을 독립적으로 재생성하지 않았다.

## 3. 수정 항목 1: 사과 관측을 보존하되 접촉은 쌍별로 허용

### 3.1 왜 충돌 객체인 사과를 관측에 남겨야 하는가

**사과가 어디 있는지 아는 것과, 어떤 로봇 부위가 사과에 접촉해도 되는지 결정하는 것은 다른 처리다.**

| 충돌 쌍 | 파지 접근·닫힘 중 처리 |
|---|---|
| 활성 손의 허용된 손가락 링크 ↔ 확인된 사과 | 파지에 필요한 접촉 허용 |
| 팔·몸통·반대 손 ↔ 사과 | 충돌 회피 유지 |
| 활성 손가락 ↔ 테이블·바구니·다른 물체 | 충돌 회피 유지 |

손바닥 등 추가 링크에 접촉을 허용할지는 실제 grasp 형상에 맞춰 명시적으로 결정한다. 활성 손 전체나 로봇 전신에 일괄 허용하는 것으로 확장하지 않는다.

현재 target-free 거리장은 권한 있는 링크가 질의할 때 사과를 제외한 주변 장애물까지의 거리를 읽도록 하려는 구현이다. 일반 로봇 부위는 사과가 포함된 원래 거리장을 읽어야 한다.

따라서 **사과 표면 보존과 올바른 접촉 허용을 함께 수정해야 한다.** 보존만 고치면 사과를 더 확실한 장애물로 만들어 파지를 막을 수 있다. 반대로 사과를 전체 지도에서 삭제하면 반대팔·몸통에 대한 충돌 보호까지 사라진다.

### 3.2 현재 문제

`PointCloudConfig.self_filter_inflation`의 기본값은 0.05 m다. `robot_sphere_mask()`는 물체 정체와 무관하게 로봇 구의 반지름+inflation 안의 점을 제거한다. 동일한 판정이 depth의 robot mask에도 적용된다.

현재 서버 생성 경로는 `AG3SConfig.from_dict()`에 range 등의 값을 넣고 inflation은 코드 기본값을 사용한다. `rby1_three_camera.yaml`에 적힌 0.02 m를 바꾸는 것만으로 이 경로가 바뀌지 않는다. constraint sphere를 줄이는 옵션도 별도의 self-filter 모델은 줄이지 않는다.

사과 픽셀을 mask하면 그 광선은 미관측으로 취급된다. 이것은 이미 누적된 TSDF의 사과 표면을 자유 공간으로 지운다는 뜻이 아니다. 따라서 **새 grounding 관측에서는 사과가 사라지고, 장애물 지도에는 이전 사과 표면이 남는 상태**가 가능하다.

### 3.3 재구현 방향

- 몸통·팔과 손가락·손바닥의 필터 여유를 분리하거나, 렌더링한 실제 로봇 표면을 기준으로 mask한다.
- depth 오차·보정 오차를 흡수할 여유는 남기되, 외부 물체 전체를 로봇으로 분류하지 않는지 검증한다.
- 전체 inflation만 줄여서 해결했다고 판단하지 않는다. 기존 base 누수·로봇 자기 표면의 장애물화가 재발하는지도 확인한다.
- 사과 주변을 무조건 필터 예외로 만드는 경우에도 로봇 표면이 함께 남을 수 있으므로 별도 검증한다.
- 실제 적용 설정과 self-filter/constraint 모델의 구성을 실행 기록에 남긴다.

검증 조건: 접근 마지막 구간에도 사과 표면이 유지되고, 로봇 자기 표면이 장애물로 누출되지 않아야 한다. 이때 사과에 대한 권한 없는 링크의 충돌 검사는 살아 있어야 한다.

## 4. 수정 항목 2: 조작 대상 정체와 순간 attention target 분리

### 4.1 세 가지 서로 다른 정보

| 정보 | 의미 | 예시 |
|---|---|---|
| attention target | 이번 관측에서 정책의 주의가 향한 대상 | 사과 또는 바구니 |
| manipulated object | 이번 파지·운반 동작의 대상으로 확인한 물체 | 사과 |
| destination | 사과를 가져다 놓을 대상 또는 영역 | 바구니 내부 |

정책은 사과를 잡기 직전이나 운반 중에 바구니를 볼 수 있다. 사과가 손에 가려져 attention 후보에서 빠질 수도 있다. 이 변화가 조작 대상을 바구니로 바꿔야 한다는 뜻은 아니다.

```text
접근: attention=사과, manipulated=사과
닫힘: attention=사과 또는 바구니, manipulated=사과
운반: attention=바구니, manipulated=사과
놓임 확인: manipulated의 파지 상태 해제
```

### 4.2 현재 문제

`TargetConfirm.select()`는 held 물체가 현재 cluster에 없으면 `unobserved` 분기에서 leader를 즉시 반환한다. 3프레임 확인은 내부 held 갱신을 늦추지만 downstream target 출력을 보호하지 못한다. 기본 score threshold도 0이라 낮은 점수의 대체 물체가 통과한다.

`GraspLatch`는 이미 있지만, 파지 전 fine 중심과 target-free 제외 기하는 현재 grounding target을 사용한다. 조작 대상 기억이 접촉 허용 계산까지 일관되게 연결돼 있지 않다. cluster index는 프레임 간 영속 ID가 아니다.

### 4.3 재구현 계약

- 확인된 조작 대상에는 프레임 간 ID를 부여하고, 접촉 허용과 제외 기하가 이 ID를 참조하도록 한다.
- 관측 소실을 새 물체 확인으로 취급하지 않는다. `visible`, `occluded`, `uncertain`, `lost` 등 정체와 관측 상태를 별도로 표현한다. 상태 이름은 제안이다.
- 마지막 위치를 무기한 확정 사실로 사용하지 않는다. 마지막 관측 시각·위치 불확실성·가림 근거·재관측 결과를 함께 관리한다.
- 불확실성을 보상하려고 제외 구를 계속 키우지 않는다. 주변 장애물까지 삭제하는 오류가 된다.
- 조작 대상 변경은 작업 전환·명시적 재선택·실패 복구 절차로 처리한다.
- attention이 다른 물체를 향했다는 이유만으로 destination을 무조건 확정하지 않는다. 목적지 가설도 별도로 확인한다.
- 소실 때 단순히 target=None을 반환하는 것만으로 끝내지 않는다. 현재 구조에서는 no_target HOLD가 반복될 수 있으므로 재관측·추적·재선택 절차와 연결해야 한다.

검증 조건: 접근 중 attention을 바구니로 바꾸거나 사과를 잠시 가려도, 확인되지 않은 새 물체에 사과의 접촉 권한이 넘어가지 않아야 한다.

## 5. 수정 항목 3: 실행 경로를 덮는 fine/target-free 거리장

### 5.1 서로 분리할 결정

| 결정 | 입력 |
|---|---|
| 접촉 허용할 물체 | 확인된 manipulated object의 ID와 기하 |
| 허용할 로봇 부위 | 활성 손의 명시적 contact-link 집합 |
| 정밀 거리장 배치 | 현재 손 자세와 곧 실행할 손의 경로 |
| 계속 회피할 표면 | 테이블·바구니·다른 물체·정적 기하 |

fine 영역과 제외 기하를 모두 순간 attention centroid 하나에 묶지 않는다.

### 5.2 현재 동작과 실패 조건

`CuroboFieldBuilder`는 target 점군 평균으로 fine 중심을 정하고, target-free는 fine 한 겹만 만든다. `target_free_distance()`는 그 창 밖에서 target이 포함된 원래 거리장을 반환한다. 이는 구현상 확인된 동작이다.

창 내부에서도 창 밖 장애물에 대한 경계 처리가 있으므로 단순히 중심점이 격자 안에 있다는 것만으로 충분하다고 가정하지 않는다. 보간 영역과 거리 계산에 필요한 주변 범위를 함께 확인해야 한다.

### 5.3 구현 순서 제안

1. 현재 자세와 앞으로 실행할 VLA 구간에 FK를 적용해 허용 링크들의 충돌 구 위치를 계산한다.
2. 현재 위치부터 실행 구간 동안 지나갈 공간을 구 반지름·충돌 여유·보간 및 기울기 계산 영역과 함께 포함하도록 fine 창을 정한다.
3. 그 창에서 확인된 조작 대상만 제외한 target-free 필드를 만든다. fine 창 확대와 대상 제외 영역 확대를 혼동하지 않는다.
4. TO가 수정한 후보 및 최종 경로도 해당 영역을 벗어나지 않는지 검사한다. 필요한 경우 확장/재배치/재계산하거나 검증 불가를 명시한다.
5. 파지 확인 뒤에는 attached 물체 형상까지 실행 경로의 검사 범위에 포함한다.

종단 자세 몇 개의 검사만으로 그 사이 연속 움직임의 무충돌까지 입증되지는 않는다. 샘플 간 최대 이동량에 맞춘 보간 검사 또는 swept-volume 검사를 별도로 정의한다.

다음 경우를 기록한다: 어떤 계층이 답했는가, target-free 적용 여부, 제외 object ID, query link, 지도 버전, 창 밖/미관측 여부. 창 밖을 자유 공간으로 해석하거나 coarse fallback을 성공한 접촉 허용으로 기록하지 않는다.

검증 조건: attention 이동과 TO 경로 변경에도 손의 검사 구간이 필요한 해상도·접촉 정책으로 평가돼야 한다. 사과를 제외한 손가락 질의에서도 테이블·바구니는 남아 있어야 한다.

## 6. 수정 항목 4: 실제 실행과 파지 확인에 기반한 attach

### 6.1 attach가 의미하는 것

attach는 물체가 손에 붙어 함께 움직인다는 충돌 모델의 선언이다. 파지를 시도한다는 표시가 아니다. 물체 기하를 부착 좌표계에 저장해 손의 FK로 이동시키므로, 빈손이나 멀리 있는 물체를 attach하면 유령 기하가 생긴다.

현재 `_run_latch()`는 실제 gripper 관측 대신 `chunk[0, column]`을 읽는다. 호출 시점은 TO 판정과 클라이언트 실행 전이다. 손-대상 근접 확인도 없다. 그리퍼가 청크 중간에 닫히면 첫 행만으로는 그 시점도 알 수 없다.

### 6.2 상태와 증거

| 상태 | 의미 | attach |
|---|---|---|
| 대상 확정 | 파지 대상 ID 확인 | 하지 않음 |
| 닫힘 시도 | 닫힘 명령을 실제 제어기에 전달 | 아직 확정하지 않음 |
| 파지 확인 | 관측·접촉 등으로 해당 물체 파지 확인 | 수행 |
| 놓임 확인 | 물체가 손에서 분리됐음을 확인 | detach |

이 표는 제안된 구분이다. 현재 enum을 그대로 묘사한 것이 아니다.

파지 확인 근거는 실제 개도 변화, 물체가 손가락 사이 파지 영역에 있는지, 접촉/힘/전류, 손과 물체의 상대 움직임 등 사용 가능한 정보를 조합한다. 닫힘 자체만으로는 빈손을 구분하지 못한다. MuJoCo의 실제 접촉을 이용해 판정기를 먼저 검증할 수 있지만, 배포 시 사용할 추정치와 시뮬레이터 참값 평가는 구분한다.

**접촉 허용은 파지 확인 전에 필요하고 attach는 파지 확인 뒤에 한다.** attach를 접촉 허용의 선행 조건으로 두면 접촉하지 못해 파지 확인도 못 하는 순환이 생긴다.

### 6.3 실행 피드백 계약 제안

실행 측은 계획 청크 ID, 실제 실행 스텝 수, 적용 action/그리퍼 명령, 측정 q·dq·개도, 제어 모드, HOLD/중단 사유와 시각을 다음 요청에 전달한다. 서버가 제안한 청크가 아니라 이 피드백을 실행 사실로 사용한다.

HOLD 중에도 실제 접촉·개도 변화가 있다면 관측에 기반해 상태를 갱신할 수 있다. 다만 **취소된 명령 자체는 파지 증거가 아니다.**

권장 처리 순서:

```text
직전 실행 피드백 + 현재 관측 수신
→ 조작 대상 추적 및 실제 파지/놓임 상태 갱신
→ 해당 상태로 world/target-free/attached 기하 생성
→ VLA 청크 최적화
→ 후보와 현재 실행 조건 검증
→ 실행 모드 선택
→ 실제 적용 명령·결과 기록
```

현재 `_scene_fn()`은 제약 생성 후 `_run_latch()`를 호출한다. 이 순서를 유지한다면 attach/detach에 의해 이미 만든 제약이 무효화되는지 확인하고 필요하면 재생성해야 한다. state/map/constraint 버전으로 불일치를 검출하는 것이 좋다.

attach 시 물체와 손 자세는 같은 시점으로 정렬한다. 물체가 강체로 고정되는 부착 좌표계를 선택하고, 움직이는 finger link를 사용한다면 그리퍼 개도에 따른 상대 이동을 올바르게 모델링해야 한다.

### 6.4 이전 계획도 실행 사실과 분리

현재 `safe_policy`는 클라이언트 실행 결과를 알기 전에 refined를 이전 청크로 저장한다. 연속성 참조는 이전 청크의 앞 K스텝이 실행됐다고 가정해 뒤를 자른다. HOLD 또는 부분 실행이면 이 가정이 틀린다.

계획 캐시와 실행 이력을 분리한다. 실제 실행 수에 맞춰 연속성 참조를 정렬하고, HOLD/중단 뒤에는 현재 상태로 재설정하거나 해당 항을 유효하지 않은 것으로 처리한다. 이전 계획을 단순 초기 추정으로 재사용하는 것과 이미 실행한 것으로 가정하는 것은 구분한다.

검증 조건: 닫힘이 제안됐지만 실행되지 않은 경우 파지 증거 없이 attach하지 않는다. 빈손 닫힘도 attach하지 않는다. 청크 중간 닫힘, 부분 실행, 이미 잡은 상태에서 HOLD, 놓임과 slip도 구별한다.

## 7. 수정 항목 5: TO 비용·제약·시간 예산 분리 검증

### 7.1 현재 최적화 요소

| 요소 | 역할 |
|---|---|
| VLA 추적 | 원본 관절 궤적 보존 |
| 평활화 | 관절 위치의 2차 차분 억제 |
| 이전 계획 연속성 | 시간 정렬된 이전 계획의 겹치는 구간과 차이 억제 |
| 충돌 제약·위반 비용 | 허용되지 않은 접촉 회피 |
| 관절 위치·속도·가속도 한계 | 로봇 실행 범위 제한 |

정정: 문서와 일부 코드 주석은 평활화를 jerk라고 부르지만 현재 `problem.py`는 `np.diff(Q, n=2)`를 사용한다. 위치의 2차 차분은 시간 간격을 고려하면 가속도에 대응하고, 위치 기준 jerk는 3차 차분이다. 이름과 수식을 일치시켜야 한다. 시간 간격을 바꾸면 비용과 한계의 단위·스케일도 재검토한다.

### 7.2 먼저 저장 입력으로 비교

같은 관측·reference·현재 상태·확인된 접촉 정책을 고정하고 다음을 비교한다. closed loop에서 서로 다른 관측과 정책 출력이 생긴 뒤의 차이를 같은 입력 실험으로 해석하지 않는다.

| 비교 | 확인할 것 |
|---|---|
| 충돌 OFF, 평활화·연속성 OFF, 추적 유지 | 실행 가능한 reference가 원본으로 반환되는가 |
| 평활화만 추가 | 접근 자세·닫힘 시점의 손 자세 변경 |
| 연속성만 추가 | 이전 계획이 현재 정책 의도를 과도하게 끌어당기는가 |
| 올바른 쌍별 접촉 허용으로 충돌 ON | 어떤 실제 장애물 때문에 수정되는가 |
| 같은 조건에서 시간·반복 예산 증가 | feasibility, 비용, 손 경로가 개선되는가 |

원본이 joint limit 등을 넘으면 충돌과 평활화를 꺼도 수정될 수 있다. 원본의 한계 초과량을 함께 기록한다. 추적 비용까지 없애면 원본 복원 검사가 아니므로 `w_track`은 유지한다.

### 7.3 시간 예산과 후보 선택

원본 로그에서 T14 30/30, T17 75/75청크가 시간 예산 도달 note를 남겼다. 각각 28개/74개는 SQP 1회 뒤 종료했다. 이는 수렴 부족 가능성을 말하지만 단독으로 실패 원인을 입증하지 않는다. feasible한 해가 예산으로 중단되는 것과 미해결 위반이 남은 것은 구분한다.

추가 코드 점검 사항: `sqp.py`는 초기 iterate의 merit를 계산하고도 `best_merit=np.inf`로 시작한다. 첫 candidate가 초기 iterate보다 나빠서 반복점으로 수락되지 않더라도 반환용 best로 저장될 수 있다. 이후 예산으로 종료하면 그 후보를 반환할 가능성이 있다. **이 경로가 실제 rollout 실패를 만들었는지는 아직 재현하지 않았다.**

초기 궤적을 비교 대상에 포함하고, 수락된 반복점·최선의 feasible 후보·위반이 남은 후보를 구분한다. 후보의 상태를 최종 기하와 실제 한계로 다시 검증한다. 단순히 초기 merit 대입 한 줄만 바꾸고 모든 후보의 적격성이 같다고 가정하지 않는다.

### 7.4 파지 보존 지표

- 그리퍼가 닫히는 정확한 실행 스텝에서 손의 위치·방향 및 사과의 파지 영역 포함 여부.
- 실행 구간별 joint 최대 편차와 손끝 위치·방향 편차. 전체 원소 중앙값 하나로 축약하지 않는다.
- 그리퍼 명령, 실제 적용 명령, 측정 개도, 그때의 손 자세.
- 활성 충돌 행의 link/object/계층/clearance와 접촉 정책. 최악 한 행만으로 모든 수정 원인을 설명하지 않는다.
- reference 한계 초과량, SQP/QP 반복 수, 예산 도달, 후보 수락/거절, 최종 위반.

그리퍼 열을 보존해도 팔 경로가 달라지면 빈 공간에서 닫을 수 있다. 수정된 팔과 원래 그리퍼 타이밍의 조합을 검증해야 한다.

## 8. 현재 HOLD 방식과 반드시 필요한지에 대한 판단

### 8.1 현재 HOLD는 무엇을 하는가

서버의 `TrajOptStatus.safe`는 optimal/feasible만 참이다. 클라이언트는 closed loop에서 safe=False이면 실행을 거부한다. 카메라·서버 오류, 응답 시간 초과, sequence 불일치, action 차원 오류 등도 HOLD로 모인다. shadow는 기하 unsafe에 대해서는 원본을 실행하지만 통신·형식 오류까지 무시하는 모드는 아니다.

실제 로컬 제어 루프는 HOLD 중 매 control step에 다음을 한다.

```python
action = rby1_state()  # 이번 스텝의 측정 관절값과 측정 그리퍼 개도
apply_action(..., action, ...)
```

즉, **매 스텝 현재 측정 자세를 새로운 위치 목표로 다시 준다.** HOLD 진입 순간의 목표를 고정해서 유지하는 방식이 아니며, 제어 출력을 끄거나 물리 시뮬레이션을 정지하는 방식도 아니다. `executed=False`는 정책 청크를 실행하지 않았다는 뜻이다. 대체 유지 명령은 계속 전달되고 물리 시간도 진행된다.

클라이언트 `_hold()`가 반환용 청크를 만드는 경로와 로컬 루프가 실제 적용하는 위 경로는 다르다. 현재 `pi05_infer.py`에서 물리 동작을 결정하는 것은 후자다.

### 8.2 왜 파지를 방해하는가

원본이 팔 접근과 그리퍼 닫힘을 명령해도 HOLD는 두 채널 모두 현재 측정값으로 바꾼다. 열려 있는 손은 닫힘 명령을 받지 못한다. 다음 청크에도 같은 모델 오류가 남으면 다시 HOLD하므로 재시도만으로 회복되지 않을 수 있다.

HOLD 중 실제 관절은 관성·중력·접촉·제어기 오차의 영향을 받는다. 움직인 측정값을 다음 목표로 계속 받아들이면 진입 자세로 복원시키는 위치 오차가 유지되지 않을 수 있다. 이것이 drift의 가능한 기전이다. **현재 기록에 모든 ctrl·토크가 없으므로 관측된 drift의 원인을 이것으로 확정하지는 않는다.**

이미 물체를 잡은 상태에서 측정 개도를 목표로 반복 재설정하는 것도 기존 닫힘 목표·파지력을 유지하는 것과 같지 않다. 접촉에 의해 벌어진 개도를 새 목표로 받아들일 수 있으므로 별도 gripper 유지 정책이 필요하다.

### 8.3 반드시 필요한가

**신뢰할 수 없거나 허용되지 않은 계획의 실행을 막는 기능은 필요하다. 그러나 현재의 “모든 실패를 하나의 HOLD로 처리하고 매 스텝 현재 자세를 목표로 다시 주는 구현”이 필수인 것은 아니다.**

VLA 단독 실행에는 이 게이트가 없어 과제를 성공할 수 있다. 따라서 HOLD는 VLA 과제 수행 자체에 필수 기능이 아니다. AG3S+TO를 충돌 보호 모듈로 사용하려면, 해결되지 않은 충돌·관측 실패·통신 문제에서 어떤 행동을 할지 명시적인 실행 정책은 있어야 한다.

사과 파지에 필요한 허용 접촉은 정상 실행 조건에 포함해야 한다. 이를 충돌 실패로 잘못 분류한 뒤 HOLD를 우회하는 것으로 해결하지 않는다. 반대로 예산 종료만으로 feasible한 청크까지 일괄 거부할 필요도 없다.

### 8.4 권장 실행 정책 구분

아래는 새 설계 제안이며 현재 구현된 기능 목록이 아니다.

| 상황 | 권장 처리 |
|---|---|
| 유효한 지도와 실행 가능한 궤적, 허용 접촉만 존재 | 정상 실행 |
| 시간 예산 도달했지만 최종 검증 통과 | 수렴 여부와 별개로 실행 가능 판정 |
| 실제 비허용 충돌이 남음 | 후보 거부 후 제어된 정지·재계획, 검증된 경우에만 후퇴 |
| 대상 정체·관측 범위가 불확실 | 재관측/추적 복구; 이동 허용 범위는 별도 검증 |
| timeout·sequence·차원 오류 | 새 청크 사용 금지, 로컬 대체 제어로 전환 |
| 이미 잡은 물체가 있음 | 팔 정지와 파지 유지 명령을 별도로 관리 |
| 팔은 멈춰도 닫힘 자체는 유효함 | 손가락 닫힘 경로와 대상 정체를 독립 검증한 경우에만 닫힘 허용 |
| 짧은 유효 구간만 실행하려는 경우 | 해당 구간과 그 끝에서의 정지/유지까지 검증한 뒤 실행 |

팔 HOLD 중 그리퍼를 항상 VLA대로 닫도록 바꾸는 것도 적절하지 않다. 손 위치가 틀렸거나 다른 물체를 끼울 수 있으므로, 부분 실행은 독립된 검증 경로가 있어야 한다. 짧은 prefix 실행도 끝에서 멈출 수 있는지 확인하지 않으면 충분하지 않다.

### 8.5 위치 유지 방식을 개선한다면

단순한 위치 제어 시뮬레이터에서는 HOLD 진입 때 팔의 유지 기준 `q_hold`를 한 번 저장하고, 이후 동일한 기준을 유지하는 방식을 먼저 비교할 수 있다. 매 스텝 현재 측정값으로 덮어쓰지 않는다.

그러나 움직이는 실물 로봇에서 순간 측정 위치를 고정 목표로 바꾸는 것만으로 제어된 정지가 보장되지는 않는다. 현재 속도, 감속 한계, 접촉 상태를 반영한 정지 궤적 또는 하위 제어기의 정지/유지 기능을 사용하고, 정착 뒤 유지 기준을 설정해야 한다. 이미 충돌 중인 자세를 고정해 힘을 계속 가하는 것도 적절하지 않을 수 있다.

그리퍼 목표는 팔의 `q_hold`와 분리한다. 열린 상태에서의 취소된 파지, 실제 물체를 잡은 상태의 파지 유지, 놓기 중단을 구별한다. 정상 경로에서 상태를 모른다는 이유로 기본 열림을 명령해 물체를 놓지 않도록 한다.

HOLD에는 진입 사유, 유지 기준, 경과 시간, 재관측/재계획 횟수, 복구 조건을 둔다. 자동 재개 전에는 현재 상태·지도·계획을 재검증하고, 오래된 청크를 중간부터 재생하지 않는다. 반복 실패가 해소되지 않으면 무한 반복 대신 작업 중단과 원인 보고로 전환한다. 구체적인 한도는 실험으로 정한다.

### 8.6 현재 timeout은 즉시 정지 watchdog이 아니다

`SafeRemoteClient.infer()`의 timeout 검사는 동기식 `_policy.infer()`가 반환된 뒤 경과 시간을 확인한다. 코드상 이 검사가 블로킹 호출을 즉시 중단하거나 호출 대기 중 제어를 수행하는 것은 아니다.

현재 MuJoCo 루프는 추론 대기 중 sim time이 정지한다. 이 특성 때문에 추론 지연이 곧바로 물리적 이동 지연과 같지는 않다. 실물 로봇이나 비동기 시뮬레이터로 옮길 경우 제어 루프와 추론을 분리하고, 로컬 watchdog 및 독립적인 정지/유지 동작을 설계해야 한다. 기존 HOLD 분기만으로 실시간 보호가 이미 보장된다고 해석하면 안 된다.

### 8.7 `--no-collision`과 HOLD의 관계

현재 옵션은 QP 충돌 행과 merit의 충돌 비용을 끄지만, 최종 `worst_row()` 측정과 violated 판정은 남긴다. 그러므로 다음 경로가 가능하다.

```text
충돌 제약 OFF → VLA와 같은 출력 → 최종 충돌 판정 → HOLD → 파지 미실행
```

T16이 이 경우다. 따라서 `--no-collision`을 “모든 안전 개입을 제거한 VLA 기준선”으로 해석하지 않는다. 연구용 비교에서는 충돌 강제, 충돌 측정, 실행 게이트, 실제 실행 출력을 각각 기록한다. shadow의 성공은 특정 기록에서 원본이 수행 가능했음을 보여주지만, 게이트를 실제 운용에서 전역 해제할 근거는 아니다.

## 9. 구현할 데이터 계약 제안

다음 필드는 설계 예시다. 이름보다 정보의 소유권과 갱신 시점을 지키는 것이 중요하다.

| 데이터 | 필수 의미 |
|---|---|
| 조작 대상 상태 | 영속 ID, 기하, 시각, 관측 상태, 위치 불확실성, 파지 단계 |
| 접촉 정책 | 물체 ID, 허용 링크, 적용 단계, 정책 버전 |
| 거리장 출처 | 지도 버전·시각, 창 범위, 해상도, 제외 ID, 관측/미관측 정보 |
| 계획 결과 | reference/refined, 적용 접촉 정책, 유효 구간, 잔여 위반, 후보 적격성 |
| 실행 결정 | 실행/정지/유지/복구 모드, 선택 이유, 사용할 계획 ID |
| 실행 피드백 | 실제 적용 action, 실행 스텝 수, q/dq/개도, HOLD 기준, 시각 |
| attached 상태 | 확인한 물체 ID, 부착 프레임·변환·기하, 확인 근거와 시각 |

충돌 측정, solver 종료 사유, 지도 유효성, 실행 결정을 단일 bool 하나의 설명으로 축약하지 않는다. 최종 실행 가능 bool이 필요하더라도 원인과 근거는 구조화해 보존한다.

## 10. 구현 순서와 완료 기준

1. 기록에 실제 적용 action·실행 스텝 수·그리퍼 관측·지도/대상 정체를 추가해 계획과 실행을 비교 가능하게 한다.
2. self-filter의 대상 보존과 manipulated identity 유지, 쌍별 접촉 허용을 연결한다. 한 항목만 바뀐 중간 결과로 성공을 선언하지 않는다.
3. 실행 경로를 덮는 fine/target-free 범위와 후보의 창 이탈 검사를 구현한다.
4. 실행 피드백 기반 latch/attach, 제약 재생성 순서, 이전 궤적 정렬을 수정한다.
5. 실행 게이트의 실패 사유를 나누고 HOLD 진입·유지·복구와 그리퍼 정책을 구현한다.
6. 고정 입력 ablation으로 TO 항별 영향과 후보 선택·시간 예산을 검증한다.
7. 동일 초기조건과 가능한 동일 정책 seed로 closed loop를 반복하고, 여러 배치·물체로 회귀 범위를 넓힌다.

### 필수 검증 시나리오

| 시나리오 | 기대 결과 |
|---|---|
| 사과 가까이 접근 | 사과 관측 보존, 로봇 표면 누출 없음 |
| 접근 중 attention이 바구니로 이동 | manipulated ID와 사과 접촉 권한 유지 |
| 사과 일시 가림 | 다른 물체에 권한 이전 안 됨, 불확실성 관리 |
| 손가락-사과 및 손가락-테이블 동시 근접 | 사과 접촉만 허용, 테이블 회피 유지 |
| reference는 창 안, 수정 후보는 창 밖 | 재계산 또는 검증 불가 명시 |
| 닫힘 제안 후 HOLD | 실제 증거 없이 attach하지 않음 |
| 빈손 닫힘·멀리 있는 target | attach하지 않음 |
| 청크 중간 닫힘·부분 실행 | 실제 이벤트 시각으로 상태 갱신 |
| 파지 후 HOLD | 파지 유지 정책 작동, 취소 명령과 실행 이력 구별 |
| HOLD 중 외력·중력 | 목표와 측정값을 각각 기록하고 drift 평가 |
| 예산 종료지만 feasible | 미수렴과 실행 불가능을 구분 |
| 첫 QP 후보가 초기 궤적보다 나쁨 | 부적격/거절 후보를 최선이라고 잘못 반환하지 않음 |
| 통신 지연·잘못된 sequence | 오래된 청크 미실행, 로컬 대체 동작 유지 |

완료 판정은 단위 테스트 개수나 collision violation=0만으로 하지 않는다. 실제 사과 파지·들림·basket place, 비대상 물체/테이블 충돌, 의도하지 않은 놓임, HOLD 빈도·지속시간을 함께 평가한다. 단일 에피소드 성공으로 일반 성공률을 보장하지 않는다.

## 11. 이전 설명과 문서에서 정정·유의할 사항

- “TO는 결백하다”: T16에서 큰 변경 없이 실패한 것은 확인됐지만 충돌 ON의 TO 영향까지 배제하지는 못한다.
- “작은 관절 편차 중앙값”: 전체 원소 중앙값과 청크별 최대 편차의 중앙값은 다르다. 후자는 T14 전체 1.05818°, 접근 구간 1.02108°였다.
- “평활화는 jerk”: 현재 구현은 위치 2차 차분이다.
- T13의 일부 apple 해석은 T14.audit에서 orange로 정정됐다. 대상을 잘못 이름 붙인 측정으로 사과 제외 기하를 튜닝하지 않는다.
- T12의 서버/로컬 기록 일부는 다른 실행이 섞인 것으로 감사 문서에서 지적됐다. seq와 reference 내용까지 맞춰 비교한다.
- T14a의 근처 비대상 물체 이름과 T14.audit의 표현이 일치하지 않는 부분이 있다. 확인되지 않은 이름 대신 비대상 물체로 표현한다.
- sphere 표면 거리, body 원점 거리, 다른 sphere 모델의 거리를 직접 비교하지 않는다.
- T16의 실제 gripper가 끝까지 정확히 -0.045였다는 표현은 전체 control 기록과 일치하지 않는다. robot XML의 qpos index 27 기준 범위는 -0.04994..-0.03745였다. 확실한 사실은 닫힘 명령 미실행이며, HOLD가 물리 자세를 완벽히 고정했다는 뜻은 아니다.
- T17의 사과 상승은 직접 재계산했다. basket place는 기존 실행 보고와 구별해 읽고, 새 검증에서는 별도의 성공 조건으로 판정한다.
