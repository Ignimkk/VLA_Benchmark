# T43Z6 — 구현: held query 구 상한 (`--held-cover-cap-mm`) · HOLD 대신 TO 궤적 따르기 (`--hold-follow-to`)

> writer: ag3s-implementer (A1) · 읽는 쪽: verifier, scribe, lead · 2026-10-06 · 기준 benchmark `cf6b410`

## 무엇을 했나 (평이한 요약 먼저)

두 기능 모두 flag 로 넣었고 기본은 off 다. off 면 비트 동일하다.

1. **held query 구 상한.** attach 때 held query 구를 관측한 사과 크기 근처로 묶는다. 대상은
   body cover 의 `sphere` · `segments` 모드와 H2 덮개 구다.
   - 반지름 ≤ 관측 반폭 + a
   - 중심은 관측 몸통 중심에서 a 안. 밖이면 그 방향으로 당긴다.
   - 같은 구와 다른 구 안에 든 구는 뺀다.

   self-filter 구는 그대로 둔다. 기록된 V5 `segments` 4 run 을 a = 10 mm 로 다시 계산했다.
   - 반지름: 58–59 → 43.3–43.4 mm
   - 반폭 x + 20 mm: 88.6–93.8 → 72.6–72.9 mm. 4 run 모두 crate 안쪽 반폭 82 mm 에 들어간다.
   - 사과 mesh: 2 run 은 다 덮는다. 2 run 은 꼭짓점 1.35 % 가 0.2 / 1.5 mm 밖으로 나간다.
2. **TO 궤적 따르기.** HOLD 였을 청크가 아래 조건을 모두 만족하면 TO refined chunk 를 실행한다.
   verdict kind 는 `follow_to` 다.
   - HOLD 를 만든 행이 `collision` 뿐이다.
   - 그 행이 전부 margin 안쪽이다 (ESDF − r ≥ 0).
   - 그 최소 clearance 가 같은 질의 구의 현재 상태 clearance 보다 작지 않다.
   - 실행할 것이 정책 reference 가 아니다.

   오프라인 재생으로는 기록된 HOLD 중 **확실히 실행으로 바뀌는 청크가 0 개**였다.
   - 1925 s19253 의 손에 쥔 HOLD 20 청크 중 18 개는 확실히 "악화"다. 계획이 구 0 을 지금
     (margin 밖, gap 22.6–44.5 mm) 보다 crate margin 안쪽 깊이 (clearance −3.4 ~ −11.1 mm, 즉 gap 8.9–16.6 mm) 넣는다.
   - 나머지 2 개는 label 이 기록에 없어 판정할 수 없다 (아래 §오프라인 2).

규칙은 코드에서 정의대로 계산된다. 서버에는 label 도 현재 상태 clearance 도 있다.
그래서 규칙을 바꾸지 않았다.

## 규칙과 문턱

### 1. `clustering.held_cover_cap` (`--held-cover-cap-mm MM`, 근거값 10)

`held_object.cap_held_spheres(spheres, centre, half_width, a)`:
```
r_i ← min(r_i, w + a)                       w = 관측 반폭
c_i ← c0 + (c_i − c0)·min(1, a/|c_i − c0|)  c0 = 관측 몸통 중심
dedupe: |c_i − c_j| + r_i ≤ r_j + 0.1 mm 인 i 제거 (같은 구면 앞의 것이 남는다)
⇒ 모든 구 ⊂ 공(c0, w + 2a)
```

기준 (`held_cap_reference`, attach 시점 target cluster):
- 맞춤 accepted: c0 = 맞춘 중심, w = R2 body radius (받침으로 올린 값).
- 맞춤 rejected: c0 = 관측 점 상자 중심, w = 수평 폭의 반.
- 수평 주축이 폭의 1.6 배를 넘으면 (`elongated`, 바나나) 상한을 걸지 않는다 (`cap.skip`).

적용 위치:
- body cover 를 켰을 때: J1 lift 전의 body 구에 건다. 그다음 lift 하고, lift 된 집합을 다시 dedupe 한다.
  sphere 모드의 두 body 구가 같은 높이로 올라 겹치는 것이 Z1 이 말한 중복이다.
- body cover 를 껐을 때: H2 query primitive 에 lift 전에 걸고, lift 뒤 dedupe 한다.
- self-filter 사본 (`filter_spheres_parent_frame`) 은 바꾸지 않는다.

a = 10 mm 를 고른 근거:
- pad 5 + slip 5 와 같은 값이다. sphere 모드의 기존 구 (R + 5, 바닥 구 shift ≤ 10) 는 그대로 남는다.
- crate 안 여유: w + 2a + 20 = 73.4 mm < 82 mm.
- 15 mm 이면 1925 s19253 이 82.6 mm 로 넘친다 (§오프라인 1).

### 2. `clustering.hold_follow_to` (`--hold-follow-to N`)

`SafePolicy._follow_to` 는 `verdict_policy="reasons"` 에서만 돈다. 순서대로 보고, 하나라도 아니면 HOLD 그대로다.

| # | 조건 | 거절 이름 (`summary.verdict.follow_to.refused`) |
|---|---|---|
| 0 | gate 가 이미 execute 면 아무것도 하지 않고 streak = 0 | `decision: not_needed` |
| 1 | HOLD 사유 kind 가 정확히 `{collision}` (uncertified · unverified 등이 섞이면 HOLD) | `hold_kinds` |
| 2 | collision 행이 모두 ESDF 행이다 (plane · candidate 행은 거절) | `no_rows` · `no_collision_rows` · `non_esdf_row` |
| 3 (i) | 행마다 d − r ≥ 0. d 는 `_esdf_clearance` 와 같은 합성이다 (권한 행은 target-free 계층) | `penetration` · `no_distance` |
| 4 (ii) | min clearance(행) ≥ min clearance(같은 질의 구, 정지 계획 Q = q_now 의 첫 스텝, 같은 scene · attached · margin 규칙). 허용 오차 0 | `worsens` · `no_current_state` |
| 5 | 실행 창 (execution_length 8) 의 refined 팔 열과 정책 reference 의 차가 1e-6 rad 초과 | `refined_is_reference` · `no_reference` |
| 6 | streak < N. streak 은 스스로 인증된 청크 (0) 와 `reset()` 에서 0 이 되고, HOLD 로는 줄지 않는다 | `limit` |

통과하면:
- `collision` 사유를 `follow_to` 사유로 바꾼다 (`action: execute`). evidence 에 `replaced` (원래
  collision 사유), `min_esdf_minus_r_m`, `plan_min_clearance_m`, `now_min_clearance_m`, `streak`,
  `limit` 을 싣는다.
- `safe=True` 다. client 는 `actions` (= refined) 를 실행한다. 비-shadow 이므로 정책 reference 가 아니다.
- `trajopt_status` 는 `violated` 그대로 둔다.
- `follow_to` 를 모르는 옛 client 는 HOLD 한다 (fail closed).

5 번 조건의 근거: 사용자 지시는 "정책 reference 가 아니라 TO 궤적" 이다. 그런데 SQP 의
`returned=initial` 은 정책 reference 를 그대로 낼 수 있다 (T43T §1).

## 오프라인 2 — TO 궤적 따르기 재생 (V5 1925 s19253 · 1807 s18071 / s18073 · 1834 s18343)

### 방법

- 서버 기록으로 held 행을 다시 지었다.
  - 기록된 fine/coarse 격자 (`fixed_input_ablation.build_field`)
  - 그 프레임의 `spheres_parent_frame`
  - refined 행 0–7 의 손바닥 FK
- 기록된 worst 행에서 재구성 값이 서버 값과 **0.001 mm** 로 같다 (`fidelity_mm`).
- **label 층은 기록에 없다.** 그래서 margin (20 mm / 0) 이 행마다 정해지지 않는다. label 이 필요 없는 것과 필요한 것을 나눴다.
  - (i) 은 label 이 필요 없고 정확하다. gap < 0 인 행은 margin 과 무관하게 위반이다.
  - plan_min 은 기록된 worst clearance 를 그대로 쓴다.
  - 위반 행 집합은 label 로 한정했다. destination 이면 기록된 worst 보다 낮아졌을 행은 label 이 없는 행으로 본다.
  - (ii) 는 현재 상태 label 의 두 극단으로 묶었다. plan_min 이 아래 극단보다 작으면 확실한 `worsens`, 위 극단 이상이면 확실한 `follow`, 그 사이는 `ambiguous_label` 이다.
- 로봇 행이 위반인 청크 (`nearest_is_not_manipulated`, obstacle margin 10 mm) 는 다시 짓지 않았다. 표에 `robot_rows` 로 남긴다.
- 실제 crate 거리는 Y 의 mesh-vertex 방법이다. 사과 mesh 꼭짓점을 청크 시작 상태 (Y replay) 에서 손바닥과 강체로 계획을 따라 옮겼고, crate box 13 개까지의 signed distance 를 쟀다.

## verifier 가 알아야 할 것

- **새 flag (둘 다 기본 off, off 비트 동일):**
  - `--held-cover-cap-mm MM` = `clustering.held_cover_cap` (m). 근거값 10.
  - `--hold-follow-to N` = `clustering.hold_follow_to`.
  - 둘 다 `--no-safe` · `--no-perception` 과 함께면 거절한다.
  - 시작 로그 `AG3S identity (T43 T fix 3): held_cover_cap=0.01, hold_follow_to=N` 에 찍힌다.
- **기록 키 (켰을 때만):**
  - `grasp.attached.held.body_cover.cap` (body cover on) / `grasp.attached.held.cap` (off).
    내용은 `applied`, `basis`, `half_width_mm`, `radius_cap_mm`, `centre_limit_mm`, 구별 전후, `n_removed`, `n_removed_after_lift` 다.
  - `verdict.follow_to` = `{limit, streak_before, decision, refused, …}`
  - 사유 kind `follow_to` 와 그 evidence.
  - client 의 `last_gate.hold_kinds` 에는 `follow_to` 가 나오지 않는다 (execute 이므로).
- **재생산이 필요한 산출물:** 없음.
- **옛 기록과의 호환:** `AG3SConfig.to_dict()` 의 clustering 에 키 두 개 (null) 가 늘었다. Z3 와 같은 방식이다. `wire.REASON_KINDS` 에 `follow_to` 가 늘었다.
- **closed-loop 짝 비교 시 주의:**
  - `follow_to` 는 snapshot 의 client 도 같은 wire 여야 실행된다. 옛 client 는 HOLD 한다.
  - Z3V snapshot (`work-t43z3`, `cf6b410`) 에는 이 코드가 없다.

## 열린 위험

1. **규칙은 정의대로 구현했지만, 기록된 place HOLD 에는 오프라인으로 거의 발동하지 않는다.** 1925 의 기전은 이렇다.
   - TO 가 지금 침투한 구 1 을 빼는 대신 margin 밖에 있던 구 0 을 crate margin 안으로 넣는다.
   - "위반 행의 질의 구" 의 현재 상태가 비교 기준이라 이 계획은 `worsens` 다.
   - 다른 정의 (현재 상태 전체 held 행의 최소, 또는 침투 행 포함) 는 구현하지 않았다. 사용자 · lead 판정 사항이다.
2. **상한과 따르기의 결합 효과는 재지 못했다.** 상한 뒤 구 1 은 55.8 → ~43 mm 다. 현재 상태 침투와 계획의 crate margin 진입이 함께 줄 것으로 보지만, field · plan 이 바뀌므로 closed-loop 측정이 필요하다.
3. **상한은 덮음을 조금 잃는다.**
   - segments 2 run 은 꼭짓점 1.35 % 가 0.2 / 1.5 mm 밖으로 나간다. 원인은 fit 중심 오차 10–13 mm 다.
   - sphere 모드의 꼭지 덮개 구가 사라진다 (MuJoCo 사과 mesh 에는 꼭지가 없다).
   - 배처럼 아래가 긴 몸통은 바닥 구 shift (> a) 가 a 로 당겨져 아랫부분 덮음이 줄 수 있다. 배 · 오렌지 기록은 재계산하지 않았다.
4. **`follow_to` 는 쥔 상태에 한정하지 않는다.** 규칙 그대로 모든 phase 에 적용된다. 다만 (ii) 때문에 지금 margin 밖에 있는 로봇이 margin 안으로 들어가는 계획은 실행되지 않는다.
5. **현재 상태 clearance 는 정지 계획의 첫 스텝이다.** 손가락 관절 경로는 계획 스텝 0 의 값이다. 쥔 구 행은 손바닥에 붙어 있어 영향이 없다. 손가락 행에는 개도 차만큼 오차가 있다.
6. 1807 s18073 · 1834 s18343 의 `robot_rows` 26 청크와 label 미기록 `ambiguous` 26 청크는 오프라인으로 판정하지 못했다.
