## 무엇을 했나 (평이한 요약 먼저)

미세 거리장 창(과 target-free 창)을 이제 **손이 있는 곳**에 놓는다. 예전에는 창 중심이 target 점 평균이었다. 이제는
권한 link(`contact.contact_links` 중 활성 손)의 구가 `q_now` 에 있는 곳과 실행 구간(`execution_path`, K step) 동안 지나갈
곳을 감싸는 상자로 정한다. 각 구는 `반지름 + 마진 + 보간 여유 2 칸`만큼 넓힌다. 여기에 manipulated 물체 상자까지
합친 것이 창(128³ × 5 mm, 보간 범위 0.635 m)에 들어가면 그 합집합의 가운데에 놓는다. 안 들어가면 지금 손 → 실행
구간(step 순) → 물체 순으로 담고, 넘친 사실을 `stats["window"]` 에 적고 노트로도 남긴다. 제외 기하(`_target_ball`)는
그대로 manipulated 기하만 쓴다. 창을 넓혀도 제외 영역은 넓어지지 않는다.

그 창에서 권한 link 질의점이 **어느 계층의 답을 받았는지**도 기록한다. 계층 이름은 `coarse` / `fine` / `target_free` /
`window_edge` / `outside` / `static` 이다. AG3S 쪽(`q_now` + path 의 권한 구)은 `stats["window"]["authorized_query"]` 와
노트에 적고, TO 쪽(refined 청크의 모든 권한 행)은 `worst_row` 신원의 `tier`·`authorized_rows` 에 적는다. 창 밖 답은
"검증 불가"로 명시하고 재계산은 하지 않는다. guard 반경 규칙(사용자 판정)도 넣었다. 설정값이 0 이 아니면 그 값을
쓰고, 0 이면 manipulated 반지름 + 미세 복셀 1 칸을 쓴다.

**live 경로는 아직 실행 구간을 넘기지 않는다.** `safe_policy._scene_fn` 은 reference chunk 를 받기 **전에** 불리고
(`refiner.refine` 이 `scene_fn(context)` → 그다음 `reference`), 두 파일 모두 이 STEP 의 금지 파일이다. 그래서 지금 live 에서는 창이 `q_now` 의 손(+물체)으로만
놓이고 `hand_source="q_now"` 로 기록된다. `AG3S.process*(..., execution_path=Q)` 는 받을 준비가 되어 있다 (T23 또는 lead 판단).

## 창 배치 규칙과 overflow 처리

```
구마다 상자  = 중심 ± (반지름 + margin + pad_voxels × fine)        margin = esdf.fine_window_margin ?? geometry.safety_margin (0.05)
손 swept     = step 0 (q_now) … step K 상자의 합집합                  pad_voxels = esdf.fine_window_pad_voxels (2)
물체 상자    = manipulated 점 min/max ± pad_voxels × fine
L (축마다)   = (128 − 1) × fine = 0.635 m                               (cuRobo esdf_grid_shape, 계층마다 같음 — 크기는 고정)

1. placement = target_centroid, 또는 손 없음      → 중심 = 물체 점 평균                basis = manipulated
2. 손 ∪ 물체 가 L 에 들어감                        → 중심 = 합집합 가운데              basis = hand_swept
3. 안 들어감 (basis = overflow):
   a. q_now 상자 자체가 L 초과                     → 중심 = q_now 상자 가운데           overflow = hand_now
   b. step 0..k-1 까지만 들어감 (k < K+1)          → 그 k step 은 반드시, 축마다 창을 밀어
                                                     (전체 손 덮는 길이, 그다음 물체) 최대 → 동률이면 가운데    overflow = hand_path
   c. 손 전부는 들어가고 물체가 넘침                → 손 전부 반드시, 물체 쪽으로 최대한 밀기                    overflow = manipulated
   (물체를 한 조각도 못 담으면 밀지 않고 손 가운데 — 여유만 잃기 때문)
미세 계층이 없으면 (fine_voxel_size null)          → 창 없음, stats["window"]["basis"] = None
```

`target-free` 창은 같은 중심을 쓴다 (`_build_tiers` 가 `self._fine_centre` 하나를 읽는다). 넘친 프레임에는 노트 하나가
붙는다: `fine window overflow (<reason>): … placed hand-first, n/N step(s) covered, manipulated covered=…`.

## "검증 불가" 의 정의 (`curobo_field.unresolved_rows`, AG3S·trajopt 공용)

| 계층 | 판정 |
|---|---|
| `fine` · `target_free` · `static` | 풀림 |
| `coarse` · `outside` | **언제나 미해결.** 여유가 커도 그렇다. 창 밖 답을 자유 공간이나 접촉 허용으로 읽지 않는다 |
| `window_edge` | 답은 창 경계 거리 `b` 이고 참값의 하한이다. `b − r − margin ≥ 0` 이면 풀림 (`n_bounded`), 아니면 미해결 |

`window_edge` 를 따로 다루는 이유: 새 창은 권한 구마다 `r + margin + 2 칸` 을 확보한다. 그래서 창 안의 손이
`window_edge` 답을 받는 경우는 가장 가까운 비-target 표면이 경계보다 멀 때뿐이고, 그 하한이 이미 여유를 넘는다.
이것까지 미해결로 세면 모든 프레임에 "unverified" 노트가 붙는다.

- 배치: 합집합이 들어가면 전부 담고 가운데 정렬. 구마다 `r + pad`. 경계 규약이 `_origin_of`·`_covers` 와 같다. 손이 없으면 물체 평균과 **비트 단위로 같다**. `target_centroid` 는 손을 무시한다. 먼 물체는 overflow `manipulated` 로 처리하고 창을 물체 쪽으로 민다. 못 닿는 물체면 손 가운데에 놓는다. 긴 경로는 앞 step 부터 연속으로 담는다(`hand_path`). 손이 창보다 크면 `hand_now`.
- 계층: `fine`/`coarse`/`outside`/`target_free`/`window_edge`/`static` 이 실제 합성 규칙과 맞는다. 4000 개 무작위 점에서 이름과 값이 모순 없음을 성질 테스트로 확인했다. `unresolved_rows` 의 표도 고정했다.
- pipeline: 창을 끄는 것은 권한 link 뿐이다(몸통·반대 손 제외). path 가 상자에 들어가고, path 폭이 틀리면 오류가 난다. margin 은 `geometry.safety_margin` 을 따르고 config 로 덮을 수 있다. 권한이 없으면 물체로 물러나며 그 사실을 기록한다. 옛 규칙은 키 하나로 돌아간다. **제외 공은 창과 무관하다.** 창이 덮으면 `n_unresolved` 0 이고, 창이 1 m 떨어지면 coarse 3/3 에 "unverified" 노트가 붙는다. overflow 도 노트가 된다. `_run` 이 `execution_path`·`contact_context` 를 전달한다.
- guard: 설정값이 0 이 아니면 그 값, 0 이면 반지름 + 미세 복셀(단일 계층이면 그 복셀), 물체가 없으면 0 이고 config 는 그대로다. 프레임 cfg 는 반경 말고는 같다. 파이프라인 2 프레임째에 cloud 필터와 depth mask 가 **둘 다** `반지름 + 복셀` 을 받는다.
- trajopt: `tier` 는 필드의 `answer_tier` 와 같고, 값(`clearance_m`)은 `full_violation` 과 같다. 창이 멀면 `verifiable=False` 와 note, 창이 덮으면 `True`. `relax` 에서는 완화 마진 행이 권한 행이다. legacy `EsdfField` 와 plane 행은 None.

## verifier 가 알아야 할 것

- **새 플래그·기본값 변경**:
  - `esdf.fine_window_placement="hand_swept"` 가 **기본**이다. curobo backend + `fine_voxel_size` 가 있는 모든 실행에서 창 위치가 바뀐다. 옛 동작은 `{"esdf": {"fine_window_placement": "target_centroid"}}`.
  - **guard 가 기본으로 켜진다.** `self_filter_target_guard_radius=0` (기본, `serve_safe` 에서 `--self-filter-target-guard` 를 안 준 경우) 이고 manipulated 물체가 있으면, 두 번째 프레임부터 guard 반경 = 반지름 + 5 mm (미세 복셀) 이다. 사용자 판정대로 구현했다. 다만 **"guard 끔" 을 표현할 값이 이제 없다** (음수는 검증에서 거절). ablation 이 필요하면 lead 판단.
