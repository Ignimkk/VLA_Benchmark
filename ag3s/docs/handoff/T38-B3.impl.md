## 무엇을 했나 (평이한 요약 먼저)

cuRobo 가 만든 거리장 계층(coarse 20 mm · fine 5 mm · target-free 5 mm, 각 128³)을 **더 이상 host 로 내리지 않는다.**
예전에는 청크마다 계층 전부(값 + site, 37–50 MB)를 D2H 하고, TO 가 첫 기울기 질의에서 **격자 전체**에 `np.gradient` 를
돌렸다 — 그런데 TO 가 실제로 묻는 점은 청크당 몇 천 개뿐이다. 이제 계층은 `DeviceEsdfField` 로 GPU 에 남고,
`distance` · `gradient` · `label` 은 **질의점이 쓰는 격자 칸만** 읽어 답한다. 정의는 예전 `EsdfField` 와 하나도
다르지 않고, 결과는 **비트 단위로 같다** (최대 절대 차 0).

나머지 셋: 라벨 층을 GPU 에서 만든다 (`np.unique` 정렬 → GPU scatter, KD-tree 는 update 당 한 번 + 씨앗 상자 밖 site 는
묻지 않음 — 정의상 같은 답), depth 는 카메라당 한 번 올려 두 mapper 가 같은 관측을 쓴다 (cuRobo 는 관측을 읽기만 한다),
`--record-constraints-esdf full` 기록은 GPU 격자를 **쓰는 순간에** (background 면 worker 스레드에서) 가져온다.

결과 (replay E3b_ep1807_r2 seq 2–75, 단독): 청크당 AG3S+TO 중앙 **1,087 → 843 ms** (−243; 반복 쌍 1,125 → 846),
esdf 254 → 68 ms, TO 130 → 69 ms (linearize 94 → 19). D2H 51.4 → 3.5 MB/청크. 모든 출력 · 기록 · 질의 비트 동일,
기준선 둘 소수점 · 프레임별 sha1 까지 동일.

## 기울기 정의와 "같다" 의 증명

**오늘의 정의** (`esdf.py:439-454`, 이번에 고치지 않음):

```python
_grad_cache = np.stack(np.gradient(distance_grid.astype(np.float64), voxel_size, edge_order=1), -1).astype(np.float32)
out = 0;  for (dx,dy,dz) in 코너 순서:  out += ((wx*wy)*wz)[:, None] * _grad_cache[min(i0+(dx,dy,dz), n)]   # float64
```

즉 **격자 위 중심차분 → float32 로 반올림해 캐시 → 8 코너 삼선형 (float64, 코너 순서대로 누적)**. 격자 밖은 0, 해석적
채널이 이기면 그 도형의 기울기. distance 도 같은 삼선형 (float32 값 × float64 가중치).

**`np.gradient(edge_order=1)` 의 복셀 값** (numpy 1.26.4 `function_base.py`, 균일 간격 스칼라 `h`):
내부 `(f[i+1] − f[i−1]) / (2.·h)`, 경계 `(f[1] − f[0]) / h` · `(f[n−1] − f[n−2]) / h` (`f` 는 float64).

**B3 의 계산** — 질의점이 쓰는 코너 복셀에서만, 축마다 `up = min(i+1, n−1)`, `dn = max(i−1, 0)`,
`den = h if i ∈ {0, n−1} else 2.·h` → `float32((f[up] − f[dn]) / den)`. 세 경우가 위 세 식과 **같은 피연산자 · 같은 연산**이다
(내부: up=i+1, dn=i−1, 2h; i=0: up=1, dn=0, h; i=n−1: up=n−1, dn=n−2, h). 그 뒤 float64 로 올려 같은 가중치 · 같은 순서로 누적.

비트가 같은 이유: (1) float32 → float64 는 정확, (2) float64 `+ − × ÷` 는 IEEE 정확 반올림이라 **같은 피연산자 · 같은 순서면 같은
비트**, (3) float64 → float32 는 양쪽 다 round-to-nearest-even. 지킨 함정 둘:

| 함정 | 실측 | 처리 |
|---|---|---|
| torch CUDA 는 **CPU 스칼라로 나누면 `a·(1/b)`** 로 바꾼다 | 100 만 개 중 **133,303** 개 1 ulp 다름 (CUDA tensor 분모 0 개, 0-d CUDA tensor 0 개) | GPU 경로의 분모는 CUDA tensor (`torch.where(edge, h_t, 2h_t)`) |
| 곱·덧셈이 한 kernel 에서 FMA 로 합쳐지면 반올림이 한 번 줄어든다 | — | torch 원소별 연산은 연산마다 kernel (`(wx*wy)*wz`, `w*v`, `out += ·` 를 따로); host 경로는 numpy |
| float32 배열 대 Python float 비교 (부호 교정 임계) | numpy 1.26 · 2.x 모두 스칼라를 float32 로 바꿔 비교 (`[f32(0.1)] > 0.1` → False) | GPU 비교도 `np.float32(thr)` tensor 로 |

**어디서 산술하나 — 두 경로, 같은 정의.** 마이크로 (128³ · 5 mm, 호출당):

| 질의점 N | 10 | 100 | 1000 | 5000 | 9000 |
|---|---|---|---|---|---|
| distance — GPU float64 산술 (ms) | 0.23 | 0.31 | 0.38 | 0.72 | 1.03 |
| distance — GPU `index_select` + host numpy 산술 | **0.08** | **0.12** | **0.32** | 1.49 | 2.24 |

GPU 산술은 kernel 25–60 개라 고정비가 크다. 이 서버의 호출은 대부분 100–1000 점 (`_esdf_clearance` 청크당 9 회 · 976 점/회,
gradient 3 회 · 152 점/회) 이므로 **1024 점 미만은 host 산술 경로** (`EsdfField` 와 같은 numpy 코드에 GPU 가 질의 칸 값만 넘김),
이상은 GPU 산술 경로다 (`config.ESDF_QUERY_HOST_ARITH_MAX_POINTS`). 두 경로 모두 격자 전체를 host 로 내리지 않는다.
