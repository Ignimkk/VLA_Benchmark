## 무엇을 했나

`pointcloud.max_points` 의 기본값을 **60000 → 200000** 으로 올렸다. 사용자 판정(2026-09-25)이다 —
*"지금은 실시간성을 고려하지 마라. 정상 작동이 먼저고, 실시간성을 잡아먹는 부분은 뒤에 가서 고친다."*

그 값에서 세 카메라 RB-Y1 프레임이 상한에 걸려 voxel 이 5.0 → 6.3 mm 로 커지고, 프레임이
`DEGRADED` 로 보고되며, `ConstraintValidity.certified` 가 그것을 "인증 안 됨" 으로 읽어
SQP 가 **모든 제약을 mm 단위로 여유 있게 통과한 궤적까지 `VIOLATED`** 로 내렸다 (X3 측정 3).

## verifier 가 알아야 할 것

- **기본값 변경**: `pointcloud.max_points` 60000 → 200000. 명시 override 는 그대로 존중된다.
- 재생산이 필요한 산출물: **없다.** 기록도 attention npz 도 안 건드린다.
- 옛 기록과 호환이 깨지는가: **안 깨진다.** 회귀 기준선 `run_16d_ep1800` 은 **상한에 애초에
  안 걸린다** (프레임별 점 수 53625~91268, `capped=False` 15/15, `validity=valid` 15/15).
  60000 과 200000 에서 같은 수치가 나온다.

## 측정 중에 밟은 함정 — **부하가 기준선을 바꾼다**

기준선을 pytest 전체 · 다른 rollout 과 **동시에** 돌렸더니 `feasible 9 / violated 6` 이 나왔다.
같은 코드 · 같은 기록 · 같은 명령인데 단독으로 다시 돌리니 `feasible 13 / violated 2` 다.

원인은 `sqp.time_budget_ms` 가 **벽시계 마감**이라는 것이다. 부하가 걸리면 같은 50 ms 안에
반복을 덜 돌고 더 나쁜 iterate 를 돌려준다. 뒤집힌 프레임 5·9·10 은 반복이 **2 → 1** 로 줄었고
clearance 가 +4.35 → −6.77 mm 까지 갔다.

**회귀 기준선은 단독으로 돌린다.** 이 함정을 `regression-baseline` skill 에 적었다.
