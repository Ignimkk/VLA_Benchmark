# T24 — TO 를 고정 입력으로 항별 분리 검증하고, 후보 선택을 바로잡는다

> writer: lead (A0) · 2026-09-28 · 읽는 쪽: implementer, verifier
> 근거: [지침](AG3S_GRASP_FAILURE_IMPLEMENTATION_GUIDE.md) §7 · §10-6 · §11, [계획](AG3S_GRASP_FIX_PLAN.md)

## 왜 지금 이것인가

T16 은 TO 가 청크를 안 바꿔도 실패함을 보였다. 그러나 T17 shadow 의 **미실행** TO 출력은 접근 구간에서 관절 최대 8.6°,
손끝 변위 중앙값 19.5 mm (T17a) 였다 — 충돌 ON 의 TO 가 무해하다는 뜻이 아니다. closed loop 에서는 관측과 정책 출력이
매번 달라지므로 항별 영향을 가를 수 없다. **같은 입력을 고정하고** 항을 하나씩 넣어 본다 (지침 §7.2).

그리고 코드 점검 하나: `sqp.solve` 는 초기 iterate 의 merit 를 계산해 놓고도 `best_merit = np.inf` 로 시작한다. 첫 후보가
초기 iterate 보다 나빠 반복점으로 수락되지 않아도 **반환용 best 로 저장**될 수 있고, 예산으로 끝나면 그것이 나간다 (지침 §7.3).
T14 30/30 · T17 75/75 chunk 가 예산 도달로 끝났으므로 이 경로는 매 chunk 열려 있다.

## 구현에 요청하는 것 (→ implementer)

### 1. 고정 입력 재실행 도구 (`benchmark/trajopt/experiments/fixed_input_ablation.py` 신설)

서버 constraint record 한 chunk (`outputs/live_test/<run>/server_constraints/run_0000/chunk_k.npz`) 에서 **입력을 그대로**
복원한다: `reference_chunk` · `sphere_centres/radii` 가 아니라 **robot model** (그 실행의 sphere option — `summary_json`/시작 로그의
`capsule_radius_scale` 등을 인자로 받는다) · `q_now` (로컬 기록 `frames.jsonl` 의 같은 seq 의 qpos, chunk k ↔ seq k+1 — T14.audit §1)
· ESDF 계층 (`esdf_distance` · `esdf_coarse_*` · `esdf_free_*` → `layer_from_arrays` 로 `CuroboEsdfField` 재구성) · `manipulated_link_margin`
/ `target_field_exclude` 가 있으면 그대로. **재구성한 필드가 기록의 `clearance (8,122)` 를 재현하는지 먼저 확인**하고 (허용 오차 보고),
재현되지 않으면 그 사실을 크게 적고 멈춘다.

그 위에서 지침 §7.2 표를 돈다:

| 변형 | |
|---|---|
| 충돌 OFF · 평활 OFF · 연속성 OFF · 추적 ON | reference 가 그대로 돌아오는가 (한계 초과량 함께) |
| + 평활만 | |
| + 연속성만 (이전 청크 = 기록의 직전 refined) | |
| 충돌 ON (기록의 접촉 정책 그대로) | 어느 행(link / 계층 / clearance / 라벨)이 수정을 만드나 |
| 같은 조건 + `time_budget_ms`·`max_iterations` ×2, ×4 | feasibility · cost · 손끝 경로 변화 |

출력: chunk 별·변형별로 **실행 창 8 step** 의 관절 최대 편차, 손끝(왼손 finger sphere 평균) 위치·방향 변위 (FK), 활성 행 목록,
reference 의 한계 초과량, SQP/QP 반복·예산 도달·후보 수락/거절·최종 위반 — **JSON 으로** (verifier 가 figure 를 만든다).
"전체 원소 중앙값 하나" 로 축약하지 않는다 (지침 §11).

### 2. 후보 선택 (`sqp.py`)

- `best`/`best_merit` 를 **초기 iterate 와 그 merit 로 초기화**한다. 첫 후보가 더 나쁘면 초기 궤적이 반환된다.
- 반환된 것이 무엇인지 `metrics` 에 싣는다: `returned = "initial" | "accepted" | "best_unaccepted"`, 그리고 각 후보의
  `(merit, violation, accepted)` 목록. **단순히 한 줄만 바꾸고 모든 후보의 적격성이 같다고 가정하지 않는다** — 반환 후보를 최종 기하와
  실제 한계로 다시 검증하는 것은 `_finish` 가 이미 하므로, 그 결과가 후보 목록과 함께 나가면 된다.
- 기존 테스트가 이 변경에 걸리면 **왜** 걸리는지 impl.md 에 적고 고친다 (T9 처럼 반대 방향으로 다시 적는다).

### 3. 이름 정정 (`problem.py` · `config.py` · `README.md` 의 해당 줄)

- `w_smooth` 는 **위치 2차 차분(가속도)** 이지 jerk 가 아니다 (지침 §7.1). config 키는 **바꾸지 않는다** (flag 호환) —
  docstring · 주석 · README 의 "jerk" 를 정정하고, `CostConfig.w_smooth` 의 설명에 "2nd difference = acceleration in step units;
  jerk would be the 3rd" 를 적는다.

### 4. 손대지 않을 것

- `linearize.py` · `refiner.py` · `safe_policy.py` · `client.py` · `wire.py` (T18 이 열려 있다). `ag3s/**` (T19).
- 최적화 **동작**의 다른 변경 (가중치 기본값·trust region 등) — 이 STEP 은 재고 바로잡는 것이지 튜닝이 아니다.
- 커밋하지 마라. 포트 8123 서버는 건드리지 마라.
