# T40 — 통합 main 의 closed-loop 시연: (1) 장애물 없음 · (2) 운반 경로 위 장애물 회피

> writer: lead (A0) · 2026-10-03 · 사용자 지시: "headless 로 장애물 없는 상황 테스트 · 녹화" + "사과를 바구니로 가져가는 경로에 임의의
> 장애물을 설치해 회피하며 성공하는지. 잘 안 되면 잘 되도록 장애물을 설치하는 것도 중요". O5 는 뒤로 미룸 (사용자).

## 사실 (lead 확인)

| 항목 | 내용 |
|---|---|
| 장애물 기능 | client `--obstacle-profile` · `--obstacle-config <json>` (`pi05_infer.py:827-833, 935-957, 1150-1154`), 16D randomized 모델 허용, fruit scene. 장면 `model_transport_pick_place_obstacles.xml` + `scenes/pick_place_obstacles.xml` |
| 장애물 형상 (mocap, 위치는 config 로) | `bollard_0/1`: 충돌 원기둥 r 27 mm · 높이 ≈ 287 mm (+ 받침 r 45 mm · 20 mm). `divider_0`: 충돌 상자 208 × 36 × 80 mm (+ 발 2 개) |
| 기존 profile | `fruit_*` 는 **pickup 통로 옆 고정 위치** — episode 마다 다른 사과 → crate 경로 위에 있다는 보장 없음 → **episode 별 config JSON 을 만든다** (코드 수정 불필요) |
| 정지 규칙 | `--obstacle-stop-distance 0.02` — 로봇이 장애물에 2 cm 안이면 멈춤 (`pick_place_obstacles.py:228-279`, `min_robot_clearance_m` 기록). 쥔 사과 ↔ 장애물 거리는 이 값에 없을 수 있음 → frames 로 따로 |
| 주의 1 | VLA 는 장애물 있는 데이터로 학습되지 않았다 — 비키는 것은 TO (계획 지평 8 step) 뿐이고 정책은 매 청크 직선 경로로 다시 당긴다 |
| 주의 2 | E3b 의 충돌 검사는 **gripper links 만** (`--links gripper`) + 쥔 사과 구. 높은 bollard 는 팔뚝이 칠 수 있으나 검사 밖 |
| 주의 3 | bollard 지름 54 mm < gripper 최대 개도 71.46 mm → admissibility 상 "잡을 수 있는 물체" 후보. attention 이 낮으면 장애물로 남지만 확인 필요 |

## 단계

| 단계 | 내용 | GPU |
|---|---|---|
| **A 배치 설계 (verifier)** | T39 의 **둘 다 성공한 쌍 22 개** 중 crate 위치가 서로 다른 6 episode (seed 는 T39 그대로). 각 run 의 기록 (frames · traj) 에서 **쥔 사과의 운반 경로** (grasp_t → place_t) 와 높이 (테이블 위 mm) 를 뽑는다. 후보 배치: (i) divider 를 경로 중간점에 경로와 직각으로 — 사과 운반 높이가 divider 윗면 + 사과 반지름보다 낮은 구간이어야 실제로 막는다, (ii) bollard 를 경로 위 (사과 · gripper 가 지나는 점) 에. 각 후보에 대해 **기록된 T39 궤적을 재생**해 장애물과의 최소 거리 (gripper 구 · 쥔 사과 · 팔 전체) 를 잰다 → 직선 경로가 **실제로 부딪히는** 배치만 남긴다. 초기 물체 · crate · 로봇 초기 자세와 겹치지 않을 것. 실제 씬 그림 (3rd person, 장애물 + 기록 경로) | 없음 (osmesa 렌더만) |
| **B 시연 1 — 장애물 없음** | 같은 6 episode · seed 로 통합 main (snapshot) 의 E3b (+ 비교용 E0) 실행 · 녹화 | 서버 2 개 ≈ 28 GB |
| **C 시연 2 — 장애물** | A 의 배치로 E0 · E3b 실행 · 녹화. 지표: 성공, 장애물 접촉 (로봇 · 쥔 사과), `min_robot_clearance_m`, HOLD 수 · 종류, obstacle stop, 청크 시간 | 같음 |
| **D 안 되면** | 실패를 분류 (HOLD 연속 · TO 가 8 step 안에서 못 비킴 · 정책이 다시 끌어당김 · 장애물을 target 으로 착각 · 팔뚝 충돌) → 원인에 맞춰 배치를 조정 (경로 옆으로 일부 걸치게 · 낮게 · divider 우선) 하거나 설정 (`--links` 범위) 을 사용자 판정으로 | |

코드 고정: 다른 세션이 main 을 계속 고치므로 B · C 는 **불변 snapshot** (T39 와 같은 방식, 새 경로) 에서 · XLA autotune 0 · `--policy-seed` · `--warmup-steps 1000`.
GPU: 시작마다 `used + EST ≤ 130 GB` (다른 세션 SUBTASK-e 가 사용 중). 8123 금지, 포트 8240–8249.
