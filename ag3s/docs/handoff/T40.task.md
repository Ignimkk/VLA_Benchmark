## A 결과 → 사용자 판정 (2026-10-03)

A (`T40A.verify.json`, `figures/t40/t40a-*`): 사과 → crate 운반 경로는 대부분 crate 위, crate 밖 구간은 ≈ 10 cm. divider (80 mm) 는 막지 못함 (사과 바닥이
테이블 위 180–240 mm 로 운반). bollard 는 사과에서 37–38 mm 라 접근 · 파지부터 간섭 → 운반 회피 시험이 아님. 막힘 1: 16D 모델 + 장애물이면 client 가 block 장면
XML 을 읽어 `apple_free missing` (`pi05_infer.py:1024`). 막힘 2: MuJoCo 3.11 `mj_geomDistance` 가 box 쌍에서 틀림 (최대 284 mm) — reset 검사 · obstacle stop 이 이 함수를 씀.

**사용자 판정:** "장애물을 추가하고 제거할 수 있도록. 지금 기둥은 무의미. subtask gate 는 끄고 진행."

## E 구현 (→ implementer, pi05_TO_hybrid)

1. **막힘 1 수정:** `--model rby1_randomized_pick_place_16d` (및 `rby1_transport_14d`) + 장애물 profile 이면 `model_transport_pick_place_obstacles.xml`.
2. **허들 slot `hurdle_0` 추가** (`scenes/pick_place_obstacles.xml`, `pick_place_obstacles.py` SLOTS): 가로 막대 (capsule, 반지름 ≈ 12 mm) + 양 끝 기둥 2 개
   (cylinder/capsule, 반지름 ≈ 12 mm, 받침 포함) — **box 를 쓰지 않는다** (막힘 2). 막대 길이 ≈ 0.26 m, 막대 중심 높이는 config 로 정할 수 있게
   (mocap 위치 z 로 전체를 올리지 않는다 — 기둥이 떠 버림. 기둥 길이와 막대 높이 조합을 몇 개 slot 으로 두거나, 막대 높이를 config 필드로 받아 기둥 geom 의
   size 를 런타임에 바꾸는 방식 중 단순한 것). 시각 geom (group 2) + 충돌 geom (prop_collision) 은 기존 slot 과 같은 관례. **쥔 사과 · 로봇과 물리적으로 충돌**해야 한다 (contype/conaffinity 확인).
3. **추가 · 제거:** 장애물 없음 = `--obstacle-profile clear` (기본, 기존 장면 그대로 — 비트 동일). 추가 = `--obstacle-config <json> --obstacle-profile <name>`.
   run 별 json 으로 위치 · yaw · (막대 높이) 를 준다. 사용법을 `pick_place_obstacles.json` 머리말 또는 docstring 에.
4. obstacle stop · reset 검사가 허들 (capsule/cylinder) 에서 정확한지 단위 테스트 (독립 거리 계산과 비교).
5. 테스트: clear 가 이전과 같은 장면 (qpos 주소 · 초기 상태 비트 동일), 허들 config 로드 · 배치 · 충돌, 16D + 장애물 장면 로드.
