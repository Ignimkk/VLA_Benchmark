# T22 — attach 는 파지가 확인된 뒤에, 접촉 허용은 그 전에

> writer: lead (A0) · 2026-09-28 · 읽는 쪽: implementer, verifier
> 근거: [지침](AG3S_GRASP_FAILURE_IMPLEMENTATION_GUIDE.md) §6 · §10-4, [T14.audit](T14.audit.md) §4.4, [T18.impl](T18.impl.md) (실행 피드백 `ag3s/exec_feedback`), [T20.impl](T20.impl.md) (manipulated identity), [계획](AG3S_GRASP_FIX_PLAN.md)

## 왜 지금 이것인가

`_run_latch()` 는 **계획 청크의 gripper 값**이 문턱 아래면 `attach()` 를 불렀다 — 실제로 닫혔는지, 손이 대상 근처인지 보지 않았다.
T14 seq 26: 손에서 636 mm 떨어진 cluster 29 점을 `ee_finger_l1` 에 붙였고 그 phantom 이 −3.1 mm 위반 → HOLD (파지 순간). T16: 닫힘이
HOLD 로 취소됐는데도 attach 됐다 (n_attached 51, t=184). 지침 §6.1: attach 는 "물체가 손에 붙어 함께 움직인다" 는 충돌 모델의 선언이지
파지 시도의 표시가 아니다.

T18 이 실행 사실(적용·측정 gripper, HOLD 여부)을, T20 이 조작 대상의 영속 ID·기하를 준다. 이 둘 위에서 attach 의 근거를 바꾼다.

```
실행 피드백 + 관측 ─► [파지 상태 갱신] ─► world / target-free / attached 기하 ─► TO ─► 검증 ─► 실행
                       ^^^^^^^^ 여기
```

## 구현에 요청하는 것 (→ implementer)

### 1. 상태와 증거 (`trajopt/grasp_latch.py` · `trajopt/safe_policy.py:_run_latch`)

지침 §6.2 의 네 상태를 latch 에 둔다 (이름은 제안): **대상 확정** (T20 의 manipulated id 가 있고 latch 가 잠김) → **닫힘 시도**
(피드백의 `applied_gripper` 가 닫힘 방향으로 실제 적용됨 — 계획값이 아니다) → **파지 확인** → **놓임 확인**.

**파지 확인의 근거** (배포에서 쓸 추정치 — 시뮬레이터 참값이 아니다):
- 측정 개도(`measured_gripper`)가 닫힘 명령 뒤 **줄어들다 완전 닫힘보다 위에서 멈춤** (빈손이면 끝까지 닫힌다 — T17 실측: 열림 −0.045 → 물체 잡고 −0.032 에서 정지; T16 빈손 hold 시 −0.037~−0.050),
- 그 순간 **manipulated 기하가 손가락 link 의 reach 안** (parent link 원점 ↔ manipulated centroid 거리 ≤ `reach` config, 기본값은 재서 정한다 — T17 파지 순간의 값을 verifier 가 준다; 636 mm 는 어떤 값으로도 거절돼야 한다),
- 닫힘이 HOLD 로 취소된 청크(`n_exec == 0` 또는 applied 가 열림 유지)는 **증거가 아니다**.

셋이 맞을 때만 `attach()`. 놓임은 개도가 다시 열리거나 `placed_fn` 이 참일 때 (지금 규칙 유지). 각 전이의 **근거와 시각**을 `LatchEvent.note`
와 constraint record 에 남긴다 (`grasp: {state, evidence:{opening_before, opening_after, reach_mm, feedback_seq}, ...}`).

### 2. 순서와 재생성 (`safe_policy.py:_scene_fn`)

지침 §6.3: 피드백 → 파지 상태 갱신 → 기하 생성 → TO. 지금은 `process_multi_debug` **뒤에** `_run_latch` 가 돌아 attach 가 다음 프레임에야
반영된다. 둘 중 하나를 골라 impl.md 에 이유를 적어라: (a) latch 를 `process_multi_debug` **앞**으로 옮긴다 (label 은 T20 의
`ag3s.manipulated` 에서 온다 — 이 프레임의 grounding 이 필요 없다), (b) 순서를 두되 attach/detach 가 일어난 프레임은 제약을 **재생성**한다.
어느 쪽이든 record 에 `state_version / constraint_version` 을 실어 어긋남을 검출할 수 있게 한다.

### 3. attach 의 reach 검사 (`ag3s/runtime/pipeline.py:attach`)

`attach()` 자체도 parent link 와 대상 centroid 의 거리를 검사해 `reach` 를 넘으면 **거절**하고 이유를 낸다 (latch 가 틀려도 마지막 관문이 막는다).
부착 좌표계는 지침 §6.3 마지막 문단대로 — 손가락 link 를 쓰면 개도에 따른 상대 이동을 모델링해야 한다. 지금 구현이 어떻게 하는지 확인해
impl.md 에 적고, 바꾸는 것은 reach 검사와 증거 기록에 한정한다.

### 4. 손대지 않을 것

- `client.py` 의 게이트(`should_execute`·`_hold`)·`pi05_infer.py` 제어 루프 (T23). `fields/**`·`_build_esdf`·`_target_ball` (T21).
  `stages/target_grounding.py`·`robot_filter.py` (T19·T20, 검증 중 — 값·의미를 바꾸지 마라). `sqp.py`·`problem.py` (T24 검증 중).
- 기본 latch 문턱(0.85 · 3 프레임)은 유지. 새 config 는 기본값이 "지금 동작" 이어야 하되, **계획값으로 attach 하는 경로는 기본에서 꺼진다**
  — 그것이 이 STEP 의 요지다. 피드백이 없는 옛 클라이언트는 attach 하지 않고 note 에 이유를 남긴다.
