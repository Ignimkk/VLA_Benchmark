## 무엇을 했나 (평이한 요약 먼저)

1. **G1 — TO 의 joint position 범위를 제어 대상 로봇에서 읽는다.** 기본 출처가 URDF 에서 **서버가 로드한 MJCF**(`--model-xml`)로 바뀌었다.
   MuJoCo 가 컴파일한 `jnt_range` 를 읽고, 그 관절의 position actuator `ctrlrange` 와 대조한다 (RB-Y1 은 14 관절 전부 일치).
   실기용으로 `limits.source: model_xml | urdf | config` 를 두었다. 서버 시작 로그에 관절별 URDF 대 사용값 표가 찍히고, 다르면 WARNING 으로 크게 찍힌다.
   속도·가속도 한계는 **MJCF 에 없어서** URDF 값을 그대로 쓴다.
2. **G2-i — 예산을 반복 수 우선으로 바꿨다.** `sqp.min_iterations`(기본 3)만큼은 벽시계 예산과 무관하게 돈다.
   E3 의 linearize ~100 ms 는 **청크마다 새 거리장에 대한 첫 호출**의 비용이었다. 2·3 번째 호출은 ~3 ms 라서 3 반복 전체가 ≈ 20 ms 더 든다.
3. **G2-ii — limit 만 어긴 초기 iterate 의 대비를 바꿨다.** 받아들여진 후보가 없으면 거절된 QP 후보 대신 **reference 의 최소 투영**(position box ∩ 첫 스텝 anchor 로 원소별 clip)을 반환한다.
   투영이 limit 을 전부 지키고 충돌 검사를 통과할 때만이다. `metrics.returned = "projection"` 으로 기록된다. T24 규칙(적격한 초기 iterate 가 기준)은 그대로다.

E3b chunk 310 (ep1808 r1) 을 T24 도구로 복원하면 이렇다. MJCF 한계에서는 reference 의 overshoot 가 0 이고, 초기 iterate 가 그대로 나간다 (refined ≡ reference, 비트 단위).
URDF 한계로 되돌려도 G2-ii 가 손목(`left_arm_6`) 하나만 8.72° 투영한다. 기록된 실행은 거절된 후보였고, 손목 8.66° 에 다른 관절도 최대 0.94° 움직였다.

## G2 — 예산 기본값과 근거

| 키 | 기본 | T31 전 |
|---|---|---|
| `sqp.min_iterations` (새 키) | **3** | (없음 = 1) |
| `sqp.max_iterations` | 3 | 3 |
| `sqp.time_budget_ms` | 50 | 50 — 이제 `min_iterations` 뒤에만 걸린다 |
| `sqp.limit_projection_fallback` (새 키) | **True** | (없음 = False) |

`max_iterations < min_iterations` 면 `max_iterations` 가 이긴다. 그래서 T24 도구의 `replay`(반복 수 = 기록)는 그대로 재현된다.

**근거 1 — T30 E3 서버 기록 1125 청크** (E3a 675 · E3b 450, 각 run 첫 청크 제외, scratch `timing.py`):

| 단계 | E3a 중앙값 / p90 | E3b 중앙값 / p90 |
|---|---|---|
| linearize | 100.2 / 182.6 ms | 92.5 / 115.1 ms |
| assemble · QP · check | 2.9 · 2.1 · 4.6 ms | 2.9 · 2.2 · 4.7 ms |
| solve 전체 | 123.6 / 209.4 ms | 116.0 / 139.2 ms |
| SQP 반복 수 | 1 반복 674 · 2 반복 1 | 1 반복 450 |
| 반환 | initial 146 · accepted 481 · best_unaccepted 48 | initial 126 · accepted 275 · best_unaccepted 49 |

**근거 2 — 그 ~100 ms 는 첫 linearize 에서만 든다.** E3b chunk 302–311 을 T24 도구로 복원해 3 반복으로 풀었다. linearize 호출마다 잰 시간이다 (이 머신):

| chunk | 1 번째 | 2 번째 | 3 번째 |
|---|---|---|---|
| 302–311 (10 개) | 121.1–144.5 ms | 2.7–3.2 ms | 2.7–3.0 ms |

**근거 3 — 반복 수별 결과.** E3b 1800 r1 · 1808 r1 의 pre-grasp 150 청크를 같은 도구로 풀었다. 청크마다 새 solver, 시계 끔, MJCF 한계, 기록 목적함수 (w_smooth 0.05 · w_cont 0.5 vs 기록의 직전 refined) 조건이다:

| 반복 | 반환 (initial / accepted) | 반환 merit ÷ 초기 merit 중앙값 | 충돌 위반 청크 | 실행 창 관절 편차 중앙값 / p90 / 최대 (°) |
|---|---|---|---|---|
| 1 | 76 / 74 | 1.000 | 0 | 0.00 / 2.86 / 7.16 |
| 2 | 60 / 90 | 0.841 | 0 | 0.95 / 2.85 / 7.05 |
| 3 | 44 / 106 | 0.742 | 0 | 1.10 / 2.85 / 7.09 |

→ 기본을 3 (= `max_iterations`)으로 두었다. 이유는 셋이다. 설계대로의 SQP 가 ≈ 20 ms 로 되돌아온다. 반복 수가 머신 부하와 무관하게 정해진다 (시뮬레이션 재현성). 시뮬레이션 루프는 동기식이라 이 시간이 제어 주기를 깨지 않는다.
**주의 (lead 판단 필요):** 반복이 늘면 받아들여지는 후보가 늘고 (74 → 106), 실행 창 편차의 **중앙값**이 0.00° → 1.10° 로 오른다 (p90·최대는 그대로다).
이것은 limit 이 아니라 평활·연속성 항이 움직이는 몫이다. 파지에 영향이 있는지는 폐루프로만 알 수 있다. 되돌리려면 `--sqp-min-iterations 1` 한 줄이다.
실기처럼 비동기로 도는 곳도 1 로 둔다.

### G2-ii 반환 규칙 (`sqp.solve` 루프 뒤, `sqp.py:297-313` · `_limit_projection` `sqp.py:391-439`)

| 조건 (순서대로) | 아니면 `projection.reason` |
|---|---|
| `limit_projection_fallback` 켜짐 | `disabled` (T24 규칙 → `best_unaccepted`) |
| 초기 iterate 부적격 **이고** 받아들여진 후보 0 (이 둘이 아니면 `projection = None`) | — |
| 초기 iterate 의 충돌 위반 ≤ `safety.violation_tolerance` (0.1 mm) = limit **만** 어김 | `initial_collision_violation` |
| 투영이 존재 (box ∩ anchor 가 비지 않음) | `no_projection` |
| 투영이 position·velocity·acceleration·anchor 를 전부 지킴 (`_limit_overshoot`) | `projection_outside_limits` |
| 투영이 전 해상도 충돌 검사 통과 (`full_violation` ≤ 0.1 mm) | `projection_collides` |
| 전부 통과 → 반환, `returned = "projection"`, `returned_index = -2`, notes 에 한 줄 | `limit_only` |

- 투영 = `limits.project_to_limits` (`limits.py:415`). 원소별 box 두 개(position box · 첫 스텝 anchor `|Q0 − q_now| ≤ max_step`)의 교집합으로 clip 한다. **box 안의 원소는 한 비트도 바뀌지 않는다.** anchor 를 넣은 이유는 QP 가 anchor 를 hard 로 지키고, 적격성(`_limit_overshoot`)도 anchor 를 재기 때문이다.
- 충돌이 꺼진 판(`collision.enabled=False`)에서는 충돌 조건 둘을 보지 않는다. T15 규율 그대로다: merit 도 충돌을 보지 않는다. 반환된 궤적의 위반은 `_finish` 가 참값으로 잰다.
- 투영의 FK 는 한 번만 한다 (`_finish` 가 그 상태를 재사용). 추가 비용은 fallback 경로에서 clearance sweep 1 회뿐이다.

## verifier 가 알아야 할 것

- **기본값 변경 셋 — 인자 없이 뜬 모든 `serve_safe` / `esdf_rollout` / `TrajOptConfig()` 가 바뀐다.**
  1. joint position 범위: URDF → **MJCF** (`--model-xml`; `esdf_rollout` 은 기록의 `meta.model_xml`; `TrajOptConfig()` 는 작업공간 `model_transport.xml`). 예전 재현은 `--limits-source urdf`.
  2. SQP: 첫 반복 뒤 예산 → **3 반복 뒤 예산** (= 사실상 항상 3 반복). 예전 재현은 `--sqp-min-iterations 1`.
  3. limit-only 부적격 + 받아들여진 후보 없음 → `best_unaccepted` 대신 **`projection`**. 예전 재현은 `--no-limit-projection`.
- **새 기록 키:** `summary.to.metrics.min_iterations` · `.projection` (`{tried, used, reason, max_change_rad, violation_m, limit_overshoot}` 또는 `None`) · `returned` 의 새 값 `"projection"` · `returned_index = -2`.
  서버 기록 meta 의 `joint_limits` · `sqp`, `esdf_rollout` JSON 의 `trajopt.joint_limits` · `trajopt.sqp` 도 새로 생겼다. **이 키가 없는 기록 = T31 전 (URDF · 1 반복 우선 · 투영 없음).**
  AG3S constraint record (`summary_json.to.metrics`) 에서 `projection` 은 `candidates` 와 같이 `str()` 로 들어간다 (`constraint_record._scalar`) — `ast.literal_eval` 로 읽는다. `--no-perception` 기록(`chunks.jsonl` 의 `sqp`)은 `to_only_policy` 가 고른 키만 싣으므로 `projection` 이 없고 `returned` 만 있다.
