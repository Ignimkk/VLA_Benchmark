# T39 — O1 큰 N 평가: E0 (VLA 단독) vs E3b (AG3S + ESDF + TO, gate · HOLD) 짝지은 비교

> writer: lead (A0) · 2026-10-02 · 사용자 순서 (3) · **상태: 사용자 승인 (2026-10-02) — S1 착수**
> 근거 조사: Explore 보고 (2026-10-02, 아래 "사실" 절에 file:line 그대로).

## 왜

지금까지 E0 / E3b 비교는 episode 3 개 (1807 · 1800 · 1808) × 2 회 = 6 run 뿐이고 (T34 E3b 3/6, T37 E3b 3/6, E0_rec 3/6),
**같은 서버를 새로 띄우면 정책 난수 순서가 같아** 조건이 달라도 파지 전까지 같은 궤적이 나왔다 (T30 · T37 에서 소수점 9 자리 일치).
즉 6 run 은 독립 표본이 아니다. O1 은 표본을 늘리고, 조건 간에는 **같은 noise 로 짝지어** 차이가 AG3S+TO 에서 온 것인지 가린다.

## 계획

### S1 — seed 입구 (→ implementer)

결과를 바꾸지 않는 추가 기능 (필드가 없으면 지금과 비트 동일).

- **서버** (`benchmark/trajopt/serve_safe.py`, safe · `--no-safe` 둘 다): 요청에 `policy_seed` (int) 가 있으면 그 요청 직전에
  정책 RNG 를 `jax.random.key(policy_seed)` 로 다시 놓는다. safe 경로는 `wire.py` `pack_request` 에 필드 추가. 기록 (manifest ·
  record) 에 seed 를 남긴다.
- **client** (`pi05_TO_hybrid/rby1_bringup/pi05_infer.py`): `--policy-seed INT` → 첫 요청 (t_step 0) 에만 실어 보낸다. 두 모드 모두.
  manifest `"policy_seed"`.
- **warmup 결정화**: `--start-delay` 를 wall-clock 이 아니라 **고정 step 수** (`round(start_delay / dt)`) 로 — 같은 (episode, seed) 는
  같은 t=0 상태. (wall-clock 동작이 필요한 실기 경로가 있으면 flag 로 분리.)
- 코드 위치: benchmark 는 worktree 브랜치 `o4-gpu-parallel` 위 새 커밋 (O1 은 빠른 코드로 돌리고, 결과는 main 과 비트 동일).
  pi05_TO_hybrid 는 추가 flag 뿐이라 main 에 (로컬 PC 는 사용자가 git pull — O10).
- 수락 조건 (verifier): 같은 조건 · 같은 (episode, seed) 2 회 → frames 비트 동일; seed 다르면 달라짐; seed 미지정이면 예전과 동일
  (기준선 둘 · B4 재생 불변).
