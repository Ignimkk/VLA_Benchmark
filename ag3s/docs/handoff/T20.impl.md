## 무엇을 했나 (평이한 요약 먼저)

붙들던 물체가 이번 프레임에 cluster 를 못 내면, 예전엔 그 프레임의 1 등(T14 에선 crate)을 target 으로 돌려줬다.
이제는 **같은 물체를 `occluded` 로, 마지막으로 관측한 기하 그대로** 돌려준다. 1 등이 target 을 가져가려면
`target_confirm_frames` 연속 1 등이어야 하고(예전과 같다), 그 프레임마다 점수가 `target_switch_min_score` 이상이어야
한다(새 조건, 기본 0.0 = 점수로 거르지 않음). `target_lost_frames` 를 넘게 안 보이면 `lost` 가 되어 target 이 없고,
사유는 `lost(id, age)` 와 `GroundingStatus.LOST` 로 `no_seed` 와 구별된다(기본 `None` = lost 없음).

이 "조작 대상"(id · 상태 · 마지막 기하)은 `TargetConfirm` 이 계산하고 `AG3S` 가 프레임마다 `self._manipulated` 로 들고
`reset()` 에서 지운다. 접촉 허용(`manipulated_link_margin`) · `target_field_exclude` · `_build_esdf` 의 fine 창 중심 ·
target-free 점 · `_target_ball` · `TARGET_LABEL` · T19 guard 중심이 **attention target 이 아니라 이것**을 읽는다.
파지 전 · 보이는 동안에는 둘이 같은 점군이다.

### 판정 요청 (lead)

1. **cluster 가 하나도 없는 프레임 (NO_SEED 등) 에서 occluded 인 경우** — `grounding.target` 은 **예전처럼 None**, status 도 그대로(NO_SEED → `no_target` HOLD) 두었다. 소비자(접촉 허용 · 제외 · fine 창 · guard) 는 manipulated(occluded, 마지막 기하) 를 계속 받는다. 반면 cluster 가 있는데 held 가 없는 프레임은 target = 마지막 기하, status OK 다. 둘을 같게 만들면 (NO_SEED 프레임도 target = 마지막 기하) T14 seq 22 의 HOLD 가 사라지지만, 그것은 인증 규칙 변경이라 T23 의 일로 남겼다.
2. **`target_lost_frames=None` (기본)** 은 "마지막 위치를 무기한" 쓴다 (지침 §4.3 이 경계하는 것). 기본을 지금 동작에 맞추라는 task 를 따랐지만, 도전자가 min_score 에 못 미치는 설정에서는 occluded 가 끝나지 않는다. 측정 뒤 유한값을 권한다.
3. **LOW_SCORE 프레임** (`target_score_threshold > 0`, 기본 아님) 은 held 가 cluster 목록에 있어도 "안 보임" 으로 센다 (`unseen`). 그 프레임은 이름을 거절한 프레임이므로 기하도 갱신하지 않는다.
4. `ManipulatedIdentity` 를 `types.py` 가 아니라 `target_grounding.py` 에 두었다 (`TargetConfirm` 이 만드는 값이라). 다른 모듈은 `pipeline.AG3S.manipulated` 로 읽는다.
