## 무엇을 했나 (평이한 요약 먼저)

**F1.** 권한 행이 target-free 층(사과를 뺀 층)에서 거리를 받으면, 이제 그 행에는 조작 대상 마진(phase 여유)을 붙이지 않는다.
그 층에는 사과가 없다. 그래서 "이 행의 최근접 장애물이 사과인가"(`|d − d_object| ≤ voxel`)가 참이 되는 경우는 테이블이 우연히 사과와
같은 거리에 있을 때뿐이다. 그때 APPROACH 여유 20 mm 가 테이블에 붙었다. 이제 그 행의 여유는 `esdf_margin`(+ 목적지 규칙)뿐이다.
권한 없는 행과 `relax` 는 값이 하나도 바뀌지 않는다. 판정 분류(`classify_violations`)는 최적화기와 **같은 값**
(`linearizer.esdf_clearance`)을 다시 읽으므로 코드를 고치지 않아도 같은 규칙을 따른다. target-free 층에서 난 위반은 지금도
`collision` · `answer_excludes_target` 이다. 다만 그 값이 이제 phase 여유 없이 잰 참 관통량이다.

**F1b** (coordinator 지시, F1 의 승인된 의도 안). target-free 행은 값뿐 아니라 **QP 방향도** target-free 층에서 받는다.
예전에는 값이 target-free 층에서 오는데 방향은 사과가 든 본 층의 `gradient` 였다. 그래서 사과 옆에서 테이블 행을 풀 때 손가락이
사과 법선 방향으로 밀렸다(E3a 증상). 이제 값과 방향은 언제나 같은 층에서 오고, 어느 층이 답했는지도 남긴다.

**F4.** 파지 확인의 `settled` 는 이제 "닫힘 명령이 3 스텝 이상 적용됐다"가 아니다. **연속 두 요청의 측정 개도 차가 ε = 0.02 미만**
이어야 한다(손가락이 멈췄다). 그래서 개도가 한 요청 만에 1.0 → 0.7 로 움직인 요청에서는 attach 하지 않고, 같은 개도를 한 번 더 본
요청에서 attach 한다. 빈손과 쥔 손의 구별(`blocked` · `not_empty`)은 T22 그대로다.

## F1 — 무엇을 바꿨고 무엇을 안 바꿨나

| 행 | 거리 `d` | 여유 (T30 전) | 여유 (T30 뒤) |
|---|---|---|---|
| 권한 · `target_free_mask` (= `exclude_authorized` 의 마스크) | `target_free_distance` | `\|d − d_obj\| ≤ voxel` 이면 `manipulated_link_margin` (APPROACH 20 mm) | **`esdf_margin`** (+ 목적지: 쥔 물체 점에만 붙으므로 사실상 무관) |
| 권한 없음 | `distance` | 일치하면 full TARGET margin (50 mm) | 그대로 |
| `exclude_all` 의 권한 없는 행 (마스크 안) | `target_free_distance` | 일치하면 full TARGET margin | **그대로** (면제 대상은 권한 행만) |
| `relax` (마스크 없음) | `distance` | 일치하면 per-link | 그대로 |
| 쥔 물체 점 (attached) | 둘 다 | `esdf_margin` (패딩) | 그대로 — 면제 패딩은 `False` |

- **면제 행 = target-free 층에 묻는 권한 행.** 정의는 `CollisionLinearizer._target_free_exempt_rows` 하나에 둔다.
  `SceneSnapshot.target_free_exempt` 가 `None`(기본)이면 `target_free_mask` 와 같다. `exclude_authorized` 에서는 AG3S 가 그 마스크를 권한 link
  집합으로 지으므로(`to_adapter.py:237-240`) 둘이 같다. `fixed_input_ablation.make_scene` 처럼 `SceneSnapshot` 을 직접 짓는 도구도
  이 기본값 덕분에 **고치지 않고** 새 규칙을 탄다(verifier 측정 #1).
- **`exclude_all`**: 마스크가 전신이라 권한 행을 따로 알아야 한다. linearizer 는 권한 집합을 모르므로 `scene_from_constraint_set` 이
  `manipulated_link_margin` 에서 읽는다. 권한 없는 구의 값은 `full_margin(TARGET)` 곧 배열의 최댓값이고, 권한 구는 phase 규칙 때문에 그보다 작다.
  둘이 같으면(TRANSIT, `margin_scale` 1.0) 가를 수 없으므로 아무것도 면제하지 않는다. 이 경우는 T30 전 규칙 그대로이고 테스트로 박았다.
- **마스크 행이라도 답이 target-free 층이 아닐 수 있다**(창 밖 → `coarse`/`outside`, 경계 → `window_edge`, `b ≤ d < f` → 사과가 든
  `fine`). task 문구대로 **마스크 행 전부**를 면제했다. 이렇게 해도 판정이 느슨해지지 않는 이유는 둘이다. 하나, 그 행들의 최근접이 실제로
  사과라면 그것은 권한 link ↔ 조작 대상이다. 둘, 분류기가 계층을 따로 본다. 미해결 계층은 `unverified`(HOLD)이고, `fine` 은 거리 일치 검사로
  `allowed`/`collision` 을 가른다. 기본 config(`esdf_margin` 0.05 > 권한 여유 0.02)에서는 그 행이 사과에 대해 **더 엄격**해진다(0.02 → 0.05).
- **AG3S 쪽 clearance.** AG3S 에는 행별 여유를 따로 계산하는 규칙이 없다. `to_adapter` 는 마진(`manipulated_link_margin`)과
  마스크(`target_field_exclude`)를 **넘길 뿐**이고 적용은 `_esdf_clearance` 한 곳이 한다. 규칙이 실린 계산은 셋이며 모두 `_esdf_clearance` 를
  부른다. `linearize`(QP 행), `full_violation`/`worst_row`(보고), `classify_violations`(판정)다. `constraints/**` 는 고치지 않았다.
  다만 규칙이 **없는** 배열이 하나 있다. 서버 기록 `chunk_*.npz` 의 `clearance`(`safe_policy.py:1038`, `bringup.py:132`)는
  `distance(main) − r − esdf_margin` 이다. target-free 층도 조작 대상 마진도 쓰지 않으므로 T30 전후 모두 TO 값과 다르다.
  lead 의 "E3a 초기 위반 34 중 28 은 AG3S(여유 0) 로는 깨끗"은 이 배열을 읽은 것이다. `_record` 는 내 소유 범위(판정 분류 · latch 호출부) 밖이고
  옛 기록과 비교할 수 있어야 하므로 **바꾸지 않았다**(아래 판정 요청 1).

## F1b — target-free 행의 방향도 target-free 층에서

`CuroboEsdfField.target_free_gradient(points, return_tier=False)` 를 새로 두었다. 이 메서드는 `target_free_distance` 와 **같은 합성**을
따라가며, 값을 낸 쪽의 기울기를 준다. 분기는 `answer_tier` 와 한 함수(`_answer`)를 공유하므로, 기울기의 tier 와 `answer_tier` 는
정의상 같다.

| 답 (`answer_tier`) | 값 | 기울기 |
|---|---|---|
| `target_free` | target 없는 층 `f` | 그 층의 기울기 |
| `static` (창 안) | 해석적 정적 기하 | 그 도형의 기울기 |
| `window_edge` | 창 경계 거리 `b` (하한) | `b` 의 기울기 — 가장 가까운 창 면의 안쪽 축 법선 (`_boundary_gradient`) |
| `fine` · `coarse` · `outside` (창 밖, 또는 창 안에서 `b ≤ d < f`) | 본 합성 `d` | 본 합성의 기울기 (`gradient`) |

- `linearize` 는 선택된 ESDF 행 가운데 `target_free_mask` 행(값이 target-free 합성에서 온 행)만 `target_free_gradient` 로 방향을 받는다.
  나머지 행은 예전처럼 `gradient` 로 받는다(`CollisionLinearizer._esdf_directions`).
- **어느 층이 답했나**는 `CollisionLinearizer.last_target_free_tiers` 에 남는다. 마지막 `linearize` 에서 선택된 마스크 행의 수를 tier 이름별로
  센 것이다. 매 `linearize` 마다 초기화한다. 서버 기록(`summary_json`)에 싣는 것은 `safe_policy._record` 의 일이라 하지 않았다.
  worst row 의 `tier` 와 `authorized_rows.by_tier`(T21)는 이미 같은 tier 를 기록한다.
- 마스크 행이 선택됐는데 필드에 `target_free_gradient` 가 없으면 **`ValueError`** 를 낸다. `target_free_distance` 가 없을 때와 같은
  규약이다. 조용히 본 층으로 돌아가면 F1b 전의 어긋남이 되살아나기 때문이다. `CuroboEsdfField` 는 언제나 이 메서드를 가진다.
  `relax` 에서는 마스크가 없으므로 한 줄도 달라지지 않는다.
- `answer_tier` 는 이제 `_answer` 를 부른다. 분기는 한 글자도 바꾸지 않았고, 기존 tier 테스트는 전부 통과한다.
  `target_free_distance`(hot path)는 건드리지 않았다.
- **보고 3 (마스크 행이라도 창 밖에서는 사과가 든 층이 답한다):** T21 뒤로 fine 창이 권한 link 의 swept AABB 를 반지름 + 마진 + 보간 여유만큼
  감싸므로 **그런 행은 드물다.** 그런 행에서는 F1b 가 값과 방향을 모두 본 합성에서 받는다. 면제(F1)는 task 문구대로 그 행에도 걸린다.

## F4 — ε 와 그 근거

`settled = |opening_k − opening_{k−1}| < settle_epsilon`. `opening` 은 요청 촬영 시점의 측정 개도(`exec_feedback.measured_gripper`, 1 = 열림)이고,
직전 요청의 측정값이 없으면 거짓(fail-closed)이다. **ε = 0.02** 로 정했다. 손가락 하나로 치면 청크당 0.9 mm (`RBY1_GRIPPER_OPEN` −0.045 m)이고,
fine 격자 5 mm 보다 한참 작다. 그래서 이 안에서 움직이는 손가락에 물체를 붙여도 모델 오차는 무시할 만하다.

요청 간 측정 개도 차 (왼손 `qpos[27]/−0.045`, 기록은 planning frame `qpos`; 수치는 내가 기록에서 읽은 것이고 판정 측정이 아니다):

| 기록 | 경우 | 연속 두 요청의 차 | ε = 0.02 에서 |
|---|---|---|---|
| T17 `shadow_ep1807` t=120 → 128 | **실제 파지**, 쥔 뒤 정착 (0.7153 → 0.7204) | **0.0051** | settled (여유 ×4) |
| T17 t=128 → 216 | 쥔 채 유지 | ≤ 0.0006 | settled |
| T17 · T16 · T28 E3a/E3b 12 에피소드 | 청크 안 모든 스텝이 스텝당 < 0.003 인 요청 793 개 | 중앙 0.0001 · p99 0.010 · 최대 0.0196 | 전부 settled |
| T17 t=112 → 120 | 파지 순간 (1.009 → 0.715) | 0.294 | **아님** — T22 는 여기서 attach |
| T22 verify #4e 빈손 sweep, 옛 규칙 attach 10 건 | 청크 경계에서 이동 중 (0.16–0.76) | 0.24–0.84 | 아님 |
| T28 E3b ep1808 r1 t=120 (옛 attach, 들림 없음) | 이동 중 0.997 → 0.364 | 0.633 | 아님 |
| 〃 t=128 | 명령 0.434 를 따라 다시 벌어짐 0.364 → 0.431 | 0.067 | 아님 |
| 〃 t=136 부터 | 명령 ≈ 0.43 추종 | 0.003–0.025 | 대부분 settled → **`blocked` 가 거절** (개도 − 명령 < 0.05) |
| T28 E3b ep1808 r2 t=128 (옛 attach) | 이동 중 0.991 → 0.775 | 0.216 | 아님 |

- **차 하나로 완전히 가를 수는 없다.** 청크 경계에서 아직 움직이는 요청(마지막 스텝 속도 > 0.005) 80 개 중 7 개는 차가 0.02 미만이다
  (최소 0.0014). 부분 명령 ≈ 0.4 를 스텝당 ≤ 0.02 로 느리게 따라가다 경계에서 방향이 바뀐 경우들이다. 이때는 개도 ≈ 명령이라
  T22 의 `blocked` 가 거절한다. 가르는 일은 여전히 `blocked`/`not_empty` 가 하고, `settled` 는 "측정이 멈춘 값인가"만 보장한다.
- **ε 를 더 작게 잡지 않은 이유.** 실제 파지 예는 T17 하나뿐이고, 그 정착 차가 0.0051 이다. ε = 0.01 이면 여유가 ×2 뿐이다.
  **더 크게 잡지 않은 이유.** 기록된 거짓 attach 의 차 가운데 가장 작은 값이 0.067(E3b 1808 r1 t=128)이다. 0.02 는 그보다 ×3 아래다.
- **대가.** attach 가 **최소 한 요청(8 스텝) 늦어진다.** T17 은 t=120 에서 t=128 로 옮겨진다. 그동안 사과는 manipulated 로 남고,
  권한 손가락은 target-free 층을 읽는다(F1 규칙).
- `settle_steps` 키는 **지웠다.** 누군가 `LatchConfig(settle_steps=…)` 로 부르면 `TypeError` 가 난다. 조용히 무시하지 않는다. 기록의
  `evidence.settled_steps`(닫힘 명령 스텝 누적)는 정보로 남긴다. 판정에는 쓰지 않는다.
