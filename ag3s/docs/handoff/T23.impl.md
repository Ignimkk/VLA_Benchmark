## 무엇을 했나 (평이한 요약 먼저)

**서버는 이제 `safe` 옆에 "왜" 를 구조화해 싣는다 (`verdict_reasons`).** 최적화기가 `violated` 라고 해도 위반 행을
**전부** 다시 분류해서, 권한 있는 손가락 link 가 조작 대상(T20 manipulated) 을 파고든 것뿐이면 `allowed_contact`(실행),
그 밖의 위반이 하나라도 있으면 `collision`(HOLD) 이다. 최악 행 하나만 보지 않으므로 손가락-사과 접촉이 팔꿈치-테이블
충돌을 가리지 못한다. `no_seed` 인데 manipulated 가 `occluded` 로 살아 있으면 `occluded_target`(실행), 예산 종료는
`budget_only`(실행). `safe = (HOLD 처리 사유가 없다)` 이고 옛 클라이언트는 `safe` 만 읽으므로 그대로 동작한다.

**로컬은 서버 `safe` 와 자기 사유 표가 둘 다 실행이라고 할 때만 실행한다.** HOLD 가 되면 팔 목표는 **HOLD 에 들어갈 때
한 번 잡은 `q_hold` = 직전 스텝에 명령한 `d.ctrl`** 이고 HOLD 가 이어져도 바뀌지 않는다. gripper 는 **마지막 명령**을
유지한다 (열지도 닫지도 않는다). 매 스텝 측정값을 목표로 주던 옛 동작은 `--safe-hold-mode legacy` 로 남겼다.
연속 HOLD 청크가 `--safe-max-hold-chunks` 를 넘으면 실행을 멈추고 사유를 찍는다 (기본 없음 = 무한).

`sqp.py` · `problem.py` · `linearize.py` · `grasp_latch.py` · `fields/**` · `pipeline.py` · `config.py` 는 건드리지 않았다.
최적화기의 `trajopt_status` 는 그대로다 — `violated` 인데 `safe=True` 인 청크(= `allowed_contact`) 가 생긴다.

## `verdict_reasons` — kind 와 처리

응답 키 `verdict_reasons: [{kind, action, detail, evidence}]` (정의: `trajopt/wire.py` 머리말 `verdict_reasons` 절).
`action` 은 서버가 `wire.GATE_DEFAULT` 로 붙인 읽기 편의값이고, 로컬 게이트는 자기 표로 다시 정한다.

| kind | 언제 (서버 `SafePolicy._reasons`) | 기본 처리 |
|---|---|---|
| `allowed_contact` | 위반 행 중 **권한 link ↔ manipulated** 로 분류된 행이 있다 (아래 규칙). evidence: 최악 허용 행 신원 · 행 수 · tier 별 수 · 판정 근거별 수 | 실행 |
| `budget_only` | `time_budget_hit` · `max_iterations_hit` · `feasible` 이고 `collision`/`unverified` 사유가 없다 | 실행 |
| `occluded_target` | `ag3s_status=no_target` ∧ validity certified ∧ manipulated `state=occluded` ∧ `cs.manipulated` 가 있다 (T20: 권한이 이번 제약에 실렸다) | 실행 |
| `uncertified_waived` | 미인증인데 `to_config.safety.require_certified_geometry=False` (기하 인증 스위치는 하나 — 기존 규칙) | 실행 |
| `collision` | 권한 없는 link · 쥔 물체의 점 · 평면 · target 이 아닌 후보 · 최근접이 manipulated 가 아님 · target 을 뺀 계층(`target_free`)/`static` 이 답한 위반 · 권한 없음(`lost`). 분류 입력이 없거나 분류가 최적화기와 어긋나면 이것 (fail closed) | HOLD |
| `uncertified` | 미인증 중 `occluded_target` 이 아닌 것 전부 (`lost` · 대상 없음 · degraded · incomplete) | HOLD |
| `unverified` | `solver_failed` · `unconstrained` (검사하지 않은 청크), **또는** 권한 link ↔ manipulated 인데 답한 계층이 미해결(`coarse`·`window_edge`·`outside`, T21 `RESOLVED_TIERS`) | HOLD |
| `comms` | **클라이언트가 만든다** — `evidence.ipc` = `timeout` · `stale` · `dimension` · `error` | HOLD |

- 모르는 kind · 모양이 틀린 항목은 HOLD (`wire.gate_decision`).
- **키가 없는 응답**: 옛 서버, 또는 씬이 없어 최적화기가 안 돈 청크(`result is None`). 후자에 키를 안 싣는 이유는 기존
  테스트 `test_closed_loop_also_carries_the_reference_but_declares_itself_not_shadow` 가 그 응답의 키 집합을 박고 있고 기존
  테스트는 고치지 않기 때문이다. 로컬은 `safe`/`geometry_certified` 로 `uncertified` 를 유도한다 (`source="derived"`) —
  유도 결과는 언제나 옛 `safe` 와 같은 결정. 서버 기록(`summary_json.verdict`)에는 그 청크도 `uncertified` 로 남는다.

### 위반 행 분류 (`safe_policy.classify_violations`)

`linearizer.clearances` / `esdf_clearance` 로 `result.trajectory` 의 **모든 행**을 최적화기가 본 것과 같은 씬(`_last_snapshot`)
으로 다시 잰다 (위반 청크에서만 — FK 한 번 추가). `clearance < −violation_tolerance` 인 ESDF 행이 `allowed` 인 조건:

1. 질의점이 로봇 구이고 link ∈ `ag3s.builder.clearance_policy.authorized_links(cs.contact_context)` (제약을 지을 때와 같은 집합).
2. 이번 제약에 권한이 실렸다 (`scene.manipulated_link_margin is not None` — T20 visible/occluded).
3. 답한 계층이 `target_free` · `static` 이 아니다 (그 답은 정의상 target 이 아닌 무엇).
4. **그 행의 최근접 장애물이 manipulated 다.** 근거는 있는 것 중 첫째: `distance` — `_esdf_clearance` 의 permission 검사와
   **같은** `|d_row − d_object| ≤ voxel` (manipulated 점군/구) · `label` — 라벨 층이 `TARGET_LABEL` · `centroid` — T20 기록의
   centroid 공 (반지름 + 구 반지름 + 그 link 의 대상 마진 + `allowed_contact_pad_m`=0.01).
5. 계층이 `fine` (또는 계층을 말하지 못하는 단일 격자 필드). 1–4 는 맞는데 계층이 미해결이면 `unresolved` → `unverified` 사유.

task 의 "centroid, 반지름 + margin" 은 4 의 마지막 fallback 으로 넣었다. 주 판정을 거리 일치 검사로 둔 이유: 부분 관측 점군의
centroid 는 사과 중심에서 17.6 mm 벗어나고(T17a), 공 판정은 사과 옆에서 **테이블**을 파고드는 손가락을 허용으로 읽는다
(지침 §10 "손가락-사과 · 손가락-테이블 동시 근접" — 테스트로 박았다). 라벨은 거친 격자에서 값과 어긋나므로(`pipeline.py` 주석) 둘째다.

  max_abs_dev_rad}` (HOLD 스텝에만; 측정 자세는 같은 줄 `qpos`, 명령은 T18 `applied_ctrl`). planning frame `extra` 에
  `verdict_reasons` · `verdict_reasons_source` · `gate` · `hold_chunks` · `hold_abort` (`--safe-remote` 면 언제나).
- **복구 한도**: 청크 경계마다 `begin_chunk` 가 연속 HOLD 청크 수를 센다 (실행 청크면 0). `> --safe-max-hold-chunks` 면 그 청크의
  planning 기록에 `hold_abort={hold_chunks, limit, reason, kinds, entry_reason, entry_kinds}` 를 남기고, 스텝을 적용하기 전에
  `[safe] t=… ABORT — …` 를 찍고 루프를 끝낸다 (`finally` 의 기록 닫기는 그대로 돈다). 종료 시 `[safe] HOLD (mode): {hold_chunks,
  hold_steps, holds, max_consecutive}` 와 `[safe] verdict reasons (chunks): …` 한 줄씩.
- T22 와의 관계: `grasp_signal_from_feedback` 은 HOLD 스텝(`executed=False`)의 `applied_gripper` 를 명령으로 세지 않는다 — 바꾸지
  않았다. `fixed` 에서 HOLD 스텝의 `applied_gripper` 는 이제 마지막 명령 값이다 (예전엔 측정값).

- **재지 않은 것**: T16/T14 재생, MuJoCo HOLD 드리프트(mm), 실제 closed loop, 회귀 기준선, figure. `--safe-max-hold-chunks` 의 값도
  정하지 않았다 (기본 무한).

### 판정 요청 (lead)

1. **`unverified` 에 미해결 계층 접촉을 넣었다.** T21 `RESOLVED_TIERS` 주석("창 밖 답은 접촉 허용 판정의 근거가 못 된다")을 따른
   것이다. 창이 손을 못 덮는 청크는 여전히 HOLD 다. 되돌리려면 `SafePolicy(allow_unresolved_contact_tier=True)`.
2. **`serve_safe.py` 배선 없음** — `verdict_policy` · `allow_unresolved_contact_tier` 를 서버 CLI 로 켜려면 한 줄씩 필요하다.
3. **`q_hold` 는 "이미 충돌 중인 자세를 고정" 할 수 있다** (지침 §8.5 경고). `collision` HOLD 에서도 직전 명령을 유지한다 — 감속/후퇴는
   이 STEP 밖이다.
4. `occluded_target` 은 **나머지 기하가 인증됐을 때만**이다 (`no_target` 은 validity VALID 에서만 나온다). `lost` 와 권한 없는
   `occluded`(있을 수 없지만) 는 `uncertified`.
