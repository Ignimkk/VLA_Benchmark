## 무엇을 했나 (평이한 요약 먼저)

client 가 `--policy-seed S` 를 주면 에피소드 **첫 요청**에 seed 를 싣고, 서버는 그 요청의 `policy.infer` 바로 앞에서
정책 RNG 를 `jax.random.key(S)` 로 다시 놓는다. 이후 요청은 거기서 이어 split 한다. 그래서 같은 서버 프로세스 안에서는
`(episode, seed)` 가 run 을 정한다. seed 를 안 주면 요청 바이트와 서버 동작이 T39 전과 같다.
`--warmup-steps N` 을 주면 첫 추론 전 시뮬레이션을 벽시계 대신 **정확히 N step** 진행한다.
openpi 는 고치지 않았다. benchmark 쪽 얇은 wrapper 가 `_policy` 사슬을 따라가 `Policy._rng` 를 바꾸고, `_rng` 가 없으면 크게 실패한다.

**smoke 에서 발견한 것 (S2 에 중요):** XLA 기본 설정에서는 **서버 프로세스가 다르면 같은 seed 라도 비트 동일이 아니다**.
t=0 상태는 비트 동일이었는데 첫 청크가 3–5e-3 달랐다. 원인은 XLA GPU autotuning 으로 본다.
`XLA_FLAGS` 에 `--xla_gpu_autotune_level=0` 을 더하면 서로 다른 두 서버 프로세스가 E0 · E3b 모두 6 청크 비트 동일이었다.
기본 env 는 바꾸지 않았고 판정은 lead 에게 맡긴다. 아래 "verifier 가 알아야 할 것" 1 번.

테스트가 박는 것:
1. **wire**: seed 없는 요청의 키 순서 = T39 전, msgpack 바이트 sha256 = T39 전 `wire.py` (`git show HEAD:trajopt/wire.py`, benchmark main 563dd4f) 로 만든 골든 (1959 B). seed 는 실제 msgpack 전송을 지나 `int` 로 돌아오고 정책 관측에는 없다. bool · float · 음수 · 2**32 는 거절한다.
2. **wrapper**: `SeededPolicy` 는 키가 없으면 obs 를 같은 객체로 넘기고 RNG 를 건드리지 않으며 회신도 없다. 키가 있으면 re-key 하고, 키를 벗기고 (호출자 dict 는 그대로), 회신한다. 틀린 seed 는 infer 전에 거절한다. `rng_owner` 는 사슬을 따라 내려가고, `_rng` 가 없으면 사슬 이름을 넣어 실패하고, PyTorch 정책도 거절한다.
3. **SafePolicy**: reset 이 RNG 를 덮어써도 seed 는 그 **뒤**에 놓인다. 정책은 `ag3s/` 키를 보지 않는다. 회신은 적용한 요청에만 있고 다음 요청은 이어서 split 한다. summary 는 `{applied, episode}` 이고 새 에피소드에서 지워진다. `_rng` 가 없는 정책에 seed 를 주면 `PolicySeedError` 다. ToOnlyPolicy 도 같다.
4. **client**: 첫 요청에만 싣는다. 회신이 없으면 (옛 서버) `RuntimeError`, seed 가 없으면 옛 서버와도 그대로 돈다.
5. **JAX 의미** (openpi `Policy.infer` 와 같은 split 규약): seed 0 = 새 서버 순서, 같은 seed 는 비트 동일, 다른 seed 는 청크마다 다르다. openpi 소스의 `_rng` 두 줄이 그대로인지도 본다 (서브모듈 sync 감시).
6. **warmup**: `run_warmup_steps` 는 N ∈ {0, 1, 1000} 에서 정확히 N step · N sync 를 돈다. viewer 를 닫으면 멈추고, 음수는 거절하고, 함수 본문에 `time.` · `sleep` 이 없다 (AST 로 꺼내 실행). flag · 첫 요청 전용 · manifest 는 소스로 확인한다.

## verifier 가 알아야 할 것

1. **프로세스 사이 비트 동일을 원하면 서버 env 에 `--xla_gpu_autotune_level=0` 을 더해야 한다.**
   ```
   XLA_FLAGS="--xla_gpu_enable_command_buffer= --xla_gpu_autotune_level=0"
   ```
   이 flag 가 없으면 같은 `(episode, seed)` 의 비트 동일은 **한 서버 프로세스 안**에서만 성립한다. 프로세스가 다르면 청크 0 부터 약 3–5e-3 다르다.
   S2 처럼 체인 · 조건마다 서버가 다르면 이것은 짝지은 비교의 "같은 noise" 에 영향을 준다.
   서버 시작 로그가 어느 쪽인지 한 줄로 말한다 (`XLA autotuning ON ... only WITHIN this server process` / `off ... across server processes`).
   CLAUDE.md 의 고정 env 를 바꾸는 일이라 lead · 사용자 판정이다. 나는 기본값을 바꾸지 않았다.
2. **새 flag (client, `pi05_infer.py`)**: `--policy-seed INT` (`[0, 2**32)`, `--remote` 필요, safe · E0 둘 다), `--warmup-steps N` (`--start-delay 2.0` 의 등가는 `1000`, timestep 0.002).
   둘 다 주지 않으면 예전 그대로다. **서버 쪽 flag 는 없다** — seed 는 요청이 싣는다.
3. **옛 서버 + 새 client 에 `--policy-seed`** 를 주면 client 가 첫 응답에서 죽는다 (safe: `RuntimeError ... does not apply policy seeds`, E0: `SystemExit`).
   브랜치 `o4-gpu-parallel` 서버로 S2 를 돌리려면 **cherry-pick 이 먼저**다. 함께 가야 하는 파일: `trajopt/policy_seed.py` (신규) · `wire.py` · `client.py` · `safe_policy.py` · `serve_safe.py` · `to_only_policy.py`.
4. **E0 frames 에는 청크가 없다** (`planning.actions = null` — T39 전부터 그렇다). E0 의 actions 비트 비교는 `--trajectory-out` npz (`predicted_chunks` · `executed_actions` · `measured_qpos`) 로 한다. E3b 는 frames 의 `actions` · `actions_reference` 로도 된다.
5. 재생산이 필요한 산출물: 없음.
6. 옛 기록과의 호환: 깨지지 않는다.
   - seed 가 없으면 요청 바이트 동일 (골든), 응답에 키 추가 없음.
   - **추가된 키**: 서버 기록 `summary_json` 에 `policy_seed` 가 **항상** 있다 (`{applied: null, episode: null}`). client manifest `timing` 에 `start_delay_s` · `warmup_steps` 가, 최상위에 `policy_seed` 가 **항상** 있다 (null 가능). npz 키는 주었을 때만 생긴다.
   - **E0 `--no-safe` 서버는 이제 `SeededPolicy` 한 겹으로 감싼다** — 키가 없으면 obs 를 같은 객체로 넘기고 `metadata` 도 같은 dict 다.
7. **공유 작업트리 주의:** main checkout 에 **SUBTASK-c Part A 의 미커밋 변경**이 함께 있다 (UTC 07:59–08:08 = KST 16:59–17:08). 파일은 `ag3s/config.py` · `types.py` · `runtime/pipeline.py` · `stages/target_grounding.py` · `experiments/sources/pi05_attention.py` · `trajopt/attention_policy.py` · 루트 `tests/conftest.py` · `tests/ag3s/test_subtask_gate.py`.
   위 suite 수와 smoke 는 그 변경 위에서 돌았다. 그 변경의 gate 는 기본 off 이고, AttentionPolicy 는 `result["subtask"]` 만 더한다.
   **커밋할 때 T39 파일만 스테이지할 것** (benchmark: 위 6 개, 루트: `tests/trajopt/test_t39_policy_seed.py`, pi05_TO_hybrid: `rby1_bringup/pi05_infer.py`).

## 내가 기대하는 결과
<**verifier 는 측정이 끝나기 전에 이 절을 읽지 않는다.**>

- seed 를 안 주는 run (기준선 둘 · B4 재생) 은 T39 전과 비트 동일일 것이다. 요청 바이트가 같고 서버 경로에서 바뀐 것은 키가 없을 때 아무 일도 안 하는 분기뿐이다.
  예외: E0 `--no-safe` 는 `SeededPolicy` 를 통과하지만 같은 obs 객체를 넘긴다.
- S2 의 "같은 조건 · 같은 (episode, seed) 2 회 → 비트 동일" 은 **같은 서버 프로세스 안**이거나 **autotune 0** 일 때만 성립할 것이다. 그렇지 않으면 청크 0 부터 1e-3 크기로 갈라지고, 파지 전후로 커질 수 있다.
