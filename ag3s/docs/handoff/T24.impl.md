## 무엇을 했나 (평이한 요약 먼저)

서버 constraint record 한 chunk 의 **입력을 그대로 복원**해서 TO 의 항을 하나씩 켜 보는 도구를 새로 만들었다. 입력은 reference,
그 실행의 sphere option 으로 다시 지은 robot model, 로컬 `qpos` 에서 얻은 `q_now`, ESDF 세 계층, 접촉 정책이다. 이 도구가
기록을 **1 mm 훨씬 안쪽(최대 5.9e-5 mm)으로 재현한다**는 것을 먼저 확인했다.
`sqp.solve` 가 반환 후보를 고를 때 **초기 iterate 도 후보에 넣도록** 고쳤다. 단, 초기 iterate 가 관절 한계 안일 때만 넣는다.
그리고 무엇이 반환됐는지(`returned`)와 모든 후보의 `(merit, 위반, 수락)` 을 `metrics` 에 싣는다.
평활 항을 jerk 라고 부르던 주석·문서 넷도 "2차 차분 = 가속도" 로 고쳤다.

**왜 "적격할 때만" 인가 — 한 줄만 바꿨을 때 기존 테스트가 깨졌다.**
`test_no_collision_ablation.py::test_with_no_collision_and_no_jerk_the_only_motion_left_is_the_limit` 가 실패했다.
그 fixture 의 reference 는 joint box 를 2.547 mm 넘고, 테스트는 "해가 box 안으로 들어온다" 를 요구한다.
merit 은 비용 + 충돌 위반뿐이고 **관절 한계를 보지 않는다.** 한계는 QP 행이 지킨다 (box·anchor 는 hard, 속도·가속도는 soft).
그래서 box 안으로 들어온 QP 후보는 추적 비용만큼 merit 이 나빠 **언제나 초기 궤적에 진다.** 초기 merit 으로 무조건 초기화하면 한계를 넘는 reference 가 그대로 나간다.
이것이 task 가 경고한 "모든 후보의 적격성이 같다고 가정하지 말라" 는 경우다. 테스트를 고치지 않고 코드에서 적격성을 가렸다.
T9 처럼 테스트를 반대 방향으로 다시 적은 것이 아니다. 기존 테스트는 **그대로 통과**한다.
- 적격한 초기화 아래에서는 `best_unaccepted` 가 나올 수 없다 (merit < best ≤ iterate_merit ⇒ 수락). 새 코드에서 `best_unaccepted` 가 나오면 **초기 iterate 가 한계 밖이었다**는 뜻이다.
- T14·T17 의 reference 한계 초과는 기록 chunk 에서 0 이었다 (도구의 `reference.limit_overshoot`). 이 실행들에서는 새 규칙이 곧 "초기 궤적도 후보" 다.
