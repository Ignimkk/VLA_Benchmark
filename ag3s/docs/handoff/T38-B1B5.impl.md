## verifier 가 알아야 할 것

- **새 인자 · 기본값:** `ConstraintRecordWriter(background=False, queue_size=8)` — 기본은 동기 그대로. **serve_safe 만 `background=True`.** verifier 의 `replay_profile.py:402` 는 writer 를 직접 만들므로, B5 를 재려면 `background=True` 를 줘야 한다 (내 사본은 `T38B_RECORDER_BACKGROUND=1`). 새 CLI flag 없음.
- **serve_safe 가 SIGTERM handler 를 단다** (recorder 가 있고 기존 handler 가 SIG_DFL 일 때만): SIGTERM → `SystemExit(143)` → atexit flush. 서버 종료 로그에 `[ag3s] constraint recorder flushed at exit (...)` 한 줄이 생긴다.
- **기록 디렉토리:** chunk npz 내용 · 이름은 같다. background 에서 쓰기 실패가 나면 그 번호가 **비어 있는 채로** 남는다 (동기는 다음 청크가 같은 번호를 다시 씀). `close()` 를 부른 경우에만 `meta.json` 에 `writer` 키가 추가된다 (serve_safe 는 원래 close 를 부르지 않아 meta.json 이 없고, 그건 그대로).
- **테스트 명령에 `--import-mode=append` 필수** (위 발견).
- 재생산이 필요한 산출물: 없음. 옛 기록과 호환: 깨지지 않음 (`load_constraint_run` 동일).
- replay "after" 는 `_drain` 의 끝난 항목 참조 해제(`constraint_record.py:312`) 를 넣기 직전 코드로 돌았다. 그 한 줄은 출력·기록에 영향이 없고 최종 코드로 단위 테스트 전체를 다시 돌렸다.
