## 환경 — `.venv-openpi-live` 다

mujoco 와 curobo 가 **한 프로세스에서 같이 돈다.** `.venv-ag3s` 에서 `import torch` 는 즉사하고
`.venv-curobo` 에는 mujoco 가 없다. 명령 앞에 `MUJOCO_GL=osmesa PYTHONPATH=/mnt/dev/work`.

**`curobo-esdf` skill 을 먼저 읽는다** — 함정 5 개와 eikonal 자가진단이 거기 있다.

GPU 로 정책을 띄우려면 `pi05_TO_hybrid/logs/serve_rby1_16d.sh` 의 환경변수를 **그대로** 쓴다
(`XLA_FLAGS` 가 없으면 CUDA graph 캡처가 실패하고, `XLA_PYTHON_CLIENT_PREALLOCATE=false` 가
없으면 JAX 가 GPU 105 GB 를 선점한다). attention 을 뽑을 때 `--config
pi05_rby1_randomized_pick_place_16d_lora` 를 **반드시** 준다 — 기본값은 14D 용이다.

## `max_field_age_sec` 를 정한다 — 이 게이트의 알맹이

**기계는 이미 있다. 없는 것은 숫자다** (2026-09-25 확인):

| 어디 | 무엇 |
|---|---|
| `benchmark/ag3s/config.py:756` | `max_field_age_sec: float \| None = None` — **아직 안 정함** |
| `benchmark/ag3s/runtime/frame_record.py:144` | manifest 에서 읽어 `stale` 판정을 낸다. **`None` 이면 `stale` 판정을 아예 하지 않는다** |
| `benchmark/trajopt/serve_safe.py:269` | CLI flag `--max-field-age-sec` 로 넘어간다 |
| `PLAN:646` | `stale` 이면 `geometry_certified = False` 로 내려 안전 게이트가 막는다 — **T4 의 검사 대상** |

**정하는 방법은 계획이 못 박아 뒀다** — *"프레임 간 필드 변화량을 재고 그 수치로 정한다."*
**기본값을 추측으로 정하지 않는다.** 근거는 **F14(상태 지연 한계를 100 ms 로 뒀는데 실제 피해
시작점보다 6 배 느슨했다)** 다 — 정확히 그 실수를 반복하지 않기 위한 조항이다.

**이미 손에 있는 입력 둘** (이것만 물려받는다):

1. **T0** — 필드 나이 P50 **2637 ms**. 실시간성은 별도 판정 실패 상태다 (P50 2519 ms, 24/24 청크가
   예산 533 ms 의 4.7 배).
2. **T2-b** — TSDF residual(물체가 떠난 뒤에도 accumulated TSDF 에 남는 occupancy) 이 decay 를
   끈 채로 **위쪽 반구 기준 26/54 프레임**(frame 47 에 영구 소거) · **탐침 중심 기준 46/54
   프레임**(frame 67 부터 영구 양수) 남는다. 그리고 **대조군 pear(움직이지 않은 과일)와 신호
   크기가 같아 필드만 보고는 잔상과 실물을 못 가른다.**

**2 번이 이 게이트의 질문을 바꿔 놓았다.** 한도를 고르는 문제가 *"얼마나 오래된 필드까지
믿나"* 가 아니라 **"잔상이 실물로 읽히는 것을 어디서 끊나"** 다. 프레임 간 변화량을 재면서
**decay 를 켠 경우도 함께 재라** — `time_decay`·`frustum_decay` 는 지금 둘 다 `1.0`(감쇠 없음)
이고, `T2-b` 의 `not_measured` 에 *"decay 를 켰을 때의 잔상 프레임 수"* 가 그대로 남아 있다.

## T2 에서 넘어온 열린 것들 — T3 에서 **다루지 않는다**

로그에 결함으로 적혀 있고 전환 신호가 붙어 있다. **T3 에서 손대지 말고, 필드 수치가 이것들에
새 빛을 비추면 그것만 기록해라.**

- **carve 1 프레임 지연** — attach 가 울린 프레임(ep1807 frame 19)에서 쥔 물체가 robot collision
  geometry 와 obstacle field 에 **동시에** 들어 있다. → T5·T6 에서 본다 (사용자 판정)
- **`destination_attention_locked` 가 한 번도 확정되지 않는다** · **detach 후 `latch.phase` 가
  `'placed'` 로 고착** — T2 의 불합격 둘
- **`runner_up_score` 수정의 효과가 미시험** — 값이 들어가긴 했지만 `confident` 가 갈리는 다섯
  프레임이 전부 이미 잠긴 뒤(`held`/`placed`)라 latch 가 그것을 보지 않는다. **`SEARCHING`
  구간에서 갈리는 기록이 있어야 시험된다**
