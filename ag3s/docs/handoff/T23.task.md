# T23 — 실행 게이트: 실패 사유를 가르고, HOLD 는 멈추되 명령을 삼키지 않는다

> writer: lead (A0) · 2026-09-28 · 읽는 쪽: implementer, verifier
> 근거: [지침](AG3S_GRASP_FAILURE_IMPLEMENTATION_GUIDE.md) §8 · §10-5, [T14.audit](T14.audit.md) §0b·§4.5 (T16: 충돌 OFF 인데 25/34 HOLD, 닫힘 명령 소실, HOLD 중 드리프트), [T18.impl](T18.impl.md), [T20.impl](T20.impl.md) (`occluded`/`lost` 상태), [T22.impl](T22.impl.md), [계획](AG3S_GRASP_FIX_PLAN.md)

## 왜 지금 이것인가

T16 이 보인 실패 기전은 **판정 → HOLD** 다: `TrajOptStatus.safe` 가 아니면(`violated`·미인증) 클라이언트가 청크 전체를 버리고
매 step `action = rby1_state()` — 현재 측정 자세와 **현재 gripper 개도**를 목표로 다시 준다. 그래서 (1) 닫힘 명령이 사라지고
(t=176·208), (2) 팔이 0.10–0.17°/step 드리프트해 사과를 밀고(t=72–92, 23 mm), (3) 파지에 필요한 접촉이 `violated` 로 분류되는 한
파지 프레임은 언제나 HOLD 다. 지침 §8.3: 신뢰할 수 없는 계획을 막는 기능은 필요하지만, 모든 실패를 하나의 HOLD 로 처리하고 매 step
측정값을 목표로 주는 지금 구현이 필수인 것은 아니다.

T18(실행 사실) · T20(`occluded` 는 실패가 아님) · T22(attach 는 확인 뒤) 위에서 게이트를 다시 세운다.

```
서버 판정 {사유들} ──► 클라이언트 게이트 ──► 실행 | HOLD(q_hold 고정, gripper 별도) | 중단
```

## 구현에 요청하는 것 (→ implementer)

### 1. 판정을 사유별로 (`safe_policy.py:_verdict` · `wire.py` · `sqp.py` 는 손대지 않고 `metrics` 만 읽는다)

응답에 `safe` bool 은 그대로 두되 **구조화된 사유 목록** `verdict_reasons: [{kind, detail}]` 을 더한다 (지침 §9 — bool 하나로 축약하지 않는다):

| kind | 뜻 | 게이트의 기본 처리 |
|---|---|---|
| `allowed_contact` | 최악 행이 **권한 있는 link ↔ manipulated 물체** 다: `max_violation_pair.link` 가 `contact.contact_links` 에 있고, 그 행의 질의점이 manipulated 기하(centroid, 반지름 + margin) 안이거나 라벨/`tier` 가 target 을 가리킨다 (T21 이 `tier` 를 더한다 — 없으면 거리로) | **정상 실행** (지침 §8.3: 파지에 필요한 접촉은 정상 조건) |
| `budget_only` | 예산/반복 상한으로 끝났지만 최종 검사 통과 (`FEASIBLE`) | 정상 실행 (지금도 safe) |
| `collision` | 권한 없는 link 또는 다른 물체와의 관통 (> tolerance) | HOLD |
| `uncertified` | `geometry_certified=False` — 단 **manipulated 가 `occluded` 인 것만으로는 미인증이 아니다** (T20). `no_seed` 인데 manipulated 가 살아 있으면 `occluded_target` 로 따로 낸다 | `uncertified` → HOLD · `occluded_target` → 정상 실행 |
| `comms` (`timeout`·`stale`·`dimension`·`error`) | 클라이언트 쪽 | 새 청크 사용 금지 → HOLD |

`safe = (사유 중 HOLD 처리인 것이 없다)`. 옛 클라이언트는 `safe` 만 읽으므로 호환된다. **`allowed_contact` 판정에 `no-collision` 처럼 판정 자체를 끄는 길을 만들지 마라** — 분류를 정확히 하는 것이 이 STEP 이다 (지침 §8.3 "충돌 실패로 잘못 분류한 뒤 HOLD 를 우회하는 것으로 해결하지 않는다").

### 2. HOLD 의 동작 (`pi05_infer.py` 제어 루프 · `client.py:_hold`)

- **`q_hold` 를 HOLD 진입 때 한 번 잡는다** — 마지막으로 **명령한** 팔 목표(직전 step 의 `d.ctrl`)를 쓴다, 측정 `qpos` 가 아니다. HOLD 가 이어지는 동안 같은 `q_hold` 를 준다. 매 step 측정값으로 덮어쓰지 않는다 (지침 §8.5).
- **gripper 는 팔과 분리한다**: HOLD 중 gripper 목표 = 마지막으로 명령한 gripper 목표 (열지도 닫지도 않는다). 쥔 물체가 있으면(T22 `held`) 그 명령이 곧 파지 유지다. 지침 §8.4: HOLD 중 VLA 대로 무조건 닫는 것도 하지 않는다.
- HOLD 기록: 진입 사유·`q_hold`·경과 step·측정 qpos 를 control frame `extra` 에 (T18 의 `applied_ctrl` 이 이미 명령을 싣는다 — 여기에 `hold={reason, q_hold, age}` 를 더한다).
- **복구 한도**: 연속 HOLD 청크 수가 `--safe-max-hold-chunks`(기본값은 재서 정한다 — 없으면 무한) 를 넘으면 실행을 **중단하고 사유를 보고**한다 (무한 반복 대신).
- `SafeRemoteClient._hold` 가 만드는 대체 청크도 같은 규칙 (팔 = 마지막 명령, gripper = 마지막 명령).
