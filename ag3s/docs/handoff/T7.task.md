## 목적함수 — 이것이 다음 의심 대상이다

`benchmark/trajopt/problem.py` · `config.py:130-157`

```
minimize  w_track‖Q − chunk‖² + w_smooth‖Δ²Q‖² + w_continuity‖Q − prev_tail‖² + w_slack·Σs
          w_track = 1.0   w_smooth = 0.05   w_continuity = 0.5   w_slack = 1e3 (선형)
          track_decay = 1.0   (뒤 스텝 tracking 감쇠 없음)
```

**`w_slack` 이 `w_track` 의 1000 배다.** 주석 자신이 *"dominate 는 필요하지만 as large as
possible 은 아니다"* 라고 적는다. 이 비율이면 **아주 작은 clearance 개선도 tracking 을 크게
희생해서 사간다** — 손이 사과에 다가가 clearance 가 줄면 tracking 을 버리고 물러난다.
**위반이 0 인 채로 손이 밀려나는 것이 그 모양이다. 다만 아직 추측이고 측정되지 않았다.**

**가중치는 CLI flag 가 없다** (`serve_safe.py` 확인). 재려면 A1 이 붙여야 한다.

**rollout 없이 잴 수 있다** — 기록된 chunk 하나를 가지고 가중치만 바꿔 QP 를 다시 풀고
손끝→사과 거리를 비교하면 된다. 서버도 로컬 실행도 필요 없다.

## 사용자 제안 셋 (2026-09-26) — 이 순서로 한다

### 1. cuRobo 를 한 번 더 본다 — **물체를 잡을 수 있도록 어떻게 설계돼 있나**

cuRobo 는 조작을 전제로 만들어진 라이브러리다. **잡는 순간 물체가 장애물이기를 그치는 것을
cuRobo 는 어떻게 다루는가**를 `curobo_src/` 에서 읽어라 — attached object, sphere 갱신,
world collision 의 활성/비활성 전환. **우리 설계(field 에 남기고 권한 link 만 margin 완화)와
어디가 다른지**를 표로 적어라. 우리가 놓친 장치가 있는지 보는 것이 목적이다.

### 2. **그리퍼만 충돌로 제한하고 나머지는 빼 본다**

- `--links` / `--exclude-links`(T6e) 로 **손가락 넷만 남긴다.** self-collision 도 **끈다**
  (끄는 flag 가 없으면 A1 이 만들되 **되돌릴 수 있게**, 그리고 시작 로그에 크게 찍게).
- 같이 **그리퍼 capsule 을 더 줄인다.** 지금 `--capsule-radius-scale 0.8` 에서 손가락 구가
  **11.5~15.4 mm** 이고 URDF 가 요구하는 13.9~18.7 mm 에 2.4~3.3 mm 못 미친다.
  **그리퍼가 테이블에 걸리지 않을 만큼** 더 줄인다 (사용자 지시).
- **이것은 진단이지 해답이 아니다.** 이 설정에서 팔뚝·몸통은 무엇에 부딪혀도 아무도 안 막는다.

### 3. **어느 관절이 충돌 제약에 걸리는지 기록한다**

`max_violation_pair` 는 **최악 한 행**만 싣는다. 필요한 것은 **활성 제약 전체의 분포**다 —
chunk 마다 어느 link 가 몇 번, 어느 물체에 대해, 얼마의 여유로 걸렸는가.
**위반이 0 이어도 활성인 행이 핵심이다** (위 lead 측정 참고).

A1 이 실을 것: 활성 행의 `(link, obstacle/candidate, clearance, required_margin)` 상위 N 개.
A2 가 그것으로 **"무엇이 손을 미는가"** 를 chunk 축에 그린다.
