# T20 — 조작 대상 정체: 가려짐은 새 물체가 아니다

> writer: lead (A0) · 2026-09-28 · 읽는 쪽: implementer, verifier
> 근거: [지침](AG3S_GRASP_FAILURE_IMPLEMENTATION_GUIDE.md) §4 · §10-2, [T14.audit](T14.audit.md) §2·§4.2, [T19.impl](T19.impl.md) (guard 가 `held_centroid` 를 따른다는 판정 사항), [계획](AG3S_GRASP_FIX_PLAN.md)

## 왜 지금 이것인가

T19 가 사과 관측을 살려도, `TargetConfirm.select()` 는 붙들던 물체가 이 프레임에 cluster 를 못 내면 **그 프레임의 target 으로
leader 를 즉시 돌려준다** (`stages/target_grounding.py:373-376`, `"unobserved"`). 3 프레임 확인은 `_held` 갱신만 늦춘다.
`target_score_threshold = 0.0` 이라 score 0.015 의 crate 도 통과한다 (T14 seq 12). 그 target 을 fine 창 · target-free 제외 기하 ·
`manipulated_link_margin` · `target_field_exclude` · T19 guard 가 **전부** 따라간다.

지침 §4.1 의 세 정보를 가른다: **attention target** (이번 관측에서 정책이 본 것) · **manipulated object** (이번 파지의 대상) ·
**destination**. 접촉 허용과 제외 기하는 두 번째를 참조해야 한다.

```
attention lifting → target grounding ─► [manipulated identity] ─► 접촉 허용 · 제외 기하 · fine 창 · guard
                                              ^^^^^^^^ 여기 (새 단계)
```

## 구현에 요청하는 것 (→ implementer)

### 1. 영속 ID 와 관측 상태 (`stages/target_grounding.py` · `runtime/pipeline.py`)

- 파이프라인이 **manipulated object** 하나를 소유한다 (`AG3S` 의 필드, `reset()` 에서 지운다). 내용: 영속 `id`, 마지막 관측
  기하(점군·centroid·반지름), 마지막 관측 시각/프레임, **관측 상태** `visible | occluded | lost` (이름은 제안이다 — 지침 §4.3),
  가려진 프레임 수.
- `TargetConfirm.select()` 의 `unobserved` 분기: leader 를 이 프레임의 target 으로 **돌려주지 않는다.** 붙들던 물체를
  `occluded` 상태로 돌려주되 기하는 **마지막 관측** 것을 쓴다 (사과가 손에 가려진 동안 "사과는 저기 있다" 가 답이다).
  `_held` 의 도전자 counting 은 지금처럼 계속 돈다 — 도전자가 `target_confirm_frames` 연속 1 등이고 **`target_switch_min_score`
  이상**일 때만 `switch`. 새 config 키 `clustering.target_switch_min_score` 의 **기본값은 0.0** (= 지금 동작, 점수로는 안 거른다;
  값은 T19/T20 검증 수치로 정한다 — 숫자를 박지 않는다).
- `occluded` 가 `clustering.target_lost_frames` 를 넘으면 `lost` — 그때는 target 없음이지만 **사유 코드** 가 `lost(id, age)` 다.
  `no_seed` 와 구별돼야 한다 (T14 seq 22 의 HOLD 사유가 "no_target/no_seed" 였다).
- cluster index 는 프레임 간 뜻이 없다 — 정체는 centroid 근접(지금의 `tolerance`)으로 잇되, **ID 는 우리가 매긴다**.

### 2. 소비자가 manipulated 를 참조한다 (`runtime/pipeline.py` · `constraints/to_adapter.py`)

다음이 **attention target 이 아니라 manipulated object** 를 읽게 한다. 파지 전에는 둘이 같으므로 (지침 §4.1) 동작이 같고,
가려짐·attention 이동에서만 갈린다:

| 소비자 | 지금 | 바꿀 것 |
|---|---|---|
| `manipulated_object(target, attached, ...)` → `manipulated_link_margin` | 이번 프레임 target | manipulated (occluded 면 마지막 기하) |
| `target_field_exclude` 마스크 | `target is not None` | manipulated 가 `visible/occluded` 면 |
| `_build_esdf` 의 `target_points` (fine 창 중심) · `target_free_points` · `_target_ball` | `target.points` | manipulated 의 점군 (occluded 면 마지막 것) — 창 배치 자체는 T21 이 바꾼다 |
| T19 guard 중심 (`self_filter` 의 centroid) | `TargetConfirm.held_centroid` | manipulated centroid |
| `TARGET_LABEL` 라벨 점 | target.points | manipulated 점군 |

`destination` 은 건드리지 않는다 (latch 가 정한다).

### 3. 기록 (`runtime/pipeline.py` metrics · `experiments/sources/constraint_record.py` summary)

`manipulated: {id, state, age_frames, centroid, n_points, last_seen_frame, switched_from}` 를 매 프레임 싣는다.
**`state` 가 `occluded` 인 프레임에서 접촉 허용이 살아 있었는지**는 이것 없이는 알 수 없다.

### 4. 손대지 않을 것

- `stages/robot_filter.py` (T19 끝났지만 검증 중 — 값을 바꾸지 마라), `fields/curobo_*` (T21), `trajopt/**` (T24 진행 중 · T22/T23 대기),
  `grasp_latch.py` (T22). `to_adapter.py` 는 위 표의 두 줄만.
- `ag3s.status`/인증 규칙 (`occluded` 를 미인증으로 볼지는 T23 게이트의 일 — 여기서는 **상태 코드만** 정확히 낸다).
- 기본값 변경 없음: 새 키 둘 다 "지금 동작" 이 기본. 다만 `unobserved` 분기의 **반환값 변경은 기본 동작이다** — 그것이 이 STEP 의 요지다. 기존 테스트가 걸리면 반대 방향으로 다시 적고 impl.md 에 이유를 적어라.
