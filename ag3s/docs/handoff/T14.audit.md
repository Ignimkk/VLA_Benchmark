## 0b. 사용자 질문 — "제약 없이 TO 만 붙여도 왜 실패하나" (T16 · T17, 2026-09-28 추가)

같은 서버(같은 카메라·같은 지연)로 두 실행이 있다. [figure](../figures/t14/t16-t17-hold-vs-shadow.png) · [json](../figures/t14/t16-t17-hold-vs-shadow.json)

| | T16 — closed loop, `--no-collision` | T17 — shadow (정책 청크 그대로 실행) |
|---|---|---|
| TO 가 청크를 바꾼 양 (실행 창 최대) | **0.00° × 34 chunk 전부** | (실행되지 않음) 0.2–8.6° |
| 정책 청크가 anchor·velocity·acceleration 한계를 넘은 chunk | 0 (T14 로 확인, 0/30) | — |
| 판정 `violated` → HOLD | **25 / 34 chunk** (t ≥ 72 전부) | 1 / 75 (shadow 라 실행됨) |
| 손가락이 사과에 닿음 | t=88 (16 mm, 중심 기준) — **HOLD 중에 드리프트로** | t=84 (−9.6 mm) |
| gripper 닫힘 명령 | t=176 (0.02) · t=208 (0.03) — **둘 다 HOLD 프레임에 떨어져 로봇에 도달 안 함**; gripper joint 는 끝까지 −0.045(열림) | t=116–120 닫힘 (−0.045 → −0.032) |
| 사과 z | **0.0 mm** | **+239 mm** (t=160) → basket 에 놓음 (끝 +8.5 mm) |

**결론: optimizer 가 아니다.** 제약을 끄면 refined ≡ reference 인데도 실패하고, 같은 청크를 HOLD 없이
실행하면 성공한다. 실패를 만드는 것은 **안전 판정 → HOLD** 경로이고, 그 판정은 `--no-collision`
에서도 돈다 (`worst_row` 는 강제와 무관하게 여유거리를 잰다 — 설계상 의도된 것이다).

HOLD 는 두 가지로 해친다:
1. **닫힘 명령을 삼킨다** — `action = rby1_state()` 가 현재 gripper 개도를 재명령한다 (§4.5).
2. **멈추지 않고 드리프트한다** — HOLD 중에도 팔이 0.10–0.17°/step 움직였고 (control record 실측),
   T16 t=72–92 에서 손가락이 사과 쪽으로 23 mm **더** 내려가 사과를 밀었다 (사과 z +0.24–0.45 mm).
   매 step 현재 자세를 목표로 다시 주므로 servo 의 정착 오차가 목표에 누적되는 것으로 보인다 (**가설** —
   ctrl 이 기록에 없어 확정하지 못했다).

그리고 판정이 `violated` 인 이유는 §2 의 사슬 그대로다: 손가락 앞의 거리장에 사과가 남아 있다
(self-filter 가 사과를 지워 grounding 이 crate 로 갔고, target-free layer 가 사과에 걸리지 않았다).
파지는 정의상 사과 표면을 파고드는 동작이므로 (T17 에서 −4 ~ −8 mm), 사과가 손가락에게 장애물인 한
**파지 프레임은 언제나 `violated` 프레임**이다.

   이 기록만으로 가르지 못한다 (§5).

## 5. 아직 못 가른 것 (측정 없이 적지 않는다)

- **정책이 t=96–176 동안 왜 gripper 를 안 닫았나.** 손가락은 사과 표면에 있었다. VLA 단독 실행의
  같은 구간 gripper 시퀀스가 있어야 "TO+HOLD 가 만든 타이밍 차이" 인지 "정책이 이 자세에서는 원래
  안 닫는지" 를 가른다. 지금 기록에는 VLA 단독 rollout 이 없다.
- **T12/T11 의 HOLD·gripper 열.** 로컬 기록이 T11 것이라 T12 에서는 읽을 수 없다.
- **4.1 을 고쳤을 때 `base` 누수가 되돌아오는가.** T1 의 이유가 그것이었다. inflation 을 link 별로
  두거나 (팔·몸통 50 mm, 손가락 ≤ 10 mm), 조작 대상 근방을 필터에서 빼거나, 로봇 mesh 를 렌더한
  정확한 self-mask 를 쓰는 것 중 무엇이 맞는지는 재야 한다.

## 6. 사용자 판정을 기다리는 것

고칠 순서를 정해야 한다. 내 추천은 **4.1 → 4.2 → 4.4 → 4.3 → 4.5** 다 — 4.1 이 없으면 나머지가 발동할
일이 없고, 4.3·4.4 는 4.1 이 있는 동안 안전 구멍이다. 어느 것도 코드를 건드리지 않았다.
