## 무엇을 했나 (평이한 요약 먼저)

self-filter 의 여유(inflation) 를 **link 별로** 줄 수 있게 했고(`arms` · `gripper` 집합 이름도 받는다),
**직전 프레임에 확정한 target centroid 반경 R 안에서는 여유를 0 으로** (구 실제 반지름으로만) 판정하게 했다.
guard 는 예외가 아니다 — 보호 구 안에서도 로봇 구 **내부** 점은 지워진다. cloud 필터와 depth robot mask 가
생성자에서 한 번 구한 **같은** inflation 객체와 프레임 시작에 고정한 **같은** guard centroid 를 쓴다. 두 값 다
기본은 꺼짐(빈 표 · R=0)이고, 그때 필터는 T19 이전과 산술까지 같다 (float 하나가 그대로 나간다).
서버에는 `--self-filter-inflation-link` · `--self-filter-target-guard` 를 달았고, 시작 로그가 실제 유효
link 별 표와 "YAML 은 이 서버에 닿지 않는다" 를 찍는다.

**T20 없이 이것만 켜면**: 사과가 관측에 남아 grounding 은 사과를 붙들 수 있지만, 사과 표면이 TSDF 에도
그대로 들어가므로 권한 없는 link 뿐 아니라 **손가락에게도 사과가 장애물**이다 (지침 §3.1). 파지 성공은
이 STEP 의 판정 항목이 아니다.

- **새 stats**: `constraint_set.metrics["self_filter"]`, `metrics["n_self_filter_guard_protected"]` (fused, 카메라별), `process_debug()[1]["self_filter_stats"]` 의 `guard_*` · `n_guard_protected`. **`frame_record.py`(T18 소유) 는 이 metrics 를 디스크에 쓰지 않는다** — 재생 측정은 `process_debug` 나 `metrics` 를 직접 읽어야 한다. 시작 로그의 표와 recorder meta 의 `self_filter` 는 남는다.
- **guard 가 보는 centroid 는 `TargetConfirm.held_centroid` 다.** T14 처럼 grounding 이 crate 로 넘어간 뒤라면 guard 는 **crate** 를 보호한다. T14 t=80→88 에서 guard 가 사과를 붙들어 두는지(사과가 이미 절반 지워진 t=80 에 held 가 아직 사과인지) 는 guard 만으로 보장되지 않는다 — 그 연결은 T20.
- **guard 안에서는 로봇 표면이 샐 수 있다 (측정한 사실).** 합성 fixture (구를 그대로 렌더, 잡음 0) 에서 보호 구가 팔 전체를 덮게 하면 로봇 픽셀 9,714 중 **6,355 가 남았다** — 전부 구 표면에서 ±5e-12 m 인 점, 즉 inflation 0 경계의 부동소수 동전 던지기다. 실제 depth 잡음(mm) 과 mesh↔구 차이에서는 **보호 구 안의 손가락 표면이 남는 쪽**이 예상 방향이다. 판정표 #2 (gripper 누수) 를 guard 반경 안/밖으로 갈라 재 주면 좋겠다. 테스트 `test_on_the_rendered_scene_the_guard_leaks_only_exact_surface_points` 가 이 사실(남는 로봇 점은 전부 표면 점, 내부 점 0) 을 박아 두었다.
