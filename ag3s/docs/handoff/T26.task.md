## 왜 지금 이것인가

T14 에서 crate 가 target 이 되자 `_target_ball` 이 반지름 246 mm 공을 만들어 crate seed 15.8k 개를 지웠다. 원인은 세 겹이다:
(1) **manipulated object 에 자격 조건이 없다** — grounding 이 attention 1 등 cluster 를 내면 그것이 무엇이든 ball·target-free·fine 창·guard·접촉 허용이
따라간다. T20 은 "붙든다" 까지만 했고 `first` 는 leader 를 조건 없이 채택한다 (`target_grounding.py:518-521`). (2) 세 역할(attention target ·
manipulated · destination, 지침 §4.1)이 하나로 뭉쳐 있다. (3) 목적지를 파지 **뒤에** "그때의 target" 으로 정한다 (`safe_policy.py:675-677`).

**반지름 상한은 답이 아니다** (사용자 판정). crate 가 manipulated 가 되는 상태 자체가 만들어지지 않아야 한다.

측정값 (lead, 2026-09-28): 손가락 원점 간격 — 닫힘 6.0 mm · 정책 open(±0.045) 96.0 mm · joint limit(±0.05) 106.0 mm.
T14 cluster extent(x·y·z mm): 사과 63·67·62 (111 점) · crate 183·**421**·149 (1,780 점, score 0.015) · banana 쪽 153·63·79 (172 점).
**crate 는 가장 좁은 축 149 mm 로 어떤 개도에도 안 들어간다. banana 쪽 cluster 는 가장 좁은 축 63 mm 로 들어간다** — banana 는 실제로
잡을 수 있는 물체이므로 그것이 맞다. banana 로 넘어가는 것은 규칙 3(score + 연속 프레임)이 막는다 (T20 verify: min_score ≥ 0.05 에서 사과 유지).

## 구현에 요청하는 것 (→ implementer)

### 1. Admissibility — manipulated 가 될 수 있는 cluster (`stages/target_grounding.py`)

- **graspable**: cluster 의 **가장 좁은 주축 extent** (PCA 주축 — 방향 무관) ≤ `max_opening`. `max_opening` 은 **로봇 모델에서 계산**한다 —
  손가락 collision geometry 의 안쪽 면 간격을 finger joint 상한에서. 숫자를 박지 않는다. 시작할 때 값과 근거(어느 geometry·어느 joint 값)를 로그와 record 에 싣는다.
  (lead 의 원점 간격 96/106 mm 는 참고치 — 안쪽 면 간격은 이보다 작다. 무엇을 썼는지 impl.md 에 적어라.)
- **not destination**: 등록된 destination 기하(§2)와 겹치는 cluster 는 후보가 아니다. 겹침 정의(예: cluster 점 중 destination 기하 + 1 voxel 안 비율)는 정하고 기록한다.
- `first`: leader 가 아니라 **rank 가 가장 높은 admissible cluster** 를 채택한다. 없으면 manipulated 없음 + 사유 `no_admissible` (NO_SEED 등과 구별).
- `switch`: 도전자가 admissible 이고 `target_switch_min_score` 이상으로 `target_confirm_frames` 연속일 때만.
- `hold/keep`: centroid 로 이어진 cluster 가 **inadmissible** 이면 (사과가 손가락·crate 와 한 cluster 로 합쳐진 경우) 그 기하를 쓰지 않고 `occluded` 로 —
  마지막 admissible 기하 유지, 사유 `inadmissible_match` 기록.
- **기본값 변경** (사용자 판정): `clustering.target_switch_min_score` **0.1**, `clustering.target_lost_frames` **None** (무기한 — 사과는 더 높은 admissible 도전자가
  기준을 넘을 때만 바뀐다).

### 2. Destination 등록 (`stages/target_grounding.py` · `runtime/pipeline.py`)

- crate 는 모델에서 **free body** 다 (`model_transport.xml`: `crate` jnt 31 free) — `--static-geometry` 로는 목적지를 얻을 수 없다. 그래서 **인지에서 등록**한다:
  **graspable 이 아닌** cluster 가 attention leader 이고 `target_switch_min_score` 이상으로 `target_confirm_frames` 연속이면 destination 으로 등록 (id · 점군 · AABB · 마지막 관측).
  재관측되면 centroid 근접으로 이어 기하를 갱신한다. caller 가 `reset` 때 `destination_points` 를 주면 그것을 우선한다 (source = `injected` / `registered`).
- destination 은 **어떤 거리장에서도 빠지지 않는다** (F18 — 쥔 물체의 점에만 20 mm 마진 — 은 그대로). ball · target-free 제외 · guard · 접촉 허용 어디에도 들어가지 않는다.
- `safe_policy._run_latch` 의 "잠금이 목적지를 확정했고 지금 target 이 그것이면" 경로(`safe_policy.py:675-677`)를 **AG3S 의 destination 을 읽는 것**으로 바꾼다.
  (T26 뒤 target 은 파지 후에도 사과이므로 옛 경로는 목적지를 영영 못 잡는다.) `placed_fn` 도 이것을 쓴다.

### 3. 불변식 — 제외 기하는 admissible manipulated 에서만 (`runtime/pipeline.py`)

`_target_ball` · target-free 층 · fine 창 중심 · guard · `manipulated_link_margin` · `TARGET_LABEL` 은 T20 이 이미 manipulated 를 읽는다. 여기에 **불변식 검사**를 더한다:
제외 기하를 만들 때 그 기하가 admissible 이라는 증거(`narrowest_extent_mm ≤ max_opening_mm`, destination 겹침 0)가 없으면 **만들지 않고** `invariant_violation` 을 기록한다
(unit test 에서는 raise). 이것은 상한이 아니다 — admissible 이 아닌 것은 애초에 여기 오지 않아야 하고, 오면 그것이 버그라는 표시다.

### 4. 파지 중에도 제외가 끊기지 않는다 (`constraints/**` · `runtime/pipeline.py` · `safe_policy.py`)

`--target-field-policy exclude-authorized` 의 시작 로그: "쥔 뒤에는 이 정책이 돌지 않습니다 (그때 target 은 crate 이고 crate 는 빼면 안 됩니다)". T26 뒤에는 이 전제가 거짓이다.
**접근 → 닫힘 → attach → 운반 → 놓음** 동안 gripper link 의 질의에서 사과가 빠지는 근거가 끊기지 않게 한다: attach 전은 manipulated 제외, attach 후는 attached 경로.
닫힘 시도 ~ attach 사이에 사과가 다시 gripper 의 거리장에 들어가는 프레임이 없어야 한다. 프레임마다 `exclusion: {active, source: manipulated|attached|none}` 을 기록한다.

### 5. Self-filter inflation 0 — 구 반지름 자체 (`ag3s/config.py`)

- `pointcloud.self_filter_inflation` 기본값 **0.05 → 0.0** (사용자 판정). T19 의 per-link override·guard 는 옵션으로 남되 기본에서 할 일이 없다.
- **사실 기록**: cuRobo `RobotSegmenter` 의 기본도 `distance_threshold=0.05` (반지름 + 5 cm, `curobo_src/curobo/_src/perception/robot_segmenter.py:53,303`) — 우리 0.05 와 같은 값이었다.
  "구 반지름 자체" 는 cuRobo 에서도 0 으로 따로 줘야 하는 설정이다. impl.md 에 적어라.
- 로봇 점 누수는 **inflation 이 아니라 구 모델로** 막는다 (cuRobo 의 원칙: 구가 mesh 를 덮는다). 누수는 T28 이 GT segmentation 으로 잰다 — 새면 그 link 의 구를 고치는 것이 다음 일이다.
- 기준선(skill `regression-baseline`)이 바뀔 수 있다 — 의도된 변경이다. 옛/새 값을 impl.md 에.
