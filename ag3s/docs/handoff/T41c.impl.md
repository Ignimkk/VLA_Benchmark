# T41c — 구현: HOLD = 현재 측정 자세에 정지 (`--safe-hold-mode measured`)

> writer: ag3s-implementer (A1) · 2026-10-05 · 읽는 쪽: verifier, scribe, lead
> benchmark HEAD 기준 `e13292d` · pi05_TO_hybrid HEAD `c7c1cc9` (작업 트리에 arrow-overlay implementer 의 미커밋 변경이 함께 있다) · **커밋하지 않았다** (lead 가 커밋)

## 무엇을 했나 (평이한 요약 먼저)

HOLD 모드를 하나 더했다. `measured` 는 HOLD 가 시작되는 순간 팔의 **측정** 관절을 `q_hold` 로 한 번
잡고, 이어지는 HOLD 동안 그 자세를 명령한다. 직전 명령 쪽으로 가지 않는다. gripper 는 `fixed` 와 같이
**마지막 명령** 이다. 연속 HOLD 청크는 처음 잡은 자세를 그대로 쓰고, 청크가 한 번 실행된 뒤에만 다시
잡는다. 기본값 `fixed` 는 바뀌지 않았다 (pre-T41c 코드와 비트 동일, 시험으로 고정).

왜: T40 I 의 C1982 에서 HOLD 가 시작될 때 팔은 직전 명령보다 7.3° 뒤에 있었다. `fixed` 의 `q_hold`
(= 직전 명령) 를 따라 팔이 HOLD 중에도 계속 움직였고, 그러다 막대에 닿았다.

### gripper — 왜 마지막 명령인가 (측정 개도가 아니라)

사과를 쥔 손가락은 사과 폭에서 멈춰 있다 (B1807 t=200: 명령 0.572, 측정 0.717). 쥐는 힘은
`kp × (명령 − 측정)` 에서 나온다. 측정 개도를 목표로 주면 그 차이가 0 이 되어 쥐는 힘이 사라진다.
MuJoCo 에서 실제로 확인했다. 아래 세 상태 모두 **측정 개도를 쓰면 2 스텝 안에 사과가 떨어진다**.

| 상태 (replay) | gripper 목표 | 사과 이동 > 20 mm 인 HOLD 스텝 | 64 스텝 뒤 사과 z |
|---|---|---|---|
| B1807 t=200 | 마지막 명령 0.572 | 없음 (5.8 mm) | 1.060 m |
| | 측정 개도 0.717 | **2** | 0.860 (테이블) |
| | 완전 닫힘 0.0 | 없음 (16.3 mm) | 1.053 |
| B1968 t=192 | 마지막 명령 0.566 | 26 | 0.859 |
| | 측정 개도 0.713 | **2** | 0.858 |
| | 완전 닫힘 0.0 | 24 | 0.860 |
| B1828 t=456 | 마지막 명령 0.578 | 30 | 0.858 |
| | 측정 개도 0.716 | **2** | 0.860 |
| | 완전 닫힘 0.0 | 16 | 0.860 |

명령을 모를 때 (에피소드 첫 스텝, 쥔 물체가 없다) 만 측정 개도를 쓴다. `fixed` 의 동작과 같다.
"완전 닫힘" 이 더 낫지도 않다는 점도 표에 있다 (아래 "verifier 가 알아야 할 것" 3번 참고).

### 드리프트 — 측정 자세를 위치 servo 로 붙들면 얼마나 흐르나

방법: T40 G E3b 기록을 `pi05_infer.main()` reset + 기록된 `applied_ctrl` 로 replay 한다. `t0` 까지 매 행의
`qpos` 가 비트 동일한지 확인한다. 그러면 속도 · 접촉 · solver warm start 가 실제 실행의 것이다. 그 상태에서
HOLD 분기를 64 제어 스텝 (×33 sim step = 4.3 s) 돈다. 산출물: `outputs/impl/T41c/drift.json`, 스크립트:
`outputs/impl/T41c/p/measure_drift.py`. "팔" 은 14 관절의 진입 대비 최대 |Δq|, EE 는 `EE_BODY_L` 의 월드 변위다.

| 상태 | 진입 때 명령 − 측정 | `fixed` 팔 8 / 64 스텝 | `fixed` EE 8 / 64 | `measured` 팔 8 / 64 | `measured` EE 8 / 64 |
|---|---|---|---|---|---|
| B1807 t=184 (운반 중) | 4.16° | 4.07 / 4.16° | 36.1 / 36.4 mm | **0.575 / 0.596°** | **7.6 / 7.5 mm** |
| B1807 t=200 | 3.88° | 3.80 / 3.88° | 31.8 / 32.0 | **0.559 / 0.580** | **6.3 / 6.2** |
| B1807 t=216 | 2.04° | 1.96 / 2.01° | 10.8 / 10.6 | **0.535 / 0.533** | **5.7 / 5.7** |
| B1968 t=192 | 4.17° | 4.08 / 4.17° | 37.5 / 37.8 | **0.543 / 0.549** | **6.4 / 6.0** |
| B1828 t=456 | 4.23° | 4.14 / 4.23° | 34.5 / 34.9 | **0.565 / 0.572** | **7.0 / 6.6** |
| C1982 t=176 (T40 I 의 HOLD) | 7.27° | 6.98 / 7.16° | 22.6 / 23.3 | **0.554 / 0.571** | **7.7 / 7.8** |

- `measured` 는 **한 번 처지고 멈춘다**: 0.53–0.60°, EE 5.7–7.8 mm. 8 스텝 (한 청크) 안에 자리를 잡고, 64 스텝까지
  더 늘지 않는다 (최대 변화 0.02°). 모델에 중력 보상이 없어서 생기는 위치 servo 의 정상상태 오차다
  (`kp` 1500–2000, `defaults_common.xml`). `fixed` 에서도 같은 크기의 오차가 있다 (명령 대비 0.57–0.60°).
  다만 `fixed` 에서는 그 오차가 이미 측정 자세에 들어 있었고, `measured` 에서는 측정 자세에서 한 번 더 생긴다.
  T23 이 본 `legacy` 의 누적 드리프트 (0.10–0.17°/step) 와 다르다. 매 스텝 다시 잡지 않기 때문이다.
- 첫 스텝은 0.64° 까지 간다 (B1807 t=200). 진입 순간 팔이 움직이던 관성이다.
- **C1982**: `fixed` 는 HOLD **2 스텝째** (sub-step 1) 에 `geom#1052 ↔ hurdle_0_collision_bar` 접촉. 기록된 접촉 행
  178 과 같다. `measured` 는 64 스텝 동안 접촉이 없고, 로봇–장애물 최소 거리는 3.9 mm 다.
- 참고 (구현하지 않음): 같은 자세를 rebuild 한 상태 (replay 아님) 에서 목표를 `q_meas + qfrc_bias/kp` (중력 feed-forward)
  로 주면 처짐이 0.016° 로 줄었다. 처짐 6–8 mm 가 T41a 여유 10 mm 에 비해 크다고 판단되면 다음 단계 후보다.
  `pi05_infer.py` 에서 `d.qfrc_bias` 를 넘겨야 해서 이번에는 넣지 않았다.

## verifier 가 알아야 할 것

- **새로 생긴 플래그·기본값 변경**: `--safe-hold-mode measured` (클라이언트). 기본 `fixed` 는 그대로다. 서버 플래그는 없다.
  T41c 를 재려면 클라이언트에 `--safe-hold-mode measured` 를 준다. `--safe-gate off` 에서는 HOLD 가 comms 때만 생기므로
  효과가 거의 보이지 않는다. E3b 는 `--safe-gate reasons` 다.
- **재생산이 필요한 산출물**: 없음. 클라이언트 쪽만 바뀌었다. 서버 · TO · ESDF 는 그대로다.
- **옛 기록과 호환**: 깨지지 않는다. `fixed` 의 control frame `hold` 키 집합은 그대로다. `measured` 일 때만
  `hold.gripper_source` · `hold.entry_command_dev_rad` 가 더해진다. `hold.source` 는 `measured` 다.
- **planning 기록의 HOLD 대체 청크** (`SafeRemoteClient._hold` 의 `actions`) 는 모드와 무관하게 여전히 "마지막 명령" 이다.
  이것은 실행되지 않는 기록용 청크다. 실제로 들어간 값은 control frame 의 `applied_ctrl` (= `q_hold`) 을 본다.
- **긴 HOLD 에서 사과가 미끄러진다 — 두 모드 공통이고, `measured` 와 무관하다.** 운반 중 HOLD 를 64 스텝 이어 가면
  운반 상태 5 개 가운데 3 개에서 사과가 떨어지거나 크게 미끄러졌다. B1968 t=192 · B1828 t=456 에서는 두 모드 모두
  17–32 스텝 사이에 떨어졌다. B1807 t=216 에서는 `fixed` 가 33–64 스텝 사이에 떨어뜨렸고, `measured` 는 64 스텝에
  손 안에서 61 mm 미끄러졌다 (`drift.json` `fruit_in_hand_shift_mm`; 위 gripper 표의 "마지막 명령" 행). 정책의 운반 중 gripper 명령이 0.57 (완전 닫힘이 아니다) 이고, 손 안에서 천천히
  미끄러진다 (16 스텝에 1.5–2 mm). 완전히 닫아도 막지 못했다. 짧은 HOLD (1–2 청크) 에서는 보이지 않는다.
  연속 HOLD 가 길어지는 run 에서 사과가 떨어진다면 이 기전부터 의심한다.
- 미커밋 상태의 pi05_infer.py 에는 arrow-overlay implementer 의 변경 (+79 줄) 이 함께 있다. 내 변경은 위 두 곳뿐이다.
