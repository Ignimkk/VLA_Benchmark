## 프롬프트 1 — 전체 아키텍처 (VLA + AG3S + trajopt), 간략

```
로봇 조작 시스템의 시스템 아키텍처 다이어그램 한 장을 그려라.
가로로 긴 한 장(16:9), 한국어 라벨, 흑백 인쇄에서도 읽히게.

## 무엇을 보여주는 그림인가
언어 지시를 받은 VLA 정책이 동작을 내놓고, AG3S 가 그 동작이 안전한지 판단할
근거(충돌 제약)를 만들고, trajopt 가 그 제약을 만족하도록 동작을 고친다.
AG3S 가 주인공이므로 시각적으로 가장 크고 강조되어야 한다.

## 노드 (이것만. 더 만들지 말 것)
A. VLA (π0.5)              — 입력: 언어 지시 "put the apple in the basket" + 카메라 영상
B. AG3S                     — 큰 컨테이너. 안에 B1·B2·B3·B4 를 담는다
   B1. 무엇이 있나          — depth → TSDF → ESDF (거리장)
   B2. 어디를 정밀하게      — action chunk 의 swept volume = ROI
   B3. 무엇이 조작 대상인가 — attention → grounding → 잠금(latch)
   B4. 충돌 제약            — 어느 로봇 구가 · 무엇에 · 얼마나 가까워도 되는가
C. trajopt                  — SQP 선형화 → QP → 전 행 재검사
D. 안전한 action chunk → 실행

## 간선 (화살표는 데이터가 흐르는 방향. 반대로 그리지 말 것)
A → B1   라벨 "카메라 depth"
A → B2   라벨 "action chunk [50 × 14]"
A → B3   라벨 "attention"
B2 → B1  라벨 "ROI"            (B2 가 B1 의 해상도를 어디에 몰아줄지 정한다)
B1 → B4,  B3 → B4              (기하와 의미가 여기서 합류한다)
B4 → C
C  → D
D → B3  점선, 라벨 "성공 판정 → 잠금 해제"   (유일한 되돌아오는 화살표)

## 배치
- 위에서 아래로 4 단: A / B / C / D
- B 안에서는 B1·B2·B3 를 가로로 나란히, 그 아래 B4 가 셋의 폭을 모두 덮는 한 줄
- B2 → B1 만 가로 화살표, 나머지 B 내부 화살표는 세로

## 색
- B1 파랑 계열(기하) · B2 주황 계열(ROI) · B3 빨강 계열(의미) · B4 보라 계열(제약)
- B 컨테이너는 초록 굵은 테두리로 강조
- 색은 역할 구분용. 채도를 낮추고 글자는 검정으로

## 부제 (제목 아래 한 줄)
"attention 은 무엇이 조작 대상인지만 정한다.  무엇이 충돌할 수 있는지는 기하가 정한다."

## 금지
- 노드 10 개를 넘기지 말 것. 모듈 파일명·성능 수치·주석 상자를 넣지 말 것
- 라벨을 상자 테두리 위에 얹지 말 것. 선끼리 교차시키지 말 것
- 되돌아오는 화살표는 D → B3 하나뿐
```

## 프롬프트 2 — AG3S 내부 아키텍처, 상세

```
로봇 충돌회피 지각 모듈 "AG3S" 의 내부 아키텍처 다이어그램 한 장을 그려라.
세로로 긴 한 장(A3 세로 또는 4:5), 한국어 라벨.

## 이 모듈이 하는 일 (한 문장)
카메라 depth · 로봇 상태 · VLA 의 action chunk · VLA 의 attention 을 받아,
궤적 최적화기가 그대로 소비할 수 있는 "충돌 제약"을 만든다.

## 설계 원칙 — 그림이 이것을 드러내야 한다
1. attention 은 **무엇이 조작 대상인지만** 정한다. 무엇이 충돌할 수 있는지는 **기하**가
   정한다. attention 을 장애물 탐지 문턱으로 쓰지 않는다 — 질량이 있으면 후보다.
2. 접촉 허용은 "제약 삭제"가 아니라 **(로봇 구, 대상) 쌍의 마진**이다. 0 mm 도 관통은 금지.
   거리장은 익명이라 "누가 묻는지"를 모르므로, 대상을 필드에서 파내면 손끝뿐 아니라
   팔꿈치·몸통·반대팔에게도 사라진다.
3. 모르는 조합(미지 링크·미지 phase·미지 source)은 전부 full margin 으로 fail-closed.
4. AG3S 는 판정만 하고 **결정하지 않는다.** phase 도 파지 성공도 외부에서 주입받는다.

## 구조 — 세 갈래가 내려와 바닥에서 합류한다
입력이 셋이고 각각 한 열을 몰고 내려온다. 세 열을 시각적으로 분리하라.

### 열 A — 기하 : "무엇이 부딪힐 수 있나"  (파랑 계열)
입력: depth 카메라 3 대 (머리 1 + 손목 2) · 카메라 내부/외부 파라미터 · 로봇 상태 · phase(주입)
 A1. 로봇 self-filter        로봇 자기 몸의 픽셀·점을 지운다 (안 지우면 자기 자신을 장애물로 본다)
 A2. 재구성 → point cloud    핀홀 역투영, uv 보존, 결정론적 다운샘플
 A3. 멀티뷰 융합             카메라별로 처리해 base 좌표계에서 합친다 (같은 칸은 max)
 A4. 지지면 RANSAC 평면      평면 하나 = 선형 제약 행 하나. 이 마스크는 열 C 로도 간다
 A5. Block-Sparse TSDF 5 mm  관측을 프레임마다 적분해 쌓는다 (누적)
 A6. Local Dense ESDF 10–20 mm   ROI 안에서만 만든다. 출력: 거리 d(p) 와 기울기 ∇d(p)

### 열 B — ROI : "어디를 정밀하게 볼 것인가"  (주황 계열)
입력: VLA 의 action chunk [50 스텝 × 14 채널]
 B1. Forward Kinematics       chunk 의 매 스텝 로봇 자세
 B2. 로봇 충돌 구 궤적        구 61 개 × 50 스텝
 B3. swept volume + padding   이번 chunk 가 쓸고 지나갈 부피
 → 이것이 A6 의 ROI 를 정한다 (B3 에서 A6 으로 가는 가로 화살표)
 주석 한 줄: "정밀 영역을 attention 의 target 에 두면 파지 순간 목적지로 옮겨간다.
 swept volume 은 attention 이 어디를 보든 로봇이 실제로 지나가는 곳이다."

### 열 C — 의미 : "무엇이 조작 대상인가"  (빨강 계열)
입력: VLA 내부의 attention 맵 (특정 layer·head, 16×16)
 C1. attention 어댑터 → 픽셀맵 (H, W)    카메라 해상도로 확대. 어느 VLA 인지를 여기서 격리
 C2. lifting — 점별 attention            uv 로 3D 점에 붙인다. 어떤 점도 버리지 않는다
 C3. grounding                           씨앗 → 3D 연결성 → 덩어리 → 점수. 출력: "주목 대상"
 C4. 잠금(latch)  ★신규                  걸기: 연속 N 프레임 같은 물체 + 1·2위 점수 격차 문턱
                                         유지: attention 이 어디로 가든 무시
                                         풀기: 성공 판정 = detach
                                         출력: "조작 대상"
 C5. attached — 쥔 물체를 로봇 쪽 구로    parent_link 를 타고 다닌다. 해석적 거리를 쓴다
 주석 한 줄: "주목 대상(attention 이 보는 것)과 조작 대상(실제로 쥔 것)은 다르다.
 접촉 권한은 조작 대상에 붙는다."

### 합류 1 — clearance 정책  (보라 계열, 세 열의 폭을 모두 덮는 한 줄)
(로봇 구 × 대상 종류) 마진 행렬. 아래 다섯 칸을 표처럼 나란히 그려라:
 | 조작 대상(쥔 것) | 목적지(담을 곳) ★신규 | 장애물 | 지지면 | 미지 기하 |
 | 0 mm, 권한 링크만 | 얇게              | full  | full  | full     |
아래 한 줄: "알 수 없는 조합은 전부 full margin — fail closed"

### 합류 2 — 출력
CollisionConstraintSet — ESDF 핸들 · 조작 대상 · 구별 마진 배열 · 지지면 · validity · phase
아래 화살표 하나로 "→ trajopt" 라고만 적고 끝낸다 (trajopt 내부는 이 그림에서 그리지 않는다)

### 되돌아오는 화살표 하나
"성공 판정 → 잠금 해제(detach)" 를 C4 로 점선으로 되돌린다.
성공 판정은 AG3S 밖(과제 소유자)에서 계산해 주입한다고 작게 적어라.

## 간선 규칙
- 열 안에서는 위에서 아래로만. **화살촉은 항상 흐르는 쪽에.**
- 가로 간선은 셋뿐: A4 → C3 (지지면 마스크) · B3 → A6 (ROI) · 성공 판정 → C4 (점선)
- 선을 교차시키지 말 것. 교차가 생기면 열 순서나 노드 위치를 바꿔서 풀 것

## 표기
- ★신규 표시가 붙은 둘(C4 잠금, 목적지 마진 칸)은 다른 테두리색으로 눈에 띄게
- 상자 안 글자는 제목 한 줄 + 설명 한 줄. 세 줄 넘기지 말 것
- 라벨을 상자 테두리나 컨테이너 경계 위에 얹지 말 것

## 금지
- 성능 수치(ms), 발견 번호(F11 등), 코드 파일명을 상자 안에 넣지 말 것 — 주석 줄에만 허용
- 장식용 아이콘·그림자·그라디언트 금지
```
